### 2.2 V4 时间旅行（`af8d0a8`，23 文件 +2608/−12）

后端（新包 `dev.workbench.timeline` + `planning` 分叉）：

- `RunObservationService`：三个只读投影

  - `checkpoints`：每个检查点 + 当时真实冻结状态（已完成节点数与节点键、交接数、模型调用数、累计 Token）。

- `RunForkService`（`planning`）+ `RunForkController`：`POST /api/runs/{id}/forks`、`GET /api/runs/{id}/forks`

## 6. 手测剧本

### 6.1 V3 画布保存闭环

1. 首页 → 新建任务 → 生成计划候选，等候选 `READY`。
2. 计划对话框切到「可视化编排」→ 把审查节点标题改掉、给它加一条验收条件。
3. 顶部徽标应显示「结构合法」，「应用画布到计划」可点；点它 → 出现绿色成功条并显示新摘要前 12 位。
4. 故意把某节点验收条件清空 → 徽标变成「N 处冲突」、应用按钮变灰；强行不可提交（按钮禁用）。
5. 恢复合法后应用成功 → 点「确认并创建运行」→ 运行详情里节点标题就是改过的那个。

### 6.2 V4 时间轴 / Checkpoint / 分叉 / 对照

1. 打开一条**已结束**运行 → 顶部「执行时间轴」：应看到节点/尝试/模型/工具/审批/压缩/检查点各泳道；点任一节点色块跳回流程视图并打开该节点玻璃盒。
2. 同页「Checkpoint 快照与时间旅行」：每个检查点显示冻结节点数、交接数、模型数与累计 Token；无检查点时给空状态文案。
3. 点「从此处分叉调试」→ 选源节点 + 填补充要求 + 选「沿用源任务模型」→ 创建分支运行 → 自动跳到新运行。
4. 打开原运行 →「分支对照」：选择刚创建的分支，应看到状态/耗时/节点/调用/Token 双轨与逐节点产出并排 diff；底部有「只对照声明写入范围」的限制说明。
5. 对一条**运行中**的运行调 `POST /api/runs/{id}/forks` → 400「只有已结束的运行才能分叉」。

### 6.3 V5 实时 X 光

1. 架构页顶部切到「实时 X 光」→ 输入一条真实运行 ID → 加载轨迹。
2. 只有被真实走到的模块显示 ACTIVE 并有调用数/耗时；未走到的显示「空闲」。
3. 模型模块应显示压缩节省率（该运行有压缩记录时）；工具模块显示安检拦截数。
4. 拖动步进回放滑块 → 步骤序号变化，未被走到的模块变淡；点「打开当前步骤」跳到运行详情对应节点与玻璃盒 Tab。
5. 切回「静态教学图」→ 原有 8 个主题与前后翻页行为不变。

## 7. 未交付范围与原因

**V6（OTel/Glass-Box Trace 导出、外部框架 Trace 接入、Eval Flywheel）本轮未实施。** 理由：本轮预算优先保证 V3 闭环与 V4/V5 完整可用（含后端投影、迁移、前端面板与实跑门禁），V6 需要「导出协议 + 接入鉴权限流限载荷 + 只读复用画布/时间轴/玻璃盒 + 评测数据集抽取与回归」四块联动，做成半成品会同时污染已有证据口径与评测口径，因此按阶段边界停在 V5。

V6 拆解建议（下一轮）：

1. `GET /api/runs/{id}/trace-export?format=otel|glassbox`（复用 V4 的 Span 投影即可，改动最小，建议先做）。
2. `POST /api/external-traces/runs` + `/runs/{id}/spans`：需要先定义外部 Span 的最小协议、归属与限流策略，并决定外部 Run 在 `runs` 表中的落库形态（复用 `parentId` 还是新表）。
3. Eval Flywheel：复用既有 `EvalCustomDataset` / `EvalCustomSample`，从运行抽取用例后跑既有回归，需确认脱敏边界。

其它已知边界（沿用上一轮，未变）：

- V3 节点级异构模型 / Skill / MCP 绑定仍未实现（`PlanCandidateDraft` 协议无对应字段）。
- V2 的 `KNOWLEDGE_SEARCH` / `CONTEXT_ARTIFACT_READ` 仍**不**默认授予内置角色（最小权限；自定义 Agent 显式声明即可）。
- V4 分叉**不复制**节点级固定模型策略与上游交接载荷（协议缺字段），统一沿用任务模型；分叉会继续写同一个工作区。
