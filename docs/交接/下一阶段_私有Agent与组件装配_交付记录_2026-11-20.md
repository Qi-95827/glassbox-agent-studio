## 1. 已完成

### A · 本地账号与服务端归属

- `users` 保存稳定账号、PBKDF2 密码摘要、管理员标记和旧数据领取标记；登录使用服务端 `HttpSession`，不信任请求体、Header 或模型输出中的用户字段。
- `POST /api/auth/initialize` 首次初始化管理员，可选择显式领取旧 `LOCAL` 任务、工作区和运行；`POST /api/auth/claim-legacy` 可稍后领取。
- `POST /api/auth/users` 由管理员添加普通用户或管理员；`GET /api/auth/status`、`POST /api/auth/login`、`POST /api/auth/logout` 构成登录入口。
- `AuthenticationFilter` 在初始化后拒绝匿名 API 请求；审计、监控、评测、费用、管理员和外部动作端点暂限管理员。
- `OwnershipService` 按任务、工作区和运行链做服务端归属校验；新任务和新工作区写入 `resource_ownership`。列表按当前用户过滤；按 ID 查询、确认、报告、事件、指标、交付下载和交付正文都先核对归属。
- 交付正文在读取前复核当前目录授权；撤权后即使文件内容未变也返回 403，历史回执保留。

### B · 私有组件与 Agent

- 「我的 Skill」：草稿编辑、Markdown 正文、发布不可变版本、归档和版本历史。
- 「我的工具」：首批仅受信授权读取 / 授权搜索执行器；可固定扩展名（如 `.jsx`, `.tsx`）；发布固定执行器与文件约束。
- 「我的 Agent」：手动组装、指定权限类别（分析 / 审查）、输出要求、Skill 和工具列表、是否参与推荐；支持从设计思路生成本地规则草稿、编辑、发布、归档和版本历史。
- 发布时固定 Skill 正文摘要、工具版本和执行器约束，保存 `spec_sha256`；发布 v2 不会改变 v1 的组件快照。

### C · 接入规划、执行与工作台

- 任务候选输入新增 `agentMode`（`BUILTIN` / `MANUAL` / `RECOMMEND`）、`manualAgentId`、`manualAgentVersion`、`candidateAgentIds` 和 `readOnly`。
- 规划器只接收本次勾选的已发布、可推荐候选短引用（`P1` 等）；模型返回 `agentRef` 只是建议，服务端校验归属、发布状态、角色相容性、只读能力和节点文件范围。
- 确认时重新校验；`plan_node_agent_bindings` 保存每个节点最终定义版本、来源、理由和固定组件快照；图摘要升级为 v7。
- 执行前再次核对私有 Agent 归属、版本和归档状态；`AgentDefinitionCatalog` 统一解析内置与私有定义，私有版本固定读取，不回退到草稿或最新版。
- 私有工具在节点授权文件与扩展名交集内注册；交集为空时装配失败，不会退化为全量授权。实际调用仍走现有工具网关和调用记录。
- 运行时节点详情新增「声明的 Agent 与来源」、固定 Skill/工具版本、「实际装配快照」、工具调用、结果和交接正文。

## 6. 补充收口（仓库授权、版本固定与模型草稿）

### 6.1 仓库导入先授权，再调用 Git

- 新增 `repository_authorizations`：管理员显式把规范化仓库根目录授予账号；工作区创建在调用任何 Git 命令之前，先用 `toRealPath()` 规范化输入路径并调用 `RepositoryAuthorizationService.requireAuthorized(repo)`。
- 授权通过后才执行 `check-ref-format`、`rev-parse --show-toplevel` 和 worktree 创建；Git 返回的根目录必须与授权路径一致，子目录或非仓库目录会被拒绝。
- 普通账号未获授权时返回 403「该仓库尚未授权给当前账号」；初始化前的单机模式和独立交付自建仓库保持原有行为。
- 管理员入口：`GET/POST /api/admin/repositories`、`DELETE /api/admin/repositories/{id}`；普通账号通过 `GET /api/repositories` 查看自己的授权。页面位于「我的 Agent · 账号与归属」。
- 页面按钮明确为「撤销导入授权」：只禁止新导入，已有工作区仍按原归属访问。
- 运行概况改为按当前会话可读取任务计数：`RunRepository.countByStatusForTasks`；普通用户不再看到全库状态计数。

验证：`AuthOwnershipIntegrationTest` 覆盖同一仓库「甲未授权不可导入 → 授权后可导入 → 乙未授权不可导入 → 授权后可导入」；对未授权普通目录返回 403（证明先授权后 Git），授权后同一非仓库目录返回 Git 错误；撤销甲导入授权后已有工作区状态 200、新导入 403；乙的运行概况 `TOTAL=0`、甲至少 1。

### 6.2 规划短引用固定到发起时的版本

- `plan_candidates.agent_aliases_json` 在发起规划时保存 `P1 → 精确 ID、版本、摘要、名称、角色和工具摘要`；模型输入也来自这份快照。
- 收到响应和确认时使用同一快照；等待期间发布 v2 仍绑定 v1。版本被归档或撤权时，服务端给出「已归档/未发布/无权」原因并拒绝进入可确认状态。
- 旧候选没有快照时保持兼容读取；新候选全部固定映射。

验证：`PrivateAgentVersionPinIntegrationTest` 用阻塞规划模型在等待期间发布 v2，断言绑定与运行节点仍为 v1；另一个用例在等待期间归档，候选为 `INVALID` 且不能确认。

### 6.3 从思路生成 Agent 的模型路径、组件建议与模型策略

- `POST /api/my/agents/draft` 的 `mode=MODEL` 调用已配置的 `TaskIdeaModel`，返回固定结构的可编辑草稿。
- 服务端只把当前账号可见且已发布的 Skill/工具摘要以 `S1`/`T1` 代号发送给模型；模型返回的 `skillRefs`/`toolRefs` 由服务端解析成稳定 ID 和发布版本，未知代号写入待确认问题。
- 页面将模型建议预选到 Skill/工具选择框，用户仍可修改；本地规则模式保留，不预选组件。
- Agent 新增 `modelStrategy`：`INHERIT_TASK` 或 `FIXED`；`FIXED` 保存 `mock` 或 `deepseek`。策略和模式进入草稿、发布版本和装配快照。

验证：`PrivateAgentDraftModelIntegrationTest` 用桩 `TaskIdeaModel` 验证结构化草稿、可见组件代号解析、固定策略保存和装配 `modelOverride=deepseek`。真实 DeepSeek 草稿调用未执行。

### 6.4 账号会话与 CSRF 对照

| 设计要求 | 最终实现 | 证据 / 差异 |
| --- | --- | --- |
| Spring Security 会话 | 引入 `spring-boot-starter-security`；`AuthenticationFilter` 从 Servlet 会话解析用户并写入 Spring Security 上下文；自定义登录/退出入口 | 未登录 401、跨账号 403；浏览器登录、退出、刷新保持会话 |
| 密码编码 | PBKDF2WithHmacSHA256（120000 次、16 字节随机盐、恒定时间比较） | 初始化/登录用例覆盖 |
| CSRF token | `CookieCsrfTokenRepository.withHttpOnlyFalse()`；初始化后的已登录状态修改请求必须带 `X-XSRF-TOKEN`；`GET /api/auth/csrf` 返回 token | 无 token 的创建任务/退出返回 403；带 token 成功；浏览器实际创建 Skill、退出并重新登录 |
| 管理员添加用户 | `POST /api/auth/users`，页面账号页 | 浏览器添加 `bob`；`AuthOwnershipIntegrationTest` |
| 旧 LOCAL 归属 | 初始化勾选领取或 `POST /api/auth/claim-legacy` | `LegacyOwnershipIntegrationTest` |

说明：会话内容仍由本地 `AuthService` 管理，Spring Security 负责过滤器链、SecurityContext 桥接和 CSRF；未使用 Spring Security 的 `UserDetailsService` 登录表单。

### 6.6 复核问题的补充修复

- 费用硬预算从任务表单传入候选确认对话框，确认请求提交 `maxCostMicros`；确认页回显并可修改，留空仍表示不限额。混合模型校验现在会随用户填写的预算触发。
- Agent 草稿建议保留 Skill/工具的 ID 和精确版本；页面预选和保存都提交该版本，发布时固定建议版本，而不是“保存时最新”。模型看到的 Skill/工具摘要改为从已发布版本快照读取，草稿未发布修改不会混入。
- 退出请求失败时不再直接清空页面状态：先复查 `/api/auth/status`，服务端仍登录时保留页面并提示重试；仅在服务端成功响应或状态复查确认未登录后切换为登录页。
- Ant Design 浮层 z-index 提升到 3000，高于 MUI Dialog，任务入口、工作流等下拉框可在新建任务对话框中用鼠标点选。浏览器实测入口下拉 `z-index=3000` 并可选中「代码」。
- Skill/工具选择标签按实际固定的版本显示；草稿建议 v1、组件当前 v2 时标签显示 v1，保存和发布仍固定 v1。
- 退出失败提示移到页头下方并增加「重试退出」按钮，不再遮挡右上角「退出」。
