# 个人版安装、升级、备份与回退

> 适用：单机个人版。共享部署、多租户和运营能力不在本文范围。

## 1. 环境要求

- Java 21、Maven 3.9+、Git、Node.js 20+ 与 npm。
- 启用 Docker 时：Docker Desktop/Engine 可用，预拉取 `python:3.12-alpine`。
- 真实模型：在仓库根目录创建 `config/deepseek-api-key.txt`，只写一行密钥；该文件不得提交。
- 默认数据库：`data/workbench.mv.db`；默认工作区根目录：`data/workspaces`。

## 2. 首次安装

1. 获取代码后安装前端依赖并构建：
   - `cd frontend/user-workbench`
   - `npm ci`
   - `npm run build`
2. 从仓库根目录启动：
   - `mvn spring-boot:run`
   - 默认地址 `http://127.0.0.1:8088`。
3. 打开页面后运行“平台运行概况 → 环境自检”，或请求 `GET /api/system/self-check`。
   - `DATABASE`、`SCHEMA`、`WORKSPACE_ROOT` 必须为 `OK`。
   - `DOCKER`、`TEST_IMAGE` 为 `WARN` 时只能使用非容器路径。
   - `DEEPSEEK_KEY` 为 `WARN` 时只能使用模拟模型。
4. 在“代码工作区”创建隔离 worktree；仓库来源必须是可信本地仓库。

## 3. 干净环境验收步骤

1. 新建临时数据库与工作区目录，不指向现有 `data/`。
2. 创建合成 Python 仓库：`calculator.py` 返回 `a-b`，`tests/test_calc.py::test_add` 断言 `add(2,1)==3`。
3. 创建 `bug-fix` 任务，显式授权 `calculator.py` 写入。
4. 在流程图确认复现、定位、修复、回归和审查节点；终态应为等待用户核对。
5. 在代码工作区发起审批、批准、本地提交；必要时准备并批准推送。
6. 下载完整报告与脱敏报告，确认分诊、证据、审计和结论。
7. 运行环境自检并保存结果。

## 4. 升级

1. 停止应用。
2. 备份数据库和工作区（见下一节）。
3. 更新代码或替换构建产物；重新构建前端。
4. 启动应用。`schema.sql` 只做增量迁移，历史表不会被删除。
5. 运行环境自检；打开一条历史运行确认旧记录可读。
6. 若迁移失败，停止应用并恢复备份，不要在新库上继续写入。

## 5. 备份

- 数据库：停止应用后复制 `data/workbench.mv.db`（以及同目录 H2 附属文件）。
- 工作区：复制 `data/workspaces/`；其中包含隔离 worktree，不包含源仓库的未提交主工作区。
- 配置：单独备份 `config/deepseek-api-key.txt` 到受控位置；分享备份时排除密钥。
- 报告与截图：如需要，另行保存；报告可能包含代码差异和自由文本。

## 6. 回退

1. 停止应用。
2. 恢复上一版本代码/构建产物。
3. 用升级前备份覆盖数据库文件；恢复对应工作区目录。
4. 启动并运行自检。
5. 已推送的 Git 提交不会因本地回退自动撤销；远端变更需单独核对和回退。

## 7. 故障处理

- 数据库不可查询：检查数据目录权限、文件锁和磁盘空间，恢复最近备份。
- 工作区不可写：检查 `workbench.workspace-root` 权限；不要在源仓库主工作区直接运行写入任务。
- Docker 不可用：容器复现/回归会阻塞；可在自检确认后先处理 Docker，不要用模拟结果代替真实证据。
- 推送/合并结果未知：查看“代码工作区 → Git 交付”中的状态和审计，人工核对远端与工作区，不自动重试。
- 回归通过后修改代码：交付结论应显示“证据已过期，需重新测试”，必须重新运行回归。
