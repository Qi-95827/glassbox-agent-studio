## 2. 关键实现

- 数据：`tasks.version`、`run_supplements`（OPEN→APPLIED）、`workspace_declared_files`（补充文件路径 + 内容摘要）。
- `SystemCheckResult.reasonCode`：`REPRODUCTION_MISSING_INFO`/`REGRESSION_MISSING_INFO`；复现缺测试时结算事务保存待补充事项，`无法绑定工作区版本` 不再被误判为缺信息。
- `TaskSupplementService.apply`：单事务校验运行状态、请求归属、任务版本、计划授权摘要、零调用安全边界、失败检查、无恢复子运行；写入 `tests/test_*.py`、登记声明文件、任务版本 +1、失败检查与跳过节点回到待执行、运行回到 `PENDING`；成功后 `RunService.dispatchContinuation` 重新排队。
- 指纹：已声明补充文件按“路径 + 当前内容 SHA-256”加入 `verificationFingerprint`；内容变化/删除使旧证据失效；其他未跟踪文件与审批签名仍拒绝。
- 接口：`POST /api/runs/{id}/supplements/{requestId}`；执行视图新增 `taskVersion`、`supplement` 与 `SUBMIT_SUPPLEMENT` 操作。
- 前端：`ExecutionFlowPanel` 补充卡片与表单，`main.jsx` 提交入口与四类事件中文名。

## 6. 已知限制与未验证项

- 本期补充种类仅 `TEST_FILE`（新建 `tests/test_*.py`），不支持修改已有测试、目录授权、其他语言或构建入口。
- 安全继续只允许“零 Agent/模型/工具调用”的检查阻塞边界；已有下游调用或部分节点完成时仍需恢复或新建运行。
- 补充文件保持未跟踪，不自动提交；用户在代码工作区自行审查/提交。审批签名仍不接受任何未跟踪文件。
- 目标/范围没有编辑入口；授权变化只能通过现有任务字段变化触发拒绝，未实现“提交补充时同时修改目标”的界面。
- 真实 deepseek 运行仅 1 次（8 次模型调用、13,440/1,005 Token），只使用合成任务与临时工作区；未覆盖真实 Bug 平台、其他语言或并发补充。
- 截图与隔离数据库位于临时目录，不作为 Git 资产提交。
