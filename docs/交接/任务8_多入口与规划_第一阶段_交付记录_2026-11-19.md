# 任务 8 多入口与规划 · 第一阶段交付记录

> 日期：2026-11-19。范围仅覆盖交接第 5 节“多入口与规划”的第一段：四类入口输入校验、交付物和验收条件。未开始规则路由、候选计划和计划调整。

## 1. 业务条件

1. 需求、设计、代码、测试四类入口分别有受信输入要求、交付物和默认验收条件。
2. 代码入口必须选择工作区、显式授权写入并至少授权一个现有文件；测试入口必须选择工作区并至少授权一个测试可见文件。
3. 需求/设计入口不因选择入口类型自动获得写入或工作区权限；声明写入时仍要求工作区和文件授权。
4. 用户未填写验收条件时，使用入口默认验收条件；用户填写时保留用户条件。
5. 实际生效的验收条件进入任务定义，交付物与验收条件另存 `task_entry_policies`，供运行详情追溯。
6. 入口策略不能扩大工具授权；权限仍由工作流模板和任务授权决定。

## 2. 权威记录与重新校验

- 权威定义：`EntryPolicyService`，版本 `POLICY_VERSION=1`。
- 任务生效验收：`tasks.acceptance_json` 与 `TaskDefinition.acceptanceCriteria`。
- 入口交付物/验收/提示：`task_entry_policies`。
- 校验时机：任务创建前；受保护权限在现有 `RunService` 和模板授权路径继续校验。
- 当前没有策略更新接口；修改代码中的策略需要提升版本并补迁移/重验，不能用运行时自由文本覆盖。

## 3. 失败后状态

- 输入校验失败发生在任务和运行写入前，不创建任务。
- 策略保存发生在任务/运行创建后、派发前；保存失败会抛出，运行保持 `PENDING`，不会自动派发。该边界尚未补清理/重试测试，列为未验证。

## 4. 用户入口

- 新建任务弹窗选择入口后显示：必填项、交付物、默认验收条件和指引。
- 运行详情接口返回 `entryPolicy`（若存在），可查看实际保存的交付物、验收和提示。

## 5. 接口与数据

- `GET /api/entry-policies`：四类策略。
- `GET /api/runs/{id}`：新增 `entryPolicy`。
- `task_entry_policies(task_id, policy_version, deliverables_json, acceptance_json, warnings_json, created_at)`。
- 任务定义继续使用原有 `acceptance_json`，不新增重复字段。
