## 3. 用户想要的系统

这是一个面向个人开发者的可视化代码开发 Agent 项目，同时用于学习 Agent 工程。用户可以从需求、设计、代码、测试或模拟 Bug 等入口发起任务；系统在已授权范围内规划并执行，结果和证据供用户查看。各入口的完整业务流程仍按计划推进，不能因为有入口类型就声称已经实现。

目标主链路：

```text
任务与授权 → 受控模板 / 计划 → 校验并保存节点和依赖
          → 根据依赖顺序选择就绪节点 → 按定义装配独立 Agent 实例
          → 执行、记录与结构化交接 → 汇总产物、证据、消耗与状态
          → 用户工作台查看计划和实际运行
```

普通任务可在保存有效计划后按策略自动运行；仅在用户要求审阅或策略要求审批时等待。计划可查询不代表用户一定已经看过。阶段、节点、Agent 定义、节点尝试和 Agent 实例是不同概念：分析、实现、审查可以是阶段或职责，不应继续作为调度器中唯一允许的固定 Agent 分类。

**重点：同一个 Agent 定义可以被同一运行中的多个节点引用。** 每个节点尝试默认创建独立实例、会话、输入、结果和记录；不应以“每种 Agent 只能出现一次”简化设计，也不应跨节点无意复用有状态实例。上下文或证据按权限通过明确的交接或受控记忆传递。不同运行之间也必须保持边界。独立会话本身不能证明共享记忆、缓存或工作区已经隔离。

Agent 是组件的组合：模型、工具列表、上下文来源、记忆策略、Skill 等按定义和授权装配；身份归属、权限、预算、取消、事件及审计等必要底座不能被任意配置绕过。复用 AgentScope 已有的执行、消息、会话等能力，项目负责计划、业务授权、状态、调度、交接、预算、证据和验收。

## 7. 发给实现 Agent 的逐项任务

任务 0 → 1 → 2 → 3 → 4 → 5 → 6。任务 2 复用任务 1 的节点结果，任务 5 基于前面功能落库的结果做验证。某项的外部验证条件缺失时，记录未验证原因和命令，继续完成独立工作。

### 任务 0 · 确认接手基线

1. 在项目根核对路径、当前提交、未提交文件及第 1 节列出的三个动态模板。读 `AGENTS.md`、代码规范、重构概要设计第 4.3、9—12、16 章及当前任务关联设计。
2. 确认测试数据隔离方式，记录既有 API、历史格式及影响面。先判断第 10 节已有证据哪些仍可复用，无需为交接文档或每个小改动重复全量回归。

**完成标准**是留下一条基线记录，包含后续 Agent 可复核的提交或工作区说明、三个模板所在文件、使用的测试环境及已知跳过项。缺少共享工作区改动时，先恢复正确的接手基线。

### 任务 1 · 实现系统检查节点和关卡

1. 先写详细设计，明确计划节点类型、受信执行器、输入输出和状态。在现有计划、API、图摘要与持久化中保存必要的类型及版本；迁移旧节点按已有 Agent 含义读取。优先复用条件认领、共享运行控制和交接事务。
2. 落地真实的系统检查执行路径，可先用于检查前置证据或验证是否可运行。检查结果可被下游引用，记录检查输入版本、结果和原因。保存的计划遇到未支持的类型或版本应显式拒绝。
3. 复用现有计划审阅能力作为人工启动关卡，核对批准前零节点调用。若模板需要节点内用户关卡，先定义等待、批准对象版本及失效规则再接入；当前模板可用明确阻塞表达等待人工核对。

**完成标准**是一次实际动态运行可分别追踪 Agent 节点和系统检查节点；检查节点有按本次计划归属的结果，Agent 实例和模型调用保持零增量。检查不通过时必需下游不启动，重复认领不会重复调度，状态与阻塞原因在 API 可见。未知类型、事务失败和旧记录读取都有可验证结果。对应 A04、A10—A12、A20、A25。

### 任务 2 · 接入模拟 Bug 动态验证

1. 以现有模拟 Bug、显式选择的工作区及文件授权为输入，接入一个可信的版本化模板。从正常建任务入口可选，用服务端规则确认 Bug、工作区、证据及权限，审批和认领前重验。保持既有兼容 Bug 流程可用。
2. 按「复现检查 → 定位 → 按授权修复 → 回归检查 → 独立审查或汇总」组织节点。只读或缺少可信失败观察的路径报告待验证、缺信息或阻塞，禁止进入写节点。修复只可使用现有授权文件工具。
3. 用任务 1 的系统节点接入既有固定检测能力和运行控制。证据绑定运行、Bug、工作区、检查类型及代码指纹；验证读取当前版本的实际记录。保留环境不可用、未发现测试、未复现、测试失败和通过的区别。只读取任务授权且满足证据归属的输出，复用已有容器限制。
4. 在工作台和报告串联每一步、实际回归证据和审查状态，保留用户主动核对与后续决定。

**完成标准**是隔离的普通测试失败样例能追踪复现记录、授权修改、回归证据和独立审查，且能证明只有对应代码版本的有效证据参与判定。跨运行或过期证据、未授权、环境不可用、失败以及取消均不得显示为已验证或继续依赖该证据的写入。检查节点不计作 Agent 或模型调用，不自动合并或关闭 Bug。容器环境缺失时单列真实容器路径未验证，本地模拟的状态测试单独记录。对应 A02、A05、A07、A09、A12、A14、A20—A22、A25。

### 任务 3 · 扩展只读工作区 Checkpoint

1. 先补恢复支持矩阵。实现动态「授权文件分析」在尚未认领节点时的恢复，再实现已结算只读节点后的恢复。复用纯文本恢复流程，按快照版本区分旧纯文本和新工作区边界；绑定批准的计划、任务、授权集合及工作区身份。
2. 在复用已完成分析时，校验已结算来源、真实工具引用和工具实际读取时对应的资源版本。优先复用可靠的授权文件摘要或读取版本；若已有日志只保存摘要说明文本，补齐必要的版本证据。无法证明分析时的版本与恢复时一致、授权或资源变化、存在已认领的后续节点或未结算调用时，拒绝复用并说明原因。
3. 恢复事务创建直接子运行，记录复用关系、来源和继承的模型、工具、时间及已有用量策略，待执行节点从剩余预算继续。子运行认领前再次查验，多次申请同一来源最多成功一次。保留会话中途、写入、Bug 及未知副作用的保守阻塞。

**完成标准**是同一授权及内容版本下，原运行历史保留，子运行可复用安全结果且不重复读取已完成节点，汇总能追溯原调用，预算不会重置。至少验证成功恢复、内容变更或撤权、来源篡改或未结算、以及重复恢复请求；工作台恢复按钮与实际 API 判定一致。只读子运行再次恢复维持现有支持范围，并在矩阵明确标注。对应 A06—A08、A10、A15、A21、A23。

### 任务 4 · 补齐装配、证据、控制与事务边界

1. 对照 A05、A13、A16—A22、A24 核对已有测试及真实入口。选用一条注册的扩展定义进入实际计划，确认无需新增固定角色调度分支；记录所用模型、上下文与证据来源、工具、Skill、授权及预算版本。现有证据足够的能力沿用原实现。
2. 对于缺失证明，补齐定义版本／组件兼容、定义能力与任务授权的交集、过期或越权来源拒绝。依据设计明确必需约束的上下文限额行为，必需约束无法完整装配时阻塞；保留同一定义多个独立实例、无工具和无记忆定义仍走控制底座。
3. 查验取消和终态下的晚到结果。验证认领、装配、交接、终态涉及的事务，及工具预算、超时、取消与未知副作用的现有口径。修复实际发现的缺口，并以失败注入验证变化。

**完成标准**是通过正常入口能观察到版本或授权不满足时拒绝并给出原因，拒绝前无实际越权调用；晚到结果不会把终态改回运行中；事务失败不会留下可被下游消费的半成品。安全重试、既有预算和网关行为仍可追踪。对应 A03、A05、A09—A10、A13、A16—A22、A24。

### 任务 5 · 补齐工作台、指标与种子评测

1. 扩展计划详情与报告，按计划节点显示真实的 Agent 尝试、检查执行、批准或阻塞、证据和历史复用。刷新或事件重连后由持久化查询重建，保留历史缺失项为未知。
2. 对齐事件、运行报告和指标，以实际调用台账计量。分别显示计划节点、系统检查、已启动模型或工具调用、未知 Token、取消、失败及未执行。证据与摘要仅展示适用的授权内容。
3. 在评测中心增加覆盖新能力的可重复用例，至少包含一条安全阻塞反例及一条成功路径。断言实际历史和结构化证据；模板或断言语义有变更时保存新版本，历史定义保留，可比性按定义快照校验。优先使用隔离工作区、确定性输入和本地模拟，外部环境相关用例注明启用条件。

**完成标准**是用户可从任务创建到页面查看和报告追溯一个成功案例及一个阻塞案例；页面刷新后，所有关键状态和引用与数据库一致，未执行的检查不计为成功。评测案例有逐项断言和运行引用，旧套件历史仍可读，不同定义不会被判定为改善或退化。对应 A09、A14—A15、A21、A24—A25。

## 8. 首期边界与开发约定

- 首期使用受控模板和注册定义，**顺序调度**；不要求用户拖拽自由编排、运行中改图、模型自行授权、动态加载不受信插件或并行多 Agent 写入。并行、租户共享部署和复杂后台后续单独设计。
- 现有工具维持可运行与受控接入，当前重点是工具扩展契约和网关，不新增一批具体业务工具。工具结果、拒绝、超时和未知副作用要区分。
- 代码按功能和职责组织；关键类、方法与非直观逻辑使用准确中文注释，固定状态使用枚举，标识、时间和数量选合适类型。Java 遵循项目 Google Java Format 约定。
- 用户希望当前先保证功能，前端视觉优化有明确待办；除满足计划与轨迹展示所需的交互，不擅自把本次重构扩成视觉重做。
- 用户已有本地 DeepSeek 配置；禁止读取、打印、上传、复制或提交 API Key。自动回归优先模拟模型；如果需要真实模型调用，确认已有授权、外发范围及费用风险，实际执行后如实报告。
- 不进行无关清理；用户希望自行删除需要移除的文件和目录。开发测试使用隔离数据库与可控目录，服务结束后正常停止，保留需用户处理的临时目录并说明。
