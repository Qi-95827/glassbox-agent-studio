## 3. A26 · 旧库兼容与服务重启

除上面的旧库启动和重复迁移外，本次发现并修复了一个真实的启动缺陷：

**缺陷**：`schema.sql` 每次启动都会先重新添加旧版 `plan_node_shape` 约束，随后才删除并添加 `plan_node_shape_v2`。当库中已有动态计划且包含系统检查节点时，旧约束要求所有动态节点都有 Agent 定义，检查节点不满足，导致应用在自身数据库上重启失败（`Check constraint violation: PLAN_NODE_SHAPE`）。

**修复**：移除每次启动重建旧约束的语句，只保留最终生效的 `plan_node_shape_v2`；旧库节点仍由 v2 的 AGENT 分支兼容读取。

**回归**：新增 `SchemaMigrationTest.schemaReappliesAfterDynamicPlanWithSystemCheckNode`，在同一内存库上连续执行 3 次完整脚本，库内同时存在动态 Agent 节点和系统检查节点；断言启动不失败、2 个节点和 v2 约束保留。

**实测**：含 3 节点动态计划（含检查节点）的 A15 数据库在修复后成功重启，父子运行、复用节点、尝试和检查均可读。

结论：A26 通过；唯一生产 Java 源码根、组件扫描、静态资源、关键 API、旧接口与旧数据兼容均有本轮证据。
