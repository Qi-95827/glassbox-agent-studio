## 2. 第 2 节行为缺口修复

### A · Flyway 旧库升级

- 新增 `persistence/migration/LegacySchemaColumnCallback`：在 `beforeMigrate` 检查旧表，补齐 `plan_nodes.plan_version_id` 与 `workflow_plans.source_checkpoint_id`，再让 V1 添加外键。
- 新增 `FlywayLegacySchemaConfiguration`，通过 `FlywayConfigurationCustomizer` 接入 Spring Boot 生产路径。
- V1/V2 校验和未改变，已应用 V1/V2 的数据库无需 repair；新增 `V3__run_model_price_bindings.sql` 只做加列。

- `LegacyH2DoubleStartupIntegrationTest` 改为 `spring.sql.init.mode=never`，与生产一致。
- 新增 `FlywayMigrationCompatibilityTest` 四个对照：
  1. 空库：V1+V2，78 张业务表。
  2. 旧 `plan_nodes` 缺 `plan_version_id`：先补列，再建外键。
  3. 重复启动：迁移幂等。
  4. 当前 H2 历史副本：生产 Flyway 配置升级并回读历史。

### B · 异步收口

- `AsyncConfiguration` 统一托管 `workflowRunExecutor`、`planningExecutor`、`evaluationExecutor`；AbortPolicy 明确暴露队列拒绝，优雅停机等待 30 秒。
- `RunCompletionWaiter` 以完成通知替代运行终态轮询；评测等待支持超时、取消与中断传播。
- `BoundedWait` 以可中断有界等待替代 `AsyncDelay`/`Thread.sleep(100)`。
- 规划候选提交拒绝：新候选标记 `FAILED`、释放 pending、保留同组旧候选为 `STALE`；`PlanCandidateQueueRejectionTest` 覆盖。
- 管理版评测提交拒绝：批次标记 `FAILED` 并记录审计；运行评测原有 `created` 回滚路径保留。
- 运行派发拒绝：`RunServiceQueueTest` 保留“失败运行可见、不启动 Agent”。

### C · 混合模型费用预算

- `CostService` 按每次 `ModelCall` 的实际 `ModelKind` 查价，预留记录保存 `price_version_id`。
- `CandidateBudgetValidator` 在候选确认前核对实际模型集合：缺价或跨币种拒绝，并给出原因。
- 支持混合模型、同币种不同单价；预算超限仍在派发前阻断。
- 每个预留的费用接口返回 `PRICE_VERSION_ID/PRICE_MODEL/CURRENCY/INPUT_MICROS_PER_MILLION/OUTPUT_MICROS_PER_MILLION`。
- 前端 `PlanCandidateDialog` 文案更新为按调用计价与同币种要求。
- 新增 `MixedModelCostIntegrationTest`、`MixedModelMissingPriceTest`。

### D · BLOCKED 语义

- 新增 `domain/BlockCategory`：`USER_REVIEW` 与 `EXECUTION_BLOCKED`。
- `RunRecordService.run()` 在 BLOCKED 时附加 `BLOCK_CATEGORY`，保留原 `STATUS/STOP_CAUSE`。
- `BlockCategoryTest` 覆盖检查失败、产物缺失、待审查与非阻塞状态。

## 6. 跳过与边界

- Windows 符号链接用例：宿主机无创建符号链接权限，既有 assumption 跳过。
- Docker 用例：已在本轮启用 Docker 执行；如个别用例因镜像/网络失败，将在最终回归结果中单列。
- `RunRecordService` 仍保留 401 行兼容门面与 223 行只读端口；接入方无需改动，后续可继续迁移到具体服务。
- `WorkbenchTaskController` 放在 `orchestration` 而非 `task`，以避免 `orchestration ↔ task` 循环；按职责拆分，HTTP 契约不变。
- MySQL 仅保留 Flyway 适配依赖与兼容写法，未做真实 MySQL 回归。
