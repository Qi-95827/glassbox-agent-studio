## 1. P1 · Bug 快捷入口默认写权限

**问题**：从「模拟 Bug 验证」点击「基于此 Bug 创建 Agent 任务」后，写入权限被预先勾选，计划审阅被关闭。

**修复**：

- 快捷入口默认 `writeEnabled=false`、`reviewPlan=true`，仍预填 Bug、工作区、`bug-fix` 模板和任务目标。
- 兼容性判断改为显式规则；未勾选写权限时 `bug-fix` 不兼容，并显示“请先勾选允许 Agent 修改所列文件”的提示。
- 新增可重复前端验收用例 `bugEntryDefaults.test.js`：默认关闭写权限、默认审阅、未授权前模板不兼容、授权后才允许创建。

**证据**：`npm test` 2 项通过；`npm run build` 通过。

## 2. P1 · 检查通过后仍使用过期证据

**问题**：容器检查比较执行前后指纹，但调度器消费 `PASSED` 时没有再次核对当前工作区；检查后代码变化仍可能放行修改或审查。

**修复**：

- `bug-fix` 模板升级到 **v2**：修复节点直接依赖复现检查，审查节点直接依赖回归检查；v1 历史计划保留原图。
- 认领下游节点前复核直接依赖中的检查证据：`bug_checks` 的 Bug、工作区、代码指纹必须与当前任务和工作区一致。
- 不一致时抛出 `StaleEvidenceException`，运行进入 `BLOCKED`/`CHECK_FAILED`，依赖节点不启动，原检查记录保留。
- `workflowChecks` 增加 `evidenceCurrent`；运行详情和报告对历史通过但已过期的证据显示“证据已过期”。
- 新增反例 `staleReproductionEvidenceBlocksDownstreamAfterWorkspaceChanges`：检查通过后工作区指纹与记录不一致时，下游认领被拒绝，节点保持待执行。

**回归中发现并修复的连带缺陷**：`StopCause.CHECK_FAILED` 映射到 `BLOCKED` 时，`settleStoppedRun` 的终止事件映射抛出异常，导致调度线程退出、运行停在 `RUNNING`。现改为显式写入 `BLOCKED` 事件；过期证据和检查阻塞路径都由新增用例覆盖。

## 3. P2 · 保存检查点失败影响正常结算

**问题**：只读节点完成后，保存检查点会重新读取授权文件；文件被删除或不可读时异常未转换为“跳过”，可能回滚已完成节点结算。

**修复**：

- 资源读取失败转换为 `UnsafeBoundaryException`，由 `saveBoundary` 记录 `CHECKPOINT_SKIPPED` 并继续，不写出边界。
- 工作区身份读取失败同样按跳过处理。
- 已完成节点的结算和运行继续；该边界不允许恢复。
- 新增反例 `unreadableFileSkipsCheckpointButKeepsSettledNode`：读取后删除授权文件，节点仍结算为完成，无检查点，事件记录跳过原因。

## 4. 真实 DeepSeek 运行补充

用户授权后执行一次真实 DeepSeek 只读运行（`workspace-analysis@2`）。运行成功：3 次模型调用、1 次工具调用、检查通过、输入 2082 / 输出 544 Token。

该运行暴露检查点缺陷：检查节点完成后，边界校验把“已完成节点总数”与“Agent 来源数”比较，导致边界被跳过。已改为只比较已完成 Agent 节点，检查节点单独核对记录数；新增 `savesAndRecoversBoundaryAfterCompletedSystemCheck`。详见[真实 DeepSeek 验证记录](真实DeepSeek验证记录_2026-11-18.md)。

## 5. 历史库重启缺陷

在补齐 A08/A26 时发现：`schema.sql` 每次启动都会先重新添加旧版 `plan_node_shape`，而库中一旦有系统检查节点（无 Agent 定义），旧约束校验失败，应用无法在自身数据库上重启。

已移除启动时重建旧约束的语句，仅保留 `plan_node_shape_v2`；新增 `SchemaMigrationTest.schemaReappliesAfterDynamicPlanWithSystemCheckNode`，在含动态 Agent 节点和检查节点的库上连续执行三次完整脚本。修复后，含动态计划的 A15 数据库可正常重启。
