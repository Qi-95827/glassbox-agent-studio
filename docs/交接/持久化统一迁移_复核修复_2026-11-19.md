## 1. AgentScope 列表追加重复

- **问题**：旧 JDBC 存储写入 `[A,B]`，新 JPA 存储保存 `[A,B,C]` 后读回 `[A,B,A,B,C]`。追加分支从正确的数据库位置开始，但仍从输入列表第一个元素读取。
- **修复**：`JpaAgentStateStore.save(list)` 的追加分支改用 `values.subList(existingCount, values.size())`，只写新增尾部。
- **反例**：`AgentStateConfigurationTest#listAppendFromLegacyJdbcStoreWritesOnlyNewTailAndReadsAfterReopen` 先用真实 `JdbcAgentStateStore` 写入 `[A,B]`，再用 JPA 适配保存 `[A,B,C]`，重建适配器后读回 `[A,B,C]`。
- **状态**：已通过。

## 2. 同键并发首次无条件保存主键冲突

- **问题**：两个无条件 `save` 同时走到插入，一次成功、一次抛出 23505。
- **修复**：无条件保存增加有限重试：主键冲突导致事务回滚后，在新事务中改为更新；`saveIfVersion` 的过期版本拒绝逻辑不变。
- **反例**：`AgentStateConfigurationTest#concurrentUnconditionalSavesDoNotExposePrimaryKeyConflict` 两个线程同时保存同一键，均完成，最终可读且版本恰好为 2；既有 stale version 断言继续通过。
- **状态**：已通过。

## 3. 历史未知状态阻断交接校验

- **问题**：写入 `FUTURE_STATUS` 后，`isCompletedAgent` 读取枚举抛异常，而不是走“上游 Agent 尚未完成”的拒绝路径。
- **修复**：把 `status = COMPLETED` 放回查询条件，只计数匹配行，不再加载未知枚举值。
- **反例**：`InvocationUnknownStatusIntegrationTest#unknownHistoricalStatusIsTreatedAsNotCompletedWithoutThrowing` 将真实 Agent 状态改为 `FUTURE_STATUS`，断言 `isCompletedAgent` 返回 false 且不抛异常，完成分析读取为空。
- **状态**：已通过。

## 第二轮复核修复

### 6. 旧库双启动测试实际打开了原库

- **问题**：`SpringApplicationBuilder.properties()` 设置的是默认属性，被 `application.properties` 覆盖；测试实际连接 `data/workbench.mv.db`。
- **修复**：改用命令行参数 `--spring.datasource...`；把环境地址校验放进 `ApplicationContextInitializer`，在上下文刷新和任何数据库连接之前失败；启动后继续用 JDBC 元数据确认实际连接是临时副本。`LegacyH2StartupIntegrationTest` 也补上生效地址断言。
- **验证**：连续两次启动用例通过；运行前后 `data/workbench.mv.db` 的大小和修改时间未变化（425984 字节，2026-11-19 20:17:24）。

### 7. `saveIfVersion(UNVERSIONED)` 并发插入冲突

- **问题**：`UNVERSIONED` 分支没有复用无条件保存的重试，两个请求同时插入同一新键时一个抛出 23505，最终版本只有 1。
- **修复**：`saveUnconditional` 在写入事务内返回最终版本，`save(State)` 与 `saveIfVersion(UNVERSIONED)` 共用；冲突回滚后在新事务改为更新；显式版本路径仍对过期版本返回 `UNVERSIONED`。
- **强制反例**：新增 `protected beforeInsert()` 同步点，两个请求都完成“更新 0 行”后同时插入，确定触发主键冲突；断言两次分别返回 1、2，最终版本恰好 2。普通 `save` 并发用例也收紧为最终版本恰好 2。
- **状态**：已通过。
