## 1. 最终结构

- 业务入口：Controller → Service → Spring Data JPA Repository。
- 实体：`backend/src/main/java/dev/workbench/persistence/entity`，共 52 个映射。
- Repository/持久化适配器：`backend/src/main/java/dev/workbench/persistence/repository`，共 51 个文件。
- 复杂多实体查询、聚合和条件更新集中在 Repository；普通主键/单表操作使用 `JpaRepository` 继承方法或派生查询。
- `spring.jpa.hibernate.ddl-auto=none`，`spring.jpa.open-in-view=false`，表结构继续由 `schema.sql` 管理。
- AgentScope 会话由 `persistence/agentscope/JpaAgentStateStore` 接管，继续读写原有 `agentscope_sessions` 表格式。

## 4. 保留的特殊查询

| 位置 | 查询 | 理由 |
| --- | --- | --- |
| `SystemCatalogRepository.ping()` | `SELECT 1` | 数据库连通性探测，不依赖业务实体；H2 验证。 |
| `SystemCatalogRepository.countPublicTables()` | `information_schema.tables` 计数 | H2 系统目录元数据，JPQL 无可移植表达；启动和测试均在 H2 验证。 |
| `ObservabilityRepository` 的 agent/model/tool 状态聚合与未知状态计数 | 原生 `status` 聚合 | 历史行可能含未知状态编码（测试使用 `FUTURE_STATUS`）；实体状态为枚举，直接 JPQL 会因未知枚举值失败。保留原始文本用于统计和显示。 |
| `EventRunSequenceMigration` | JPQL 按 `run_id,id` 回填 `run_seq`，与 `event_run_seq_v1` 标记同事务 | 保持历史事件提交顺序和重复启动幂等。 |

除以上位置外，没有 `nativeQuery=true` 或数据库特定业务 SQL。
