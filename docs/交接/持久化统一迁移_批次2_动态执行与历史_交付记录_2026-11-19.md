## 1. 迁移入口

原 `dev.workbench.persistence` 下的 Hibernate Store 已替换为 `dev.workbench.persistence.repository` 中的 Repository/持久化适配器：

| 原入口 | 迁移后 |
| --- | --- |
| `PlanGraphStore` | `PlanGraphRepository` |
| `PlanStateStore` | `PlanStateRepository` |
| `WorkflowExecutionStore` | `WorkflowExecutionRepository` |
| `WorkflowRecoveryEvidenceStore` | `WorkflowRecoveryEvidenceRepository` |
| `SupplementStore` | `SupplementRepository` |
| `RunCheckpointStore` | `RunCheckpointRepository` |
| `InvocationStore` | `InvocationRepository` |
| `HandoffStore` | `HandoffRepository` |
| `HandoffEvidenceStore` | `HandoffEvidenceRepository` |
| `AgentConfigurationStore` | `AgentConfigurationRepository` |

调用方已切换：`PlanService`、`WorkflowScheduler`、`WorkflowExecutionService`、`WorkflowRecoveryService`、`TaskSupplementService`、`RunRecordService`、`HandoffValidator`、`ExecutionViewService` 等。

## 2. 删除的旧路径

- 删除上述 10 个 Hibernate Store 和 `HibernateSessions` 适配器。
- 所有 `Session.createSelectionQuery` / `createMutationQuery` 调用已移除。
- 复杂多实体投影、聚合和条件更新集中在 `persistence.repository`，使用 Spring 管理的 `EntityManager` 与 JPQL；常规单表/主键操作继续使用继承方法或派生查询。

## 3. 保留的特殊查询

- 运行/任务行锁：`@Lock(PESSIMISTIC_WRITE)`，保证节点认领、事件排号和审批串行化。
- 计划确认：带 `review_required`、`approved_at is null`、`id` 和 `run_id` 条件的更新，按受影响行数判定。
- 节点认领/完成/重新排队：带节点状态、运行、Agent 和计划版本条件。
- 恢复边界：运行、节点、检查、调用和文件证据的聚合查询保留在 Repository；没有新增数据库特定原生 SQL。
- 事件回填仍由批次 8 处理。
