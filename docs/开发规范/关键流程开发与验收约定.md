# 关键流程开发与验收约定

> 用于审批、状态迁移、恢复、外部操作、证据判定、评测对照和报告导出。普通文案和展示调整按原有风险匹配规则验证。保持一个功能闭环结束后集中回归一次的节奏。

## 实现前先写清楚五件事

在该功能的任务说明或详细设计中，用几行写清下列内容。常规改动可以直接写在交付记录中。

1. **要保持的业务条件**。写成可证伪的句子，例如「批准合并后，目标分支的新提交不能被这次批准合入」，或者「第二次无改动交还不能解除第一次修改造成的证据失效」。
2. **当前事实从哪里取**。指出权威记录、稳定标识和版本。区分实际执行与页面状态、历史通过与当前有效、运行新增调用与继承消耗。
3. **什么时候重新核对**。列出动作执行前、资源改变后、用户再次操作时或续跑时必须检查的条件。明确哪些字段能清除阻塞，谁有权改变它们。
4. **失败会留下什么**。分清数据库事务、文件系统及远端动作的边界。明确哪些状态必须回滚，哪些证据要留下，哪些未知结果要转人工核对。
5. **如何证明**。每条关键条件至少给一个能区分正确实现与错误实现的观察。既有测试覆盖同样的条件时引用它，缺口才补用例。

## 按改动选反例

下表是从已有复验中提炼的检查项。只选与本次改动相关的场景。涉及多步流程时，除了单步拒绝，还要尝试下一次合法操作是否会误清除原有阻塞。

| 改动类型 | 优先验证场景 | 应观察的结果 |
| --- | --- | --- |
| 审批后执行 Git 或外部写入 | 审批后变更远端、源提交或待合入版本。核对之后、调用之前改变指向 | 实际请求只使用该次校验通过并固定的目标与内容。审批对象变化时拒绝并要求重新确认。校验读到的地址或提交不能在执行阶段被另一次查询悄悄替换 |
| 人工接手、暂停、恢复、再次继续 | 修改后交还，再接手且无改动后交还，再调用继续接口。刷新或服务重启后核对 | 旧证据失效持续有效，直到明确规则确认当前版本已重新验证，或创建新运行。前端不能仅按最近一次操作决定按钮，服务端也要拒绝 |
| 文件写入、补充、记录入库 | 不同任务在同一工作区提交同路径。在文件写入后让数据库记录失败，再重试 | 最多一个请求成功，已存在内容及成功请求的摘要一致。清理只针对本次写入。验证请求状态、版本、调度次数和最终文件，而不只检查异常文字 |
| 测试证据与交付 | 混合失败、相似测试名、相似断言、目标跳过。通过后按正常入口改动被测文件 | 用逐用例稳定标识及完整规范化断言判断，只有目标确实执行并通过才产生该版本的回归通过。旧通过保留，当前交付明示过期，页面与报告一致 |
| 事件增量与计量 | 同一运行晚提交、断线超过一页、切换运行、恢复后混有继承与新增调用 | 增量与持久化记录相符，没有遗漏或重复。补齐积压前不显示已同步。继承用量与本次实际调用分别展示 |
| 评测条件与比较 | 套件相同而轮次、工具、时限或其他受控条件不同。旧配置或用量缺失 | 使用可验证的实际生效条件决定可比性。预算条件不同要说明差异，不能把它标为质量改善。未知字段保持未知 |
| 权限、导出与脱敏 | 绕过按钮直接调用接口、权限撤回、含空格路径及实际导出内容 | 服务端独立拒绝不合法操作，受保护范围内无未授权副作用。校验导出正文和相关字段，明确规则支持范围 |

对拒绝用例，优先断言**目标没有收到修改、下游没有启动或旧记录没有被改写**。拒绝本身的审计可以保留。对超时和未知结果，验证有可查状态以及人工核对入口，避免把结果未知算成成功或失败后自动重放。

## 自验流程与提交证据

1. **先验证反例能区分错误实现。** 能在隔离样本复现旧问题时，记录旧行为。新功能也可以用同一流程只改一个关键条件，对照正常和拒绝结果。证据优先经过实际服务、入口或持久化路径。
2. **实现后集中验证。** 同轮运行相关反例、主链路和受影响的既有测试。涉及流程图、报告或审批入口时，加一次实际页面、API 与落库结果对照。确定性反例使用隔离库、临时仓库或固定测试输出。真实模型只在已有授权且需要验证实际模型与工具交互时选用代表性样本。
3. **按要求标明状态。** 交付区分「已通过」「部分通过」「未实现」「未验证」，并列出对应需求、命令或操作、实际结果和证据位置。保留被跳过的用例与原因。任务范围缩小时，把被移出的原要求列为未交付，不能用全量用例数或当前交付范围代替原任务逐项对照。
4. **完成后直接推进下一项。** 已有有效证据可复用，无需每个小改动再跑全量。需要真实环境而当前缺失时，先完成能独立验证的工作，并保留未验证范围。

交付记录可使用下面的最小表格。

| 需求或业务条件 | 正常路径与一个相关反例 | 实际结果及证据位置 | 状态 |
| --- | --- | --- | --- |
| 合并的批准绑定待合入提交 | 相同版本可合并；批准后目标分支新增提交则拒绝 | 测试名称、执行结果、工作区和目标提交是否改变 | 按实际填写 |
