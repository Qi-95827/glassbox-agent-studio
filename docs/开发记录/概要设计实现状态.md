# 动态工作流重构验证

本轮验证覆盖同定义多节点、双前置汇合、角色权限上限、审批前无调用、累计预算、取消及认领回执失败的事务回滚。恢复验证覆盖已结算边界、跨运行来源、已报告用量继承、结果被修改和边界后已认领时的拒绝。使用隔离旧 H2 文件副本核对角色、依赖和预算数据，并验证同一迁移执行两次和按迁移前文件恢复。[详细设计](../概要设计/重构_动态工作流计划迁移与顺序调度设计.md)

系统检查节点的验证覆盖：只读模板中检查通过后下游获得检查结论和独立接收收据、无读取证据时检查失败并阻塞下游、重复认领被拒绝、检查记录写入失败时节点与检查记录整体回滚、未注册检查在写入计划前拒绝、旧角色计划节点按 Agent 类型读取。检查节点不产生 Agent 实例、模型或工具调用。[系统检查节点设计](../概要设计/重构_动态系统检查节点设计.md)

模拟 Bug 动态工作流在启用 Docker 的隔离临时仓库中验证：固定容器复现失败后，授权修改使回归通过，检查记录保存运行、Bug、工作区、检测类型和代码指纹，独立审查接收回归证据，运行保持等待用户核对且不自动关闭 Bug。另验证复现缺信息、环境不可用、未复现、过期、回归失败、取消、确认前零调用及模板授权拒绝。[动态 Bug 修复工作流设计](../概要设计/重构_动态Bug修复工作流设计.md)

只读工作区恢复验证覆盖首个节点前和已结算分析后的成功恢复、分析结果复用与预算继承；文件内容变化、授权集合变化、来源结果篡改、后续检查已认领、重复恢复和恢复子运行再次恢复均被拒绝。工具版本证据来自实际读取调用，纯文本历史边界算法与用例保持兼容。[只读工作区恢复设计](../概要设计/重构_动态只读工作区恢复设计.md)

动态检查评测覆盖只读工作区检查通过和 Bug 复现缺信息阻塞；运行详情和报告按持久化记录显示计划节点、检查、实际调用与未知用量。使用隔离内存数据库启动应用，通过 HTTP 创建、确认并执行双视角计划，浏览器核对计划、尝试、装配、指标和事件。独立审查后补充：Bug 快捷入口默认不授予写权限；检查证据在被下游消费前复核当前代码指纹，过期显示“证据已过期”；检查点保存遇到不可读文件时跳过而不影响节点结算。经用户授权执行一次真实 DeepSeek 只读运行，3 次模型调用、1 次工具调用、检查通过，并修复检查后边界保存缺陷。实际历史 H2 副本已连续启动两次并重复迁移，旧任务、运行、交接和检查点可读；修复了含系统检查节点的动态计划导致应用无法重启的旧约束缺陷。恢复子运行的页面刷新和事件断线重连已用真实浏览器验收。完整回归 188 项，失败 0、错误 0、跳过 1；前端测试 2 项和构建通过。A01—A26 逐项结论见[最终验收清单](../交接/A01-A26_最终验收清单.md)，迁移和恢复页面证据见[验收记录](../交接/历史库迁移与恢复页面验收_2026-11-18.md)。
