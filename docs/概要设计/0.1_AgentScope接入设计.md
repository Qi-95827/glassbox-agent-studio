# 0.1 AgentScope 接入与迁移设计

> 2026-11-11。用户确定复用 AgentScope Java，不自行建设通用 Agent 执行框架。本文先明确本次变更的范围；实际完成情况以开发记录和验证结果为准。

## 目标与职责

- 使用 AgentScope Java 的 `ReActAgent`、模型接口和 Toolkit 执行模型决策、工具调用、工具结果输入模型和最终回答；真实 DeepSeek 和确定性模拟模型都走同一个框架循环。
- 保留项目层任务、运行、持久化、页面、事件、预算和取消等已有能力，通过框架允许的模型／工具边界接入；不把框架内核再实现一遍。
- 首期仅注册无外部副作用的模拟工具，不开放文件、Git 或命令。模拟模型仅用于确定性测试；真实 DeepSeek 模式由模型决定工具调用，不能以固定流程冒充。
- AgentScope 选定版本及实际依赖能力以本地构建和官方版本文档为准；先采用 ReActAgent 小范围接入，不假称已经启用 Harness、长期记忆、多 Agent 或生产安全沙箱。

## 兼容与限制

- 延续已有任务入口、DeepSeek 密钥文件、轮次／工具次数／时间限制和前端运行记录。额度检查应在模型和工具实际发起前执行；支持取消的外部请求应传播停止信号。
- 框架实际事件及项目记录需要能对应。Token 以服务实际返回为准，未知时保留未知；工具成功、失败、取消和结果未知不得混淆。
- 当前旧检查点只保存手写流程的节点和模拟结果，并非 AgentScope 会话状态；不能把旧快照当成框架快照继续执行。迁移时保留历史记录，并在实际支持的范围内提供明确的恢复方案；无法安全恢复时拒绝并说明。
- AgentScope 的默认内存、工具与会话是框架能力，项目仍需在安全策略、数据生命周期、版本兼容和多租户方面验证；不得因引入依赖而宣称相关需求已完成。

## 验证要求

1. 无密钥自动测试使用 AgentScope 与可控模型：至少验证模型发起工具调用、工具执行、结果返回模型、最终回答及事件记录。
2. 验证工具和模型调用次数限制、失败、取消、时间限制、恢复边界，以及原有历史任务查询。
3. 使用用户已授权的 DeepSeek 密钥执行小规模真实验证：确认实际调用由 AgentScope 发起，工具调用来自模型返回而非程序固定调用；不输出密钥，记录实际 Token 和费用不确定性。
4. 所有原有测试根据真实行为更新，不降低验证要求；前端展示需区分真实 Agent 和模拟数据。
