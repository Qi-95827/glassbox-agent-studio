# 0.1 Agent 框架概要设计

> 状态：概要设计草案，2026-11-11。本文是 0.1 实现前的设计依据，不代表功能、接口、数据存储或技术选型已经实现或验证。依据：[0.1 迭代计划](../迭代计划/0.1_框架骨架.md)、[迭代总览](../迭代计划/README.md)和《可视化代码开发Agent_统一功能与概要设计》。本阶段先完成设计，不开发业务代码。

## 1. 目标与交付边界

0.1 建立一个**能真实运行的 Agent 框架最小闭环**：个人用户从页面发起模拟任务，协调者委派 Agent，Agent 在限定轮次内通过模拟模型决定并调用模拟工具，系统记录事件和状态，页面据此展示过程；运行中可执行基础限制和取消，并在预先定义的安全节点保存状态，在中断后从有效状态恢复。

这里的“模拟”指模型与工具使用受控的确定性行为，**运行、工具调用、事件产生、限制检查和恢复动作本身都必须真实发生**，不是预先写死一段页面动画。目的在于验证框架模块、控制和观察链路，而不是证明真实代码开发能力。

### 1.1 0.1 要交付

1. 一个个人使用的本地运行入口，以及最小用户任务页面。
2. 一个运行协调者、一个可配置的模拟 Agent 角色、一次实际的子任务委派和结构化交接。
3. 模拟模型适配器与一个无外部副作用的模拟工具；至少覆盖正常、失败和可等待／可取消的测试情形。
4. 运行状态、事件、基本时间和调用次数；刷新页面后仍能读取已保存记录。
5. 轮次、工具调用次数和运行时间限制，以及显式取消与失败状态。
6. 在规定安全节点保存内部 Checkpoint，支持终止进程后重新启动并从有效快照恢复；提供明确的失败提示。
7. 最小平台概况：服务健康、运行数量或状态与入口链接；便于学习和排障，不等同于完整后台。
8. 不依赖真实模型密钥的自动化验证、启动／停止说明、已知限制及示例。

### 1.2 0.1 不交付

真实 LLM、真实仓库读取／写入、Git 自动建分支或合并、Shell／测试命令执行、真实 Bug 获取、HTML 交付报告、长期记忆、多人协作、租户隔离、复杂 Agent 并行、分布式恢复、生产级监控告警和商业计费。相关目录可以有职责说明，但界面必须标记为不可用或不展示；不能提供假成功实现。

不以 Redis、Milvus、RabbitMQ、Prometheus 或 Grafana 成为 0.1 启动前提。既有 Grafana 复用方向保留，实际接入和原环境可用性后续验证。模拟结果不应标成真实代码修改或 Bug 修复。

## 2. 使用方式与演示场景

### 2.1 使用者

第一版按**个人在本地使用、单个后端进程**设计。操作者可以通过页面创建和查看任务，也可以访问基础概况页面。系统记录本地所有者标识作为未来边界的一部分，但它不是登录认证，更不能声称实现多用户或多租户隔离；0.1 不应暴露为未经保护的公网服务。

### 2.2 示例任务

页面提供一个可重复的示例，例如“请分析模拟问题并整理下一步建议”。用户可编辑有限的任务描述并选择预设场景：正常、模拟工具失败、慢速工具／取消。输入是演示材料，不连接实际代码仓库。

正常场景：

1. 用户创建任务，系统生成任务和运行标识，任务进入待执行。
2. 协调者生成一个简单子任务，将其委派给模拟分析 Agent。
3. Agent 通过模拟模型获得“调用模拟工具”的结构化指令；运行控制器先检查轮次、工具次数、时限和取消状态。
4. 模拟工具根据受控输入返回固定但真实执行产生的结果。系统记录调用开始、结束、结果和耗时。
5. Agent 接收工具结果，经模拟模型形成结构化结论，交回协调者；协调者完成运行并保存结果。
6. 用户页面展示实际发生的状态与事件；刷新后仍可读取。

如果被限制、取消、模拟失败或进程中断，展示对应状态、原因和已产生的记录，不生成虚假的成功结论。

## 3. 整体逻辑结构

```text
个人用户
   │ 创建 / 查看 / 取消 / 选择恢复
   ▼
用户工作台 ────────────── 基础平台概况
   │ 查询任务、运行、事件和恢复状态
   ▼
应用入口 / 任务服务
   │
   ├── 运行协调者 ── 计划一个子任务并委派
   │       │
   │       ▼
   │   Agent 运行实例 ── 模拟模型 ── 模拟工具
   │       │                     ▲
   │       └── 运行控制（轮次、工具次数、时间、取消）
   │
   ├── 事件与运行记录 ── 页面查询 / 时间线
   └── Checkpoint ─────── 持久保存 / 单进程恢复

以上模块共用本地持久化；具体构建方式和存储产品在详细设计时确认。
```

0.1 是单进程逻辑分层，不要求微服务、消息队列或每个模块单独部署。用户工作台和基础概况可以在一个前端应用中实现。模块文件夹用于按职责导航，不代表每个文件夹都必须实现接口或单独运行。

## 4. 模块及责任

| 模块 | 0.1 职责 | 输入 | 产出与限制 |
| --- | --- | --- | --- |
| 应用入口 | 接收页面请求、启动服务、装配已实现模块 | 创建／查询／取消／恢复请求 | 返回明确结果；不暴露未实现的真实工具 |
| 任务与运行 | 创建任务及运行，保存目标、状态与所有者占位 | 用户输入、运行事件 | 当前状态、历史运行和结果；默认单人单进程 |
| 协调者 | 选择固定的示例流程，生成并委派一个子任务 | 任务、当前状态 | 子任务、委派记录与汇总；不是自主无限规划 |
| Agent 核心 | 根据角色和上下文执行受限循环，处理模型和工具结果 | 子任务、角色配置、控制上下文 | 结构化结果及执行状态；不得跳过控制器 |
| 模拟模型 | 根据预设场景产生可重复的下一步指令或结果 | 当前上下文和场景 | 模拟输出；调用真实发生，但不是 LLM 推理 |
| 模拟工具 | 执行固定的无外部副作用操作，可模拟失败或延迟 | 经校验的参数 | 结果、失败或取消；不读写仓库、不访问网络 |
| 上下文 | 保存当前目标、子任务、必要工具结果和证据引用 | 任务、模型／工具结果 | Agent 可消费的运行上下文；无长期记忆 |
| 运行控制 | 检查轮次、工具次数、时间和取消信号 | 当前额度和动作请求 | 允许／拒绝与原因；不依赖 Agent 自觉停止 |
| 事件与记录 | 记录关联事件、状态、调用次数、时间和必要结果 | 模块产生的事实 | 用户可查询的历史；事件不能由模型自报代替 |
| Checkpoint | 保存和读取安全节点内部状态、校验版本与完整性 | 当前可保存的运行状态 | 有效快照或明确失败；不负责 Git 工作区 |
| 最小工作台 | 创建任务、查看过程、取消和恢复 | 实际服务状态与事件 | 任务列表／详情／时间线；不展示虚构状态 |
| 基础概况 | 显示服务可用性、运行状态计数和已实现功能 | 后端健康与运行记录 | 基础排障页面；非完整管理后台 |
| 验证与示例 | 对正常与异常路径执行可重复检查 | 固定场景、运行结果 | 可复现的验证结果，不依赖真实模型服务 |

在代码层面，AgentScope Java 是已讨论的候选框架，0.1 保留集成方向，但**其当前版本、许可证及模拟模型和控制能力需要开发前核验**。项目自己的任务、预算、事件、恢复及安全责任不因为采用框架而自动完成。若核验后框架不能支持可重复的本地模拟，需记录替代方案和影响，而不是假设已经支持。

## 5. 运行对象和结构化交接

本节规定概念与必要信息，不冻结接口名称、数据库表或类结构。

| 对象 | 本期需要的信息 | 说明 |
| --- | --- | --- |
| 任务 | 标识、本地所有者占位、目标、场景、创建时间 | 个人任务；标识不代表身份验证 |
| 运行 | 标识、所属任务、来源运行（恢复时）、状态、起止时间、结果／原因 | 恢复时创建关联的新运行，保留原运行历史 |
| 子任务 | 标识、目标、角色、状态、预期结果 | 本期固定一个示例子任务 |
| Agent 实例 | 标识、角色、所属运行／子任务、状态 | 角色配置与一次调用实例分开 |
| 工具调用 | 标识、所属 Agent、工具名、输入摘要、状态、输出或错误、耗时 | 输出必须来自实际调用；避免记录敏感信息 |
| 交接 | 来源、接收方、目标、约束、状态、产物／证据引用 | 0.1 至少记录一次委派及一次结果返回 |
| 事件 | 标识、运行内顺序、任务／运行／关联对象、类型、发生时间及必要内容 | 事件表达事实；顺序以持久记录为准，时间用于展示 |
| Checkpoint | 标识、原运行、版本、节点、创建时间、内容完整性、状态和事件位置 | 内部状态快照；无代码文件或 Git 提交保证 |

结构化结果至少表达：任务／子任务标识、执行状态、简要结果、已执行的工具及结果引用、失败或未完成原因。模拟输出需要明确标识来源。后续增加角色和工具时，应在现有语义上扩展，而不是依赖任意自然语言猜测状态。

## 6. 状态与执行流程

### 6.1 运行状态

| 状态 | 含义与允许操作 |
| --- | --- |
| 待运行 | 已创建，尚未开始；可取消 |
| 运行中 | 正在协调、执行 Agent 或等待模拟工具；可请求取消 |
| 已完成 | 所有本期步骤完成并记录了结果 |
| 已失败 | 模型／工具模拟失败或内部错误；显示原因 |
| 已取消 | 取消信号被处理并停止新增动作；显示最后已知状态 |
| 已超限 | 轮次、工具次数或运行时间达到限制；显示具体原因 |
| 中断待处理 | 进程异常结束后未正常结束的运行；可查看有效快照并发起恢复 |
| 恢复失败 | 恢复请求因快照损坏、版本不兼容或状态不满足而未能创建可运行的新运行；显示原因 |

创建后由待运行进入运行中，运行中以完成、失败、取消、超限或中断待处理结束。进程重启后，原本处于运行中的记录需要按规则识别为中断待处理，不能自动显示完成。恢复成功是**新运行**，关联原运行和所选快照；原运行保留中断记录。恢复失败应保留请求结果和原因，不修改原有历史。

0.1 不要求通用暂停／继续；取消不是暂停，取消后的任务不自动重新启动。为避免对并发恢复做超出能力的承诺，本期只允许单进程持有本地数据并串行执行恢复操作；检测到另一实例占用时拒绝启动或拒绝恢复。跨进程分布式协调留待后续。

### 6.2 关键事件

至少记录任务创建、运行开始／结束、子任务创建／委派、Agent 开始／结束、模型调用开始／结束、工具调用开始／结束或失败、结果交接、限额触发、取消请求／生效、Checkpoint 成功／失败、中断识别、恢复请求／成功／失败。页面展示按事件关联生成，不由模型描述推断。

一次调用开始后可能因中断没有结束事件；页面显示“中断时结果未知／未完成”，不能自行填充成功。事件记录不得因查询失败就伪造空结果；展示不可用提示并允许刷新。实时推送不是 0.1 必要条件，**定时查询加刷新恢复**足以满足本期可观察性，后续再研究推送和断线游标。

## 7. 控制、限制和异常

### 7.1 限额定义

- **Agent 轮次**：每次请求模拟模型决策前计数并检查，达到上限不再开始下一轮。
- **工具次数**：每次实际准备调用模拟工具前检查并计数，失败的调用也计入；达到上限不再开始调用。
- **运行时间**：从运行开始计算，超时后不再启动新动作，要求可取消模拟操作尽快结束；0.1 不承诺可强制中止任何外部进程。
- **取消**：用户请求后记录取消请求，控制器向正在等待的模拟操作传播并阻止新动作；确认停止后标记已取消。如果运行已完成，应返回当前真实状态，不得改写历史。

每次恢复要携带原快照中已消耗的次数，不因新运行而归零；运行时间在 0.1 按**本次运行实际执行时间累计**，不把进程停止期间算作执行时间，并保存已消耗部分。恢复后若剩余额度不足，直接显示超限。是否允许调整预算和如何统计真实模型 Token／成本留待后续。

### 7.2 错误策略

模拟模型／工具错误、参数错误、存储失败、快照无效、限制触发和取消分别表示，不全部转成成功结果或同一个模糊错误。本期默认不自动重试模拟工具；重新发起任务或恢复必须是明确的用户操作。记录阶段性结果，但未完成的任务不能标记完成。

## 8. Checkpoint 与恢复概要

### 8.1 适用范围与安全节点

本期 Checkpoint 是**系统内部状态快照**，独立于 Git，不保存仓库文件。仅支持单进程、一个示例子任务、无外部副作用的模拟场景。初始计划在以下节点保存：

1. 子任务已创建、Agent 尚未开始模拟工具调用前。
2. 模拟工具返回并已被记录、Agent 尚未生成最终结果前。

实际实现要确保快照状态与其记录的事件位置一致：先完成该节点已确认的数据，再以可检测完整性的方式保存并发布快照；不完整快照不能被选择为有效。存储事务、原子写入等具体机制属于详细设计，但必须通过故障测试证明节点不会呈现为“快照完整、关联状态缺失”。如果无法满足，应将其标记不可恢复。

### 8.2 保存内容

保存任务目标和场景、原运行和子任务／Agent 标识、当前节点、必要上下文与已确认的模拟结果、控制限额和已消耗数值、事件位置、快照格式版本及完整性信息。原始事件保留在运行记录中，不能仅靠摘要重建实际发生过什么。

### 8.3 恢复流程

1. 启动时发现未正常结束的原运行，标记为中断待处理，列出可用或无效快照。
2. 用户明确选择有效快照；系统检查格式、完整性、任务归属、控制额度与单进程占用。
3. 创建关联新运行，加载安全节点状态及已消耗额度，记录恢复来源；原运行和快照之后已经发生的事件继续保留供查看。
4. 从所选节点继续模拟执行，产生新的事件和结果。由于只允许无外部副作用的模拟工具，本期可以在工具调用前节点重新执行该模拟工具；页面须区分两次运行，不能将历史事件伪装成新调用。
5. 如果快照无效、版本不兼容、存储不可用或额度已耗尽，明确拒绝或结束，并展示原因。

0.1 不支持从已完成或已取消的任务通过恢复绕过用户决定，也不承诺恢复真实外部写入。后续接真实 Git、网络或命令前，必须另行实现外部动作结果核对、权限重新验证和工作区保护。

## 9. 页面与交互

### 9.1 用户工作台

| 区域 | 本期展示 | 本期操作 |
| --- | --- | --- |
| 任务列表 | 任务目标、最新运行状态、创建／更新时间 | 创建示例任务、进入详情 |
| 创建任务 | 描述、模拟场景和可配置的基础限额 | 创建并启动；说明模型和工具均为模拟 |
| 任务详情 | 任务／运行状态、子任务、Agent、结果和错误 | 取消运行；中断后查看并选择有效快照恢复 |
| 过程时间线 | 协调、Agent、模拟模型和工具、事件时间与耗时 | 展开实际结果和原因；查看原运行与恢复后运行 |
| 资源／控制 | 已用轮次、工具次数、执行时间和剩余额度 | 查看停止原因；0.1 暂不要求运行中调整额度 |

页面至少通过定期查询显示运行进展；刷新时从持久记录还原。调用次数、耗时来自真实记录；没有真实模型 Token 或费用时显示“未采集／不适用”，不显示零费用作为结论。

### 9.2 基础平台概况

展示服务是否可访问、已保存任务／运行数量、运行中／终态数量和本期模拟能力说明；允许进入对应用户任务详情。此页暂不提供租户管理、真实配置发布、Grafana 嵌入或评测中心。计数应说明统计范围及数据是否可用。

## 10. 技术与部署决策的边界

| 事项 | 0.1 概要决定 | 开发前／详细设计需确认 |
| --- | --- | --- |
| 后端 | Java 单进程、模块化；模拟模式无需真实模型凭据 | JDK、构建工具、具体框架及依赖版本；本机环境可用性 |
| Agent 框架 | 优先核验 AgentScope Java 的适用性 | 官方版本、许可证、模拟适配与控制能力；不满足时记录方案 |
| 前端 | 单个本地应用覆盖工作台与基础概况 | 技术栈、开发端口与构建方式；避免占用已有 Grafana 端口 |
| 持久化 | 本地可重启保存任务、事件与快照 | 具体存储方式、原子性、路径、备份和损坏处理；以验收为准 |
| 通信 | 页面请求后端获得状态与事件；允许定时查询 | 协议与接口形态留待详细设计，不预设必须使用推送 |
| 安全 | 个人本地、无真实危险工具；数据默认不发外部模型 | 启动绑定地址、访问边界、日志脱敏；不是完整认证或租户隔离 |

优先让干净环境按文档启动。现有 Docker 服务和 Grafana 是后续可复用资源，不作为本期硬依赖。任何具体版本与环境能力均在实施前核实，不在本文假定已经安装或可运行。

## 11. 可验证的验收场景

| 编号 | 场景 | 预期 |
| --- | --- | --- |
| A01 | 干净环境按文档启动 | 无真实模型密钥可进入页面，清楚标明模拟模式 |
| A02 | 正常示例 | 创建任务，看到真实委派、Agent、模型、工具、交接和最终结果，关联标识一致 |
| A03 | 页面刷新／重启后查询 | 已持久化的任务、事件、结果仍可读取，时间线无伪造事件 |
| A04 | 模拟工具失败 | 看到实际失败、原因与已完成事件，不展示成功结果 |
| A05 | 轮次／工具次数上限 | 分别触发超限，不启动超出额度的后续动作，记录实际消耗 |
| A06 | 运行时间限制 | 模拟慢操作在超时后按本期能力结束，不启动新动作，状态及原因可见 |
| A07 | 用户取消 | 等待中的模拟操作接收取消；不再开始新调用，页面显示取消结果 |
| A08 | 安全节点中断与恢复 | 终止进程并重启，原运行标识中断；用户选择有效快照，创建新运行并继续，历史可区分 |
| A09 | 损坏／不兼容快照 | 拒绝恢复并显示原因，原运行及已有事件不被覆盖 |
| A10 | 恢复后的预算 | 已消耗次数和时间不倒退；额度耗尽时不继续执行 |
| A11 | 不完整工具事件 | 从模拟工具调用开始后中断，原运行显示未完成／结果未知，不伪造结束结果 |
| A12 | 单进程边界 | 第二实例或并发恢复被拒绝或被串行保护，不产生两个同时接管的运行 |
| A13 | 基础概况 | 健康与运行计数与已保存状态一致，暂不可用功能不伪装为已实现 |

自动化检查至少覆盖正常链路、限制／失败、取消和恢复；涉及进程重启、单实例与前端刷新等场景可以结合自动化集成检查和有记录的手工验收。具体断言、超时和测试实现将在开发前进一步制定。

## 12. 从概要设计到实现的顺序

1. 核验本机环境、Java／AgentScope 候选与前端构建方案，记录决策；选择满足可重复模拟与持久化需求的最小组合。
2. 细化本期对象、模块间契约、持久化原子边界及状态转换；确定示例输入和自动化测试方式。
3. 完成后端模拟运行、控制、事件和状态保存，再连接最小用户界面与基础概况。
4. 逐项执行第 11 节验收，记录实际结果、限制和未完成项；达到要求后再考虑标记 0.1。

实现前需要解决的开放设计：具体技术版本与可用性、存储方案、API／类结构、快照格式、用户页面视觉设计和验收的数值阈值。这些不影响本文确定的功能边界，但在开发相应部分前需要落到可检查的具体决策。
