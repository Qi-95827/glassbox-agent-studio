# 0.1 领域类型与状态设计

> 本文先定义本轮代码优化的边界和规则，再调整实现。保留当前 HTTP 返回格式、数据库编码及已有数据兼容；不声称已经完成整个系统的详细设计。

## 1. 为什么要调整

早期演示代码将状态、事件、场景和检查点阶段等大量固定取值写成 `String`，又在协调逻辑里直接读取 `Map<String, Object>`。这会导致拼写错误只能在运行时发现，合法值散落在代码中，恢复条件和调用职责不容易理解，也不利于以后扩展。

字符串仍适合用户输入的目标、模型回答、错误说明、外部模型名称等开放文本；UUID 在 HTTP 和现有数据库中仍以字符串传输，应用边界应校验其格式。不能为了“消除 String”将可自由扩展的文本强行做成枚举。

## 2. 核心领域类型

| 类型 | 含义与允许值 | 存储／接口兼容 |
| --- | --- | --- |
| `RunStatus` | `PENDING` 待执行、`RUNNING` 执行中、`COMPLETED` 成功、`FAILED` 失败、`CANCELLED` 取消、`LIMITED` 达到限制、`INTERRUPTED` 中断 | 继续使用现有大写编码；终态判断集中实现 |
| `InvocationStatus` | Agent、工具或模型调用的 `RUNNING`、`COMPLETED`、`FAILED`、`CANCELLED`、`LIMITED`、`INTERRUPTED` | 与现有调用记录编码一致；与运行状态分开，不包含待排队 |
| `Scenario` | 模拟场景：`NORMAL`、`FAIL`、`SLOW` | 外部和数据库继续使用 `normal`、`fail`、`slow` |
| `ModelMode` | 任务选择：`MOCK`、`DEEPSEEK` | 保留 `mock`、`deepseek`；具体实际调用模型单独记录 |
| `ModelKind` | 单次调用模型：`MOCK`、`DEEPSEEK_FLASH` | 保留 `mock`、`deepseek-flash`；不是任务入口模式 |
| `CheckpointStage` | `BEFORE_TOOL`、`AFTER_TOOL` 两个已定义安全节点 | 保持原编码，旧版本快照仍按校验规则处理 |
| `EventType` | 目前实际产生的事件类别，如任务创建、调用开始／结束、交接、取消、检查点、运行终态 | 保持现有大写事件编码；新增事件必须同步枚举和展示 |
| `HandoffDirection` | `DELEGATION`、`RESULT` | 保持已有编码 |
| `HandoffStatus` | 已委派 `ASSIGNED`、完成 `COMPLETED` | 保持已有交接 JSON 编码 |
| `HandoffParty`、`HandoffSource` | 当前协调者／分析 Agent，和协调者／模拟模型／DeepSeek 来源 | 显式维护现有连字符编码，不使用 `ordinal()` |
| `RunSnapshot`、`TaskDefinition`、`CheckpointSnapshot` | 供执行与恢复使用的强类型只读数据；标识为 `UUID`，消耗与额度为整数，状态／场景／节点为枚举 | 持久化和 HTTP 边界负责转换；当前对前端的查询响应暂保留原格式 |

`Integer` 用于可能不存在的 Token 数量；未知不是零。时间消耗使用毫秒 `long`，标注单位；起止时间仍是现有持久化的 ISO-8601 字符串，后续详细设计可迁移到明确的时间类型。交接的目标、约束、摘要是文本，证据 ID 是数字列表。

## 3. 状态与边界

- 运行正常路径为待执行 → 运行中 → 完成；运行中可进入失败、取消、超限或中断，待执行可取消。重启时未完成运行被标记中断，从有效检查点创建关联的新运行。**本次集中表达状态和基本终态判断，并不声称所有数据库更新已经由完整状态机强制验证。**
- 单次调用从运行中进入完成／失败／取消／超限／中断；中断的外部调用结果与 Token 可能未知。
- 在请求或数据库边界解析类型，未知输入明确拒绝；不得把未知值默认为成功或静默降级。现有前端依赖的 JSON 大小写与字段名不随本轮改动。
- 协调层使用只读领域对象，不用不受约束的键名读取状态；展示／历史查询仍暂用 JDBC 结果映射，后续可逐步引入响应 DTO。
- 模拟工具名和模型名不可因为字符串拼写变化而失去识别；提示文案仍使用自由文本。

## 4. 中文注释与代码组织

类和重要公开契约用简洁中文说明职责、输入／输出和边界；并发、取消、预算、检查点、外部请求等非直观位置说明原因与限制。注释解释**为什么**、何时和约束，不逐行翻译代码，也不对未实现的行为作承诺。保持文件和方法按职责划分，避免把整个系统继续堆在一个类中；本轮先整理核心执行与类型边界，持久化和 API 响应的进一步拆分保留为后续工作。

## 5. 验证

运行已有测试并补充枚举非法值、兼容旧编码、状态与检查点解析的测试；验证正常模拟、真实模型适配的本地模拟、工具失败、排队／运行中取消、限额和恢复。验证原有本地数据库可读取，前端展示格式未变。不能读取、输出或提交真实 API Key；真实模型如不必重复验证，不额外发起付费请求。
