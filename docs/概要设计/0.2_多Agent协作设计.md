# 0.2 多 Agent 协作设计

> 本设计面向学习与可验证实现；“最佳实践”须受任务、风险和评测结果约束，不假定任何方案普遍最优。先实现可证实的顺序协作，不把未实现的生产能力标为完成。

> 2026-11-15 更新：本文记录原始两角色基础；授权写入任务已增加独立开发角色，当前行为以 [三角色协作设计](首期_分析开发审查三角色协作设计.md) 为准。

## 目标与边界

用户目标经项目协调器顺序交给两个独立的 AgentScope `ReActAgent` 实例：分析 Agent 使用只读模拟工具生成分析；审查 Agent 接收有明确来源的结构化交接，对结论和证据进行复核。每个 Agent 有独立模型上下文；审查 Agent 不注册工具。协调器选择固定顺序是项目业务流程，模型推理、消息与工具调用由 AgentScope 完成。当前不是 Harness 子 Agent 自动派遣、分布式并行或真实代码开发。

## 交接与状态

- 交接数据沿用 `Handoff`：任务／运行／发送实例、发送方、接收方、目标、约束、状态、摘要、证据来源运行及事件 ID。增加分析 Agent → 审查 Agent 的方向和接收方，并将序列化后的同一交接传给审查 Agent，不能只保存给界面看。
- 证据来自已持久化的真实模拟工具事件；工具结果是模拟观测，分析与审查结论是模型输出，禁止混为真实仓库事实。审查输入包含目标、约束、分析结论、事件引用和模拟性质；不转发完整历史或密钥。
- 每个角色独立 `agent_invocations`，模型和工具调用按实际 Agent ID 关联；协调器是单写者，顺序执行避免共享状态并发冲突。每次结果／失败有各自记录，后续步骤失败不回写前一角色为失败。
- 复用单次运行全局轮次、工具次数和总执行时间；每次模型和工具前检查，在两个角色之间检查取消。审查不使用工具；预算不足或取消时保留已完成的分析，不得伪装为全流程成功。
- 检查点只支持启动前重新执行，预算不倒退；不声称保存了 AgentScope 会话或多 Agent 的中途一致快照。恢复会新建运行，保留原始历史。

## 验收方向

1. 模拟模型驱动两个独立 AgentScope 实例：分析 Agent 调用工具，审查 Agent 接收与持久化一致的交接内容后输出审查；页面展示角色、状态、调用与交接关系。
2. 记录每个 Agent 的模型／工具调用与证据，跨角色关联正确；输出明确模拟性质与未验证内容，不能用审查模型回答充当真实测试。
3. 分析失败时审查不启动；审查失败／超限／取消时保留已完成分析及真实状态；全局预算不能在角色切换时归零。
4. 自动化检查正常流程、工具失败、预算不足、取消、角色隔离、交接实际传递和检查点兼容。真实 DeepSeek 仅进行少量用户已授权调用，人工检查不输出密钥。
