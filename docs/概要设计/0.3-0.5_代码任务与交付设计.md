# 0.3—0.5 代码任务与交付概要设计

> 2026-11-12。以 0.2 多 Agent 为基础，推进仓库工作区、模拟 Bug 和用户交互。真实代码执行必须具备隔离、授权、取消、超时和证据，不把 Git 工作区误当成沙箱。本文是范围和实现依据；各能力是否完成以测试及开发记录为准。

## 0.3 工作区

- 用户明确提供本地仓库与基础分支，系统先检查 Git、基础提交和用户工作区未提交文件；不得修改原工作区已有内容。用户选择后为任务创建独立分支和受控工作区，保存基础提交、目录和归属。
- 仓库操作使用参数化进程调用，禁止 shell 字符串拼接；路径必须规范化，拒绝越界和符号链接。读取与编辑只允许显式授权范围；默认只读。工具访问统一经过可审计的授权检查。
- 差异、状态与基础提交由真实 Git 结果生成。提交、推送与合并分别授权；初期不自动推送或合并。目标分支变动时明确显示，不能沿用过期审查。
- Git 分支与文件路径控制不是恶意代码执行沙箱；在隔离环境未具备前不执行仓库脚本或将命令工具交给模型。

## 0.4 模拟 Bug

- 使用受控模拟 Bug 源，记录编号、描述、复现条件及状态；信息不完整、不可复现、复现成功和失败应分别呈现。
- 分析、开发、验证、审查按结构化交接完成；修复证据包含实际代码差异、测试命令、退出状态和环境。无法执行测试时标记未验证，不能宣称完成或通知已修复。
- 运行仓库测试须在已验证的沙箱中执行，限定镜像、资源、网络、超时和进程生命周期，保存真实结果；不允许模型直接执行任意宿主命令。隔离不可用时明确阻塞，仅允许不执行的准备工作。

## 0.5 用户交互与交付

- 在现有工作台呈现任务阶段、Agent、工具、模型、交接、仓库状态、差异、证据及异常。支持取消与已有启动前恢复；暂停、继续和人工接手要有明确状态与并发规则后才启用。
- 审批绑定待执行动作及其代码版本；拒绝不执行。代码、目标分支或证据变化后旧审批失效；不得自动合并。
- 提供可单独阅读的 HTML 报告，使用真实持久化数据、对不可信文本进行转义；明确模拟、未运行及未知，不输出密钥。

## 阶段测试

完成每个迭代后集中执行针对该迭代与已有功能的回归；真实仓库使用临时测试仓库，真实模型调用控制规模和预算。测试沙箱不可用时不宣称完整修复／回归闭环已经完成。
