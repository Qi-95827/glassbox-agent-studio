# 功能模块与 Agent 代码重构设计

## 目标和边界

现有功能保持 API、数据库、运行状态、授权和交接语义兼容。按功能将已实现的 Java 代码放到 `backend/modules/<功能>/src/main/java`；应用入口和跨模块共享的领域类型暂留 `backend/src/main/java`。各目录属于同一个 Maven 工程，不是独立发布的 Maven 子工程，也不表示已实现隔离或可热插拔。资源和测试暂保留在原来的 `backend/src`。

| 目录 | 职责与依赖 |
| --- | --- |
| agent | AgentScope 执行适配、角色配置、运行回调、模型／工具适配；使用项目控制回调，不能绕过权限与预算。 |
| orchestration | 运行编排、结构化交接和跨角色顺序调度；调用 Agent、任务、Bug 等能力。 |
| task | 任务和运行记录的持久化。 |
| tool | 模拟业务工具；AgentScope 工具适配位于 agent 模块。 |
| workspace | Git 工作区、文件范围授权和审批。 |
| bug | 模拟 Bug 及固定容器验证。 |
| report | HTML 报告。 |
| backend/src | Spring Boot 入口、跨模块领域类型、资源和现有测试。 |

其他模块保留 README 并标注为预留。应用级 HTTP 入口目前仍放在 `app`，后续可按业务进一步迁移；这次不为拆目录引入空接口或多模块 Maven 依赖图。`RunService` 仍有跨阶段职责，后续应在契约明确后继续拆分。

## Agent 类的分工

将原 `AnalysisAgent` 更名为表达真实职责的 `AgentScopeExecutor`；抽出 `AgentRuntime` 回调契约、`AgentRoleDefinition` 角色配置、模型包装、模拟模型和各个工具适配器。两个角色由相同执行器各自创建独立 AgentScope 实例，仍为固定顺序；这种拆分不宣称支持动态编排、并行或者完整可插拔能力。审查角色继续禁止注册文件工具。

## 格式与验证

Java 使用 Google Java Format 约定：两个空格缩进、统一换行与大括号、成员之间一个空行；避免靠连续空行区分层级。中文注释解释职责、边界和关键原因，避免无意义逐行注释。完成重构后集中运行全部现有测试（含 Docker）及构建，确保保留真实测试结果和历史数据兼容；不需要重新调用付费模型。
