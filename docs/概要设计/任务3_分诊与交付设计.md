# 任务 3 分诊与交付设计

> 日期：2026-11-19。承接[目标现象匹配关卡](任务3_目标现象匹配关卡设计.md)与[产品开发与验收交接](../交接/动态Agent重构后_产品开发与验收交接.md)任务 3。

## 1. 范围

本期在已有目标现象关卡上补齐：

- 按 unittest 逐用例记录完整测试标识、结果和断言，不再使用字符串包含关系判定目标现象。
- 模拟 Bug 原始描述、来源标识、版本、提交时间与内容摘要持久化；同来源重复提交与内容变化可追溯。
- 复现检查结果映射为分诊状态：待补充、未复现、环境不可用、现象不符、其他失败、目标现象匹配。
- 交付视图和 HTML 报告只读组合原始描述、分诊、复现/回归检查、逐用例结果和最终结论。
- 页面展示分诊与交付卡片，并保留“不自动合并、不自动关闭、需用户审查”的边界。

## 2. 逐用例证据

容器内仍执行固定命令 `python unittest discover`，但 runner 固定输出到 stdout，避免与 `TESTS_DISCOVERED` 交错。

解析器 `UnittestResults` 记录：

| 字段 | 说明 |
| --- | --- |
| `testId` | unittest 完整标识，例如 `test_calc.TestCalc.test_add` |
| `outcome` | `PASSED`、`FAILED`、`ERROR`、`SKIPPED`、`EXPECTED_FAILURE`、`UNEXPECTED_SUCCESS` |
| `message` | 该用例自身汇总块中的异常/断言文本；跳过时保留原因 |

判定：

- 复现：必须找到**完整标识精确相等**的目标用例，且该用例结果为 `FAILED`，其自身 `message` 中有一行**完整等于**预期断言 `AssertionError: 1 != 3`。其他用例出现同一断言无效，`1 != 30` 也不能命中 `1 != 3`。
- 相似名称：`test_add_extra` 不等于 `test_add`，记为 `TARGET_NOT_EXECUTED`，阻断下游。
- 混合失败：目标用例失败但断言不同（如 `1 != 4`），即使其他用例出现 `1 != 3`，仍记 `TARGET_MISMATCH`。
- 目标被跳过：记 `TARGET_SKIPPED`；回归时即使整体退出码为 0，也不能记为通过。
- 回归：目标用例必须实际执行且结果为 `PASSED`；整体仍有其他失败时记 `FAILED`。

逐用例结果写入 `bug_check_cases`，并通过检查记录 `CASES` 返回；检查原始输出同时保留可读摘要。

## 3. 原始描述与来源版本

任务创建时（`entryKind=BUG`）保存 `bug_intakes`：

- `original_description`：用户提交的任务目标原文。
- `bug_description` / `expected_symptom` / `expected_test_id`：受信模拟 Bug 定义。
- `source`、`source_version`：当前为 `synthetic-local` v1。
- `content_sha256`：来源、版本、原文、定义与预期现象的组合摘要。
- `submission_seq`：同一 `bug_id + source + source_version + workspace` 下的提交序号。
- `duplicate_of`：同来源且摘要相同的首次记录。
- `previous_intake_id`：同来源上一份记录，用于展示内容变化。
- `triage_status`、`triage_reason`、`triage_check_id`、`triage_updated_at`。
- `regression_status`、`regression_check_id`、`regression_updated_at`。

历史记录只新增、不覆盖；同一内容再次提交保留独立 intake 并指向首次记录。

## 4. 分诊映射

| 复现检查状态 | 分诊状态 | 下游 |
| --- | --- | --- |
| `FAILURES_OBSERVED` | `MATCHED` | 允许定位与授权修复 |
| `NEEDS_INFO` | `NEEDS_INFO` | 阻塞，复用任务 2 补充请求 |
| `NOT_REPRODUCED` | `NOT_REPRODUCED` | 阻塞 |
| `ERROR` / `TIMEOUT` / `STALE` | `ENVIRONMENT_UNAVAILABLE` | 阻塞 |
| `TARGET_MISMATCH` / `TARGET_NOT_EXECUTED` / `TARGET_SKIPPED` | `TARGET_MISMATCH` | 阻塞，显示现象不符 |
| `PASSED` / `FAILED` / `INTERRUPTED` | `OTHER_FAILURE` | 阻塞 |

分诊只由受信检查写入；用户补充后再次复现会更新为最新结论，不改变原始描述。

## 5. 交付结论

`GET /api/bugs/delivery?runId=` 与 HTML 报告“Bug 分诊与交付”章节使用同一组合逻辑：

| 条件 | 结论 |
| --- | --- |
| 无 intake | `NO_INTAKE` |
| 分诊未完成 | `PENDING` |
| 分诊非匹配 | 对应分诊状态（待补充/未复现/环境不可用/现象不符/其他失败） |
| 匹配但无回归 | `AWAITING_REGRESSION` |
| 回归通过 | `WAITING_USER_REVIEW` |
| 回归记录指纹与当前工作区不一致或当前不可读 | `EVIDENCE_STALE`（证据已过期，需重新测试） |
| 回归未通过或目标用例未执行/被跳过 | `REGRESSION_NOT_PASSED` |

查询交付时始终复核当前工作区指纹：历史回归记录（包括 `PASSED`）保留，但只有记录指纹等于当前指纹时才能作为当前版本依据；否则结论为“证据已过期，需重新测试”。页面与 HTML 报告使用同一交付结果和指纹字段。

报告和页面都明确：结论不自动合并、关闭 Bug 或替代用户审查。旧运行没有 intake 时显示缺少原始描述，不补造记录。

## 6. 反例与验收

- `UnittestResultsTest`：完整标识、混合失败断言归属、相似名称、跳过用例。
- `BugReproductionStatusTest`：完整断言行匹配；`1 != 30`、附加文本不能命中 `1 != 3`。
- `BugDockerIntegrationTest#assertionPrefixIsNotTargetSymptom`：真实容器中 `AssertionError: 1 != 30` 判为 `TARGET_MISMATCH`。
- `BugDockerIntegrationTest#perCaseResultsRejectMixedSimilarAndSkippedTargets`：真实容器覆盖混合失败、相似名称、目标被跳过。
- `BugDynamicWorkflowIntegrationTest#assertionPrefixReproductionBlocksBeforeFix`、`#mixedFailureReproductionBlocksBeforeFix`、`#similarTestNameReproductionBlocksBeforeFix`、`#unrelatedTestFailureBlocksBeforeAnyFix`：错误复现不启动修复节点，Agent/模型/工具为零。
- `#skippedTargetRegressionNeverReportsFixed`：目标被跳过时回归映射为失败，不进入审查。
- `#staleRegressionEvidenceChangesDeliveryAndReport`：回归通过后改动工作区，交付变为 `EVIDENCE_STALE`，历史 `PASSED` 保留，报告显示同一结论。
- `#bugIntakePersistsSourceVersionAndDistinguishesRepeatAndChange`：首次、重复、变化三类 intake。
- 真实合成样本：deepseek-flash 7 次模型调用、输入 12,277 / 输出 1,016 Token、5 次工具调用，结论“等待用户核对”。

## 7. 已知限制

- 仅支持 `synthetic-local` v1 模拟 Bug；intake 不接收外部 Bug 平台的任意描述与版本。
- 重复判断基于来源/版本/工作区与原文摘要，不做语义去重或跨工作区合并。
- 逐用例解析依赖 unittest verbose 输出；带多行 docstring 的用例描述可能无法解析，仍会因缺少目标标识而阻断。
- 分诊状态不接受人工改写；用户反馈与最终关闭仍走既有审查/回归证据校验。
- 交付报告是生成时组合，不是跨数据库与 Git 的一致性快照。
