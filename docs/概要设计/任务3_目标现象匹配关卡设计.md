# 任务 3 目标现象匹配关卡设计

> 承接[产品开发与验收交接](../交接/动态Agent重构后_产品开发与验收交接.md)任务 3。状态为已实现首个关卡（2026-11-19），交付证据见[任务 3 阶段交付记录](../交接/任务3_目标现象匹配关卡_交付记录_2026-11-19.md)。

## 1. 范围

任务 3 要求先记录模拟 Bug 的来源、版本和预期失败现象，再以目标现象而不是“任意测试失败”判定复现。本期交付：

- 模拟 Bug 定义增加 `source`、`version`、`expectedSymptom`、`expectedFailingTest`、`expectedFailureText`。
- 复现检查在容器退出码为 1 时解析输出：只有同时出现目标失败测试和预期断言，才视为 `FAILURES_OBSERVED`；否则记为 `TARGET_MISMATCH`，阻断下游。
- 检查证据保存 Bug 来源、版本、预期现象和容器实际输出；流程图显示未匹配原因。
- 未匹配时定位、修复、回归和审查节点全部未执行，模型、工具（含写入）调用为零。

## 2. 判定口径

| 容器结果 | 判定 | 下游 |
| --- | --- | --- |
| 未发现测试（exit 3 / TESTS_DISCOVERED=0） | `NEEDS_INFO` | 阻塞；复用任务 2 补充请求 |
| 测试全部通过（exit 0） | `NOT_REPRODUCED` | 阻塞；不可进入修复 |
| 有失败且输出包含 `FAIL: test_add` 与 `AssertionError: 1 != 3` | `FAILURES_OBSERVED` | 允许进入定位与授权修复 |
| 有失败但不包含目标测试/断言 | `TARGET_MISMATCH` | 阻塞；明确显示未复现目标现象 |
| 环境、超时、中断、代码版本变化 | `ERROR`/`TIMEOUT`/`INTERRUPTED`/`STALE` | 阻塞 |

- 目标现象由受信模拟 Bug 定义提供，不接受模型或测试文件自行声明。
- 证据仍绑定容器实际输出与工作区指纹；`TARGET_MISMATCH` 不生成补充请求（补充测试不能改变目标现象定义）。

## 3. 展示

- 流程图：复现检查显示“失败”，阻塞面板显示“测试存在失败，但未出现模拟 Bug 的目标现象”，未启动下游逐项列出。
- 节点详情：检查摘要、Bug 来源/版本、预期失败测试与断言、容器实际输出。
- 页面“本次 Bug 检测证据”始终显示目标现象定义；检测记录状态使用中文标签（含“未匹配目标现象”）。

## 4. 验收样本

| 样本 | 仓库（合成） | 预期 | 实际 |
| --- | --- | --- | --- |
| 目标匹配 | `calculator.py` 为 `a-b`；`tests/test_calc.py::test_add` 断言 3 | 复现通过，允许定位/修复/回归，终态等待用户核对 | deepseek-flash 运行 5 节点完成，任务等待核对 |
| 仅无关失败 | `calculator.py` 为 `a+b`；`tests/test_other.py::test_other` 断言 `2+2==5` | `TARGET_MISMATCH`，修复节点未执行，写入零 | 复现检查失败，下游全部未执行，0 模型/0 工具 |

模拟回归同时覆盖 Docker 直接检查与完整工作流；真实验收仅使用隔离数据库、临时合成仓库和 1 次 deepseek-flash 运行。
