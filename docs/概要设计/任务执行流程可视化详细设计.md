# 任务执行流程可视化详细设计

> 承接[任务执行流程可视化与接口设计](任务执行流程可视化与接口设计.md)。本文把任务 1 的接口、事件关联、页面组件和验收口径落到可实现的字段与边界。状态为实施中。

## 1. 范围与原则

- 任务详情以流程图为主视图，计划图与真实执行叠加。图只渲染服务端返回的计划、节点、依赖、状态和结构化操作，不按模板名、角色名或文件名编排业务。
- 计划、节点、尝试、检查、模型、工具、交接和恢复来源继续以现有持久化表为权威。投影只做聚合，不复制正文、不补造缺失关联。
- 旧运行、旧事件和旧接口继续可读。缺失字段返回空值或 `null`，页面显示“未记录”，不根据节点顺序或日志文案猜测。
- 本阶段只读投影；审批、暂停、继续、取消、恢复仍调用既有写接口。服务端在提交时再次校验运行状态、计划版本和检查点归属。
- 第一版刷新使用受控轮询。断线保留旧图并标注最后成功同步时间；重连先补取事件，再以新快照对齐。

## 2. 后端投影

### 2.1 入口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/api/runs/{id}/execution-view` | 流程图最小快照：计划、节点、边、焦点、阻塞、操作、恢复、计数。 |
| `GET` | `/api/runs/{id}/execution-view/nodes/{nodeId}` | 单节点详情：尝试、模型、工具、检查、交接、证据和来源。 |
| `GET` | `/api/runs/{id}` | 保持原样，继续返回既有明细和事件。 |
| `GET` | `/api/runs/{id}/events?after=&limit=` | 保持原样，新增结构化引用字段。 |

两个新接口先调用 `RunRepository.runSnapshot(id)` 校验运行存在；节点详情再校验 `nodeId` 属于该运行，跨运行或未知节点返回 400。

### 2.3 节点

| 字段 | 口径 |
| --- | --- |
| `id`、`planVersionId`、`sequence`、`key`、`label`、`kind`、`phase` | 计划节点权威字段。`kind` 为 `AGENT` 或 `SYSTEM_CHECK`。 |
| `status` | `PlanNodeStatus` 原值：`PENDING/RUNNING/COMPLETED/REUSED/FAILED/CANCELLED/LIMITED/INTERRUPTED/SKIPPED`。 |
| `agentId`、`sourceAgentId`、`startedAt`、`finishedAt` | 实际实例或复用来源；无记录为空。 |
| `workspaceRead`、`workspaceWrite`、`maxModelCalls`、`maxToolCalls` | 计划保存的权限与节点预算。 |
| `definitionId/version`、`checkId/version` | 计划引用的定义或系统检查版本。 |
| `dependencyIds` | 直接前置节点标识；边同时以 `edges` 表达。 |
| `ready` | 依赖均已结算为 `COMPLETED` 或 `REUSED`，且自身仍为 `PENDING`。 |
| `waitingForNodeIds` | 尚未结算的直接前置节点。 |
| `attemptCount`、`checkCount` | 实际尝试和检查记录数。 |

### 2.4 焦点

`focus.active[]` 只列在途实体：

- Agent 节点为 `RUNNING`：优先列最新的 `RUNNING` 模型调用（`activityKind=MODEL_CALL`），否则列 `RUNNING` 工具调用（`TOOL_CALL`），否则列尝试本身（`ATTEMPT`）。
- 系统检查节点为 `RUNNING`：列最新 `RUNNING` 检查（`CHECK`）。
- 每个焦点项携带 `nodeId/nodeLabel/attemptId/checkId/agentId/activityId/activityLabel/startedAt/status`。
- 运行暂停时保留最后已知焦点，另以阻塞项解释暂停；不把已结算调用继续显示为在途。

### 2.5 阻塞与操作

稳定原因码：

| 原因码 | 触发条件 | 作用对象 |
| --- | --- | --- |
| `PLAN_APPROVAL_REQUIRED` | 计划 `reviewRequired` 且未确认，运行仍为 `PENDING` | 运行 |
| `RUN_PAUSED` | 运行 `PAUSED` | 运行 |
| `RUN_INTERRUPTED` | 运行 `INTERRUPTED` | 运行 |
| `RUN_BLOCKED` | 运行 `BLOCKED` 且无可定位检查 | 运行 |
| `CHECK_FAILED` | 最近一次检查为 `FAILED/BLOCKED/INTERRUPTED` | 检查节点 |
| `NODE_FAILED` | 节点 `FAILED/LIMITED/CANCELLED/INTERRUPTED` | 节点 |
| `DEPENDENCY_NOT_STARTED` | 下游仍为 `PENDING` 且直接前置未结算 | 节点 |

`blocking[]` 每项含 `code/message/scope/nodeId/nodeLabel/blockingNodeIds`。`blockingNodeIds` 表示尚未启动、受该原因影响的下游节点。

`availableActions[]` 由后端判定：

| actionCode | 条件 | 目标 |
| --- | --- | --- |
| `APPROVE_PLAN` | 计划待确认、运行 `PENDING` | `planVersionId` |
| `PAUSE` | 运行 `RUNNING` 且无待生效暂停请求 | `runId` |
| `RESUME` | 运行 `PAUSED`，或 `RUNNING` 但最新暂停事件尚未被 `RESUMED/PAUSED` 收束 | `runId` |
| `CANCEL` | `runStatus.canCancel()` | `runId` |
| `RECOVER` | 运行 `INTERRUPTED` 且检查点 `available=true` | `checkpointId` |

每项带 `label`、`enabled` 和 `disabledReason`；本期可用操作均为已实现入口，`enabled=false` 仅用于历史或不可用检查点，避免前端自行猜测。

### 2.6 恢复来源

`recovery` 在以下情形返回：

- `parentRunId`：子运行的直接父运行。
- `sourceCheckpointId`：父计划上的恢复检查点。
- `inherited`：检查点记录的继承消耗（`rounds/tools/elapsedMs`），只来自持久化检查点，不推算。
- `reusedNodes[]`：本运行计划中 `status=REUSED` 的节点、复用来源 `sourceAgentId`。
- `newCalls`：本运行实际新增模型和工具调用数。

无父运行、无检查点或历史缺失时字段为 `null`，页面显示“未记录/不适用”。

## 3. 事件结构化关联

### 3.1 迁移

`events` 表新增可空列：

```sql
ALTER TABLE events ADD COLUMN IF NOT EXISTS plan_version_id VARCHAR(36);
ALTER TABLE events ADD COLUMN IF NOT EXISTS node_id VARCHAR(36);
ALTER TABLE events ADD COLUMN IF NOT EXISTS attempt_id VARCHAR(36);
ALTER TABLE events ADD COLUMN IF NOT EXISTS agent_id VARCHAR(36);
ALTER TABLE events ADD COLUMN IF NOT EXISTS check_id VARCHAR(36);
ALTER TABLE events ADD COLUMN IF NOT EXISTS model_call_id VARCHAR(36);
ALTER TABLE events ADD COLUMN IF NOT EXISTS tool_call_id VARCHAR(36);
```

`reason_code` 已存在。新列不写外键，避免历史事件因清理或迁移失败无法读取；关联在写入时由服务端从已保存记录取得。

### 3.2 写入口径

- 节点认领、交接接收、检查开始/结算、限流重试、计划确认：写 `planVersionId/nodeId/attemptId/checkId` 中实际存在的标识。
- Agent 运行事件：至少写 `agentId`，并由服务端按 `agent_id` 解析当前节点和尝试后补 `planVersionId/nodeId/attemptId`。
- 模型事件补 `modelCallId`，工具事件补 `toolCallId`；调用 ID 来自 `RunControl` 已持久化的本次调用。
- 运行级事件（取消、暂停、恢复、检查点、内存装配）保持节点列为空。
- 旧事件查询返回 `null`，前端不据此归入任何节点。

### 3.3 读取

`RunEvent` 增加上述可空字段，`EventQueryService` 继续按 `id > after` 排序并返回 `nextCursor`。不同运行仍可能跳号；前端只按服务端游标翻页，不以数字连续性判断漏读。节点详情可附带该节点事件，但运行轮询只取增量事件。

## 4. 前端组件

| 组件 | 职责 |
| --- | --- |
| `main.jsx` | 维持轮询与运行切换；并行请求运行明细、`execution-view`、事件页；断线保留最后成功快照和同步时间；切换运行时丢弃旧响应。 |
| `ExecutionFlowPanel.jsx` | 流程图主视图：分层布局、依赖边、状态图例、焦点高亮、阻塞标记、节点选择、运行级操作、恢复来源和同步时间。 |
| `NodeExecutionDetail.jsx` | 节点下钻：计划职责、权限、依赖、尝试、模型、工具、检查、交接、证据和事件；切换节点时丢弃旧请求。 |
| `WorkflowPlanPanel.jsx` | 保留为“列表视图”，继续服务旧运行和键盘/窄屏阅读。 |

### 4.1 图形布局

- 节点按依赖最长路径分列，列内按计划 `sequence` 排序；无边时按顺序单列。
- 每个节点显示序号、标签、类型徽标和状态文字；`RUNNING` 使用动态边框，`REUSED` 使用虚线，检查节点使用独立形状图标。
- 边从右缘连到左缘，箭头指向下游；未满足依赖的边使用弱化虚线。
- 焦点节点加 `focus` 标记，阻塞节点加 `blocked` 标记；图上方显示“当前动作：节点 → 实际动作”。
- 节点使用 `button`/`role=button`，支持 Tab 聚焦、Enter/Space 打开详情；依赖和状态同时有文字，不依赖颜色区分。

### 4.2 断线与切换

- 每次成功轮询记录 `lastSyncedAt`；请求失败时保留 `detail`、`executionView` 和已收事件，顶栏显示“连接中断”，面板显示最后更新时间。
- 重新连接后先补齐事件页，再应用新快照；事件按 `id` 去重。
- 切换运行或任务时清空游标、事件和节点详情；每次请求带运行标识，响应回来时若已不是当前运行则丢弃。
- 节点详情请求带 `nodeId`，返回时校验仍对应当前运行和选中节点。

## 5. 兼容与扩展

- 旧接口字段不变；新增字段只增不改。`GET /api/runs/{id}` 仍返回 `planNodes/workflowAttempts/workflowChecks/workflowHandoffs` 等。
- 新模板只要保存节点、依赖和受信执行器引用，即可进入同一图；新节点类型沿用 `kind/status/label`，专用详情通过尝试/检查投影接入。
- 未知枚举值由服务端读取时拒绝并给出明确错误，不用“未知”状态静默吞掉；历史缺失字段保持空值。
- 流程编辑器、运行中改图、并行调度不在本期范围；`focus.active` 已按数组设计，为后续多活动预留。

## 6. 验收对照

| 验收项 | 数据来源 | 页面/证据 |
| --- | --- | --- |
| 确认前零调用 | `run.PENDING`、计划 `approvedAt=null`、`counts.modelCalls=0`、事件无 `MODEL_STARTED` | 图可查看，操作区只有确认/取消 |
| 正常 Bug 流程 | 节点、尝试、工具、检查、交接 | 逐节点下钻到复现、分析、读取、写入、回归、审查 |
| 检查阻塞 | 最近检查 `FAILED/BLOCKED`、下游 `PENDING` | 阻塞面板列原因、证据和未启动下游 |
| 限流重试 | 同节点多尝试、`stop_cause=MODEL_RATE_LIMIT`、累计消耗 | 尝试列表保留失败，图仅高亮新在途 |
| 取消/预算停止 | 运行终态与 `stop_cause`、在途/未执行节点 | 终态清晰，晚到结果不改回运行中 |
| 刷新/重连 | `execution-view`、事件游标、`lastSyncedAt` | 断线保留旧图，重连事件不重不漏 |
| 切换历史/恢复子运行 | `taskId`、`parentRunId`、`sourceCheckpointId`、`REUSED` | 可跳父运行与检查点，复用与新调用分开 |
