# 用户私有 Agent 与组件装配设计

> 2026-11-20 设计稿。当前优先级为本地用户、私有 Agent、可创建的 Skill 和工具配置，以及私有 Agent 参与既有顺序编排。

## 1. 现状与第一期体验

工作台目录显示分析、开发、审查 3 个基础角色。后端还为固定模板注册了文本分析、文本综合、工作区分析、发现汇总、授权修改、变更审查 6 个专用定义，合计 9 个内置定义。角色表示受控的权限上限，定义用于装配，实例由每个节点的实际尝试创建。候选规划器当前从角色映射到内置定义。工具有模拟检查、授权读取、授权搜索、授权修改四种执行能力。Skill 目前来自内置目录。

用户登录后进入「我的 Agent」，可以从空白表单或内置定义副本开始，也可以输入一段设计思路生成草稿。用户编辑职责、输出内容、模型、Skill 和工具，预览装配后保存并发布。创建任务时可以指定某个私有 Agent，也可以勾选允许规划器从本次备选清单推荐。计划确认前展示实际选中的定义版本、选择理由及本节点预计获得的能力。运行完成后从同一张流程图查看实际装配、工具调用、结果和交接。

示例用户创建「前端交付检查 Agent」。职责是核对网页交互、列出覆盖和遗漏，使用「可访问性核对」Skill、授权文件读取和限定前端文件的搜索工具。计划把它分配给只读核对节点，随后把输出交给一个独立汇总节点。成果中列明实际读过的文件和验证范围。

## 2. 本地用户和资源归属

- 采用本地账号与服务端会话。首次初始化由本地管理员显式领取现有 `LOCAL` 归属，再由管理员添加用户或生成一次性激活入口。接入 Spring Security，使用密码编码、服务端会话和 CSRF 保护。普通用户只能管理自己的资源。保留本机回环访问，组织、角色共享、跨主机部署和团队管理另期。
- 服务端从已认证会话解析用户和操作人。请求体、Header、模型输出和浏览器选项中的用户 ID 只可作为普通输入核验。接入 `ExecutionScopeResolver`，创建、查询、确认与异步运行使用同一归属，派发时携带确认事务中保存的归属。匿名只能访问登录和初始化入口等必要公共资源。
- 私有 Agent、Skill、工具配置和候选绑定用户。任务及其运行、节点、事件、报告、交付文件按资源链追溯到同一归属。工作区需验证用户可访问后才能提交、预览、检索或执行工具。同机用户若共用某个仓库，仍由显式工作区授权决定。
- 历史数据显式归属引导管理员。普通账号启用前，使用两用户反例验证相关接口的列表、按 ID 查询、确认、报告和下载。仍使用全局查询的旧页面或端点先限制为管理员访问，等逐项接入归属校验后再开放。

## 3. 用户可以组装哪些组件

| 组件 | 第一阶段具体能力 |
| --- | --- |
| Agent | 名称、简介、职责、受控权限类别、模型选项、输出要求、Skill 和工具列表、是否参与推荐。选择权限类别只决定能力上限，任务运行时再授权。 |
| Skill | 用户可编写或导入 Markdown 指导，填写用途、输入约定和预期输出，预览后发布私有版本。Skill 正文是装配时的指导，不授予工具、文件或系统能力。 |
| 工具 | 内置工具可直接选用。用户可新增可执行的私有工具配置，绑定受信执行器，并收窄参数和作用范围。示例为基于授权搜索能力配置「搜索前端标签」，固定文件类型和查询方式，仍在本任务授权文件内搜索。 |
| 模型 | 从服务器已经配置的模型中选择，或引用任务模型策略。凭据由服务器管理。页面展示模型、数据用途和用量。轮次、时长等任务预算保持默认留空。 |

首批将私有工具配置限制为受信只读读取或搜索执行器。增加新的执行能力时由开发者实现并注册提供者，声明稳定标识、输入输出、授权、超时和副作用，再通过现有网关接入。上传脚本、用户指定命令、通用外部插件及任意外部服务另行确定执行和授权边界。

执行时逐项取交集。工具必须满足用户可用、组件允许、模板和权限类别允许、任务及节点已授权等条件。文件范围还须取节点授权与当前工作区有效授权的交集。私有开发 Agent 可以按后续批次接入既有授权写入链路，仍需文件回执和独立审查。

## 4. 从设计思路到私有定义

1. 「从思路生成」由用户显式触发。展示将发送给模型的设计文本和可选组件摘要。规划适配器以结构化 DTO 返回名称、职责、权限类别建议、输出要求、组件引用和待确定问题。未配置模型时可编辑空白表单。
2. 服务器从当前用户可见且可用的组件中解析引用，检查角色、工具、Skill、模型和输出契约是否相容。模型输出未知组件或越权要求时，保留可编辑草稿并指出具体问题。服务器提供固定的上层系统约束，用户职责和 Skill 正文作为较低优先级的指导。
3. 草稿可多次编辑。发布时生成不可变版本，绑定 Agent ID、所有者、版本、规范摘要和精确的组件版本。版本更新生成新版本，旧运行继续依据当时保存的装配记录展示。归档后从新任务选择和推荐中移除，既有历史按归属可查。已有候选若引用失去当前使用资格的版本，确认时需重新选择。
4. 发布和草稿生成只保存定义。实际 Agent 实例仍按已有计划，在节点被认领时由执行器装配。创建和运行使用独立身份标识，工作台详情展示「声明的配置」「实际装配」「实际调用」所对应的记录。

## 5. 规划器如何选它

- 任务入口支持三种明确选择。沿用内置模板、指定某个私有定义版本、允许从用户勾选的备选集合推荐。用户可随时切回内置模板。
- 给模型的备选集合只包含本次可见且允许参与规划的版本。传入服务端生成的短引用、用途、角色、所需能力和输出摘要。私有职责正文与 Skill 正文仅在需要时由执行装配加载。模型以可选短引用表达节点选择，服务端把它解析成稳定定义引用。未指定私有定义的旧候选继续按角色映射到内置定义。
- 计划校验复核私有定义归属、发布状态、角色相容性、工具能力和节点授权。候选摘要覆盖解析出的定义版本与规范摘要。确认时重新核对，计划落库固定版本。确认及执行期间发生的撤权还要经过运行时装配和工具网关处理。指定版本不可用时给出原因，由用户在确认前重新选择。
- 计划卡片和流程图上显示「私有」或「内置」、Agent 名称与版本、分配原因及授权范围。运行后在原节点详情中展示实际装配、来源版本、调用记录和完整可读交接。

## 6. 持久化与接入约定

| 聚合 | 权威记录与约束 |
| --- | --- |
| 用户与归属 | `users` 保存稳定用户 ID、账号状态及密码摘要。历史 `LOCAL` 映射由明确初始化操作登记。任务、候选和工作区的归属以持久化记录为准，运行与证据从父对象继承。 |
| 私有资源和版本 | Agent、Skill、工具配置各自保存稳定 ID、所有者、生命周期状态及版本。发布记录按 ID 和版本唯一，引用精确版本。私有 ID 由服务端生成，内置与私有名称可相同，引用不混淆。 |
| 计划和运行 | 扩展现有 `AgentDefinitionRef` 的解析能力，优先复用计划节点、候选摘要和装配快照。对私有资源的精确版本查询必须带当前归属，新旧计划可照常反序列化。旧摘要校验按原协议，新摘要只有在内容契约变化时才升级。 |
| 审计 | 添加用户、发布、归档、指定或推荐使用私有 Agent 等动作记录操作者、目标版本、时间和结果。授权失败与组件不可用有稳定原因。 |

后端保持 Controller → Service → Spring Data JPA Repository。内置 Agent 和组件继续走原目录。由归属感知的解析服务选择内置或私有版本，避免把用户数据注册进全局内置 Map。用户配置使用 DTO 和受控类型，工具配置引用执行器契约。数据库迁移继续用 `schema.sql`，在隔离 H2 副本验证重复启动与旧图读取。

## 7. 建议的开发顺序与验收

| 批次 | 交付产物 | 验收样本 |
| --- | --- | --- |
| A · 本地账号 | 初始化与登录、添加用户、会话归属、历史数据归属和服务端隔离 | 管理员保留旧历史，两位普通用户不串任务、工作区、运行、报告、下载和新目录。直接用另一个用户的 ID 请求也被拒绝。 |
| B · 私有组件与 Agent | 我的 Skill、我的工具、我的 Agent、手动装配、从思路生成草稿、发布与归档 | 用户甲新增 Skill 和只读搜索工具，发布 Agent v1。更新生成 v2，v1 内容可核对。用户乙读不到甲的草稿、组件和定义，模型也拿不到这些备选。 |
| C · 接入规划与工作台 | 手动指定、允许推荐、计划确认和运行装配、流程图版本与证据 | 先用确定性模型验证推荐一个已授权的私有 Agent，再走一次浏览器「登录 → 创建组件 → 发布 → 生成计划 → 确认 → 查看交接」。真实模型调用独立记录。 |

最低验收包含五个反例。跨用户擅自引用被拒绝。草稿和已归档定义无法进入新运行。规划后撤权会拒绝确认或阻断受影响的装配。已发布 Agent 更新到 v2 时，旧计划仍按获准且绑定的 v1 装配，旧报告不被新版本覆盖。用户 Skill 或工具配置请求超出节点只读范围时，工具调用失败并留下拒绝证据。

先发布一条可重复的只读样本。首批私有定义进入分析节点或符合现有权限规则的审查节点。私有开发 Agent 的上线条件在后续授权写入批次明确。完成各批后做一次集中回归，记录浏览器流程、运行标识、定义及组件版本、实际调用、交接和未验证项。
