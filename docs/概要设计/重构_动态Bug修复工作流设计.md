# 动态模拟 Bug 修复工作流设计

> 实施日期：2026-11-18。对应交接任务 2 与验收 A02、A05、A07、A09、A12、A14、A20—A22、A25。复用既有模拟 Bug 容器检测与任务 1 的系统检查节点。

## 1. 目标与边界

在动态计划中增加版本化模板 `bug-fix@2`，把已有模拟 Bug（`MOCK-PY-001`）的固定容器检测接入「复现检查 → 定位 → 按授权修复 → 回归检查 → 独立审查」。证据必须来自本次运行、同一 Bug、同一工作区及对应文件版本；消费检查结果前再次核对当前代码。系统只报告事实和阻塞，不自动合并或关闭 Bug。v1 历史计划保留原图。

首期边界：

- 只支持注册的模拟 Bug 和服务端固定的 unittest 容器命令；不接受模型提供的 shell 命令。
- 修复只能使用既有授权文件读、写、搜索工具；未授权路径、无写入授权或无文件集合的请求在创建计划时拒绝。
- 复现或回归检查未通过时，必需下游不启动；不把“模型声称已修复”当作验证。
- 只读 Bug 任务继续使用兼容流程；本模板要求显式写入授权，不新增只读动态 Bug 模板。
- 真实容器路径依赖本机 Docker 与 `python:3.12-alpine` 镜像；不可用时检查结果为 `BLOCKED`，不会退化成本地猜测。

## 2. 模板与节点

| 顺序 | 节点 | 类型 | 依赖 | 职责 |
| --- | --- | --- | --- | --- |
| 1 | `reproduce` | 系统检查 `bug-reproduction@1` | 无 | 在只读容器中运行固定 unittest，要求观察到测试失败。 |
| 2 | `analyze` | Agent `workspace-analysis@1` | `reproduce` | 结合本次复现证据和授权文件定位失败原因。 |
| 3 | `fix` | Agent `workspace-edit@1` | `analyze`、`reproduce` | 读取当前文件版本后，仅修改授权文件；启动前复核复现证据仍对应当前代码。 |
| 4 | `regression` | 系统检查 `bug-regression@1` | `fix` | 在当前代码版本上重新运行固定检测，要求通过。 |
| 5 | `review` | Agent `workspace-change-review@1` | `analyze`、`fix`、`regression` | 独立审查修改声明、写入回执与回归证据，列出待人工核对项。 |

检查节点不创建 Agent 实例、模型或工具调用；下游 Agent 通过交接输入获得检查摘要、证据说明和检查记录标识。

## 3. 服务端规则与授权

新增模板范围 `WORKSPACE_BUG_FIX`，与只读、写入模板并列：

- 必须为 `TaskEntryKind.BUG` 且绑定受支持的模拟 Bug；Bug、工作区、授权文件集合与模板共同参与授权摘要。
- 必须显式 `writeEnabled=true`，且至少有一个文件授权；工作区与文件集合变化会使计划摘要失效，确认或认领时拒绝。
- Bug 快捷入口只预填 Bug、工作区、模板和任务目标；写入授权默认关闭，“先审阅计划再运行”默认开启。用户必须主动勾选允许修改，前端才允许提交 Bug 修复模板。
- 创建任务时再次核对 Bug 是否受支持；未知 Bug 或缺少工作区在服务端拒绝。
- 模板引用、检查版本、Agent 定义版本仍由受信代码注册；保存计划前预校验全部定义与检查，避免留下半成品。

## 4. 检查执行与证据

### 4.1 复现检查

调用 `BugService.runForTask(runId, bugId, workspaceId, REPRODUCE, guard)`：

- `FAILURES_OBSERVED` → 通过，允许进入定位与修复。
- `NOT_REPRODUCED` → 失败，说明未观察到失败，不允许修改。
- `NEEDS_INFO` → 阻塞，缺少 `tests` 目录或无法验证。
- `ERROR` / `TIMEOUT` / `INTERRUPTED` / `STALE` → 阻塞，区分环境不可用、超时、中断和代码版本变化。
- 其他状态 → 阻塞，不能作为复现证据。

### 4.2 回归检查

在修复后调用同一检测的 `REGRESSION`：

- `PASSED` → 通过；工作区在执行前后指纹一致才保留指纹，否则检测本身标记 `STALE`。
- `FAILED` / `FAILURES_OBSERVED` → 失败，运行阻塞，独立审查不启动。
- `NEEDS_INFO` / `ERROR` / `TIMEOUT` / `INTERRUPTED` / `STALE` → 阻塞。
- `NOT_REPRODUCED` → 阻塞，不当作通过。

### 4.3 证据归属

`bug_checks` 保存运行、Bug、工作区、检测类型、状态、输出和代码指纹；`workflow_checks.external_evidence_id` 指向本次检查创建的 `bug_checks` 记录。系统检查只读取本次 `runForTask` 返回的记录，不扫描工作区历史检测，因此跨运行证据在结构上不能进入本次判定。

检查通过不等于永远有效。调度器在消费直接依赖的检查结果、启动下游节点前，会重新读取当前工作区指纹并与外部证据比对：

- 复现检查在定位节点启动前复核；修复节点同时直接依赖复现检查和定位结果，也在启动前复核。
- 回归检查在独立审查启动前复核。
- 证据缺失、Bug/工作区归属不符或代码已变化时抛出 `StaleEvidenceException`，运行进入 `BLOCKED`/`CHECK_FAILED`，不启动依赖节点。
- 运行详情和报告保留检查的历史 `PASSED`，但以 `evidenceCurrent=false` 和“证据已过期”明确标识，不把旧结果展示为当前有效。

容器只读挂载工作区、无网络、低权限、资源上限和 30 秒超时继续沿用既有实现；运行控制通过 `guard` 在执行前和等待期间响应取消、暂停与时间限额。

## 5. 阻塞、取消与用户决定

- 检查失败或无法判定：检查节点 `FAILED`，未启动节点 `SKIPPED`，运行 `BLOCKED`，停止原因 `CHECK_FAILED`；已发生的读取、模型和写入记录保留。
- 取消或中断发生在检查结算前：运行按受控停止结算，检查记录标记 `INTERRUPTED`，不显示为已验证。
- 回归通过且审查完成后，运行仍为 `BLOCKED`，原因明确“等待用户核对代码差异、原问题和验收条件”；不写入反馈、不自动合并、不自动关闭 Bug。

## 6. 工作台与报告

- 运行详情 `workflowChecks` 显示检查标识、版本、状态、摘要和外部证据标识；计划面板按节点显示检查结果。
- 运行详情的检测证据面板继续读取 `/api/bugs/checks/by-run`，只展示明确归属该运行的 `bug_checks`。
- HTML 报告“本次运行的检测证据”列出检测记录、类型、状态、代码指纹和输出；缺失归属时显示未知。

## 7. 兼容与迁移

- `workflow_plans.scope_type` 新增 `WORKSPACE_BUG_FIX`，约束升级为 v3；历史 `TEXT_ONLY`、只读和写入记录保持可读。
- `workflow_checks.external_evidence_id` 为追加列；历史检查记录该字段为空，按未知处理。
- 兼容 Bug 流程（无模板）保持原有界面与行为；只在选择 `bug-fix` 模板时走动态计划。
- 含系统检查的模板不生成动态恢复边界，沿用任务 1 的保守限制。

## 8. 验收与测试

| 场景 | 结果 |
| --- | --- |
| 真实容器：失败样例 → 授权修复 → 回归通过 → 独立审查 | 运行 `BLOCKED` 等待用户核对；5 个节点全部完成；2 次检查通过且外部证据标识可定位；复现与回归指纹不同，回归指纹等于当前工作区指纹；原仓库未修改；无自动反馈记录。 |
| 复现失败/缺信息/环境不可用/过期 | 检查节点失败，下游全部跳过；无 Agent、模型或工具调用。 |
| 回归失败 | 写入记录保留；回归检查失败；独立审查跳过；运行 `CHECK_FAILED`。 |
| 取消 | 检查标记 `INTERRUPTED`，运行 `CANCELLED`，无 Agent 或模型调用。 |
| 计划确认前 | 运行 `PENDING`，容器检查、Agent 和模型调用均为零；确认后执行。 |
| 模板授权 | 缺少写入授权、缺少文件集合或未知 Bug 均在服务端拒绝。 |
