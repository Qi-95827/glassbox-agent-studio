# 动态只读工作区检查点与恢复设计

> 实施日期：2026-11-18。对应交接任务 3 与验收 A06—A08、A10、A15、A21、A23。扩展原有纯文本动态恢复，不改变其历史语义。

## 1. 恢复支持矩阵

| 边界 | 支持 | 条件与限制 |
| --- | --- | --- |
| 纯文本动态计划，已结算节点后 | 支持 | 原有规则：无工作区、Bug、写入和工具调用；尚无重试记录。 |
| 只读工作区分析，首个节点认领前 | 支持 | 无历史结果可复用；子运行从头执行，已获批准的计划、任务授权和工作区身份必须一致。 |
| 只读工作区分析，已结算只读节点后 | 支持 | 复用已结算 Agent 结果；工具读取版本必须与当前授权文件一致。 |
| 含系统检查节点的只读计划 | 支持 | 已结算 Agent 结果可复用；未完成的系统检查在子运行重新执行，检查本身不创建 Agent 或模型调用。 |
| 写入授权、Bug 修复计划 | 不支持 | 可能改变工作区或依赖容器副作用；保留明确阻塞。 |
| 会话中途、未知工具副作用、在途调用 | 不支持 | 无法证明安全和完整性。 |
| 恢复子运行再次恢复 | 不支持 | 与原纯文本限制一致；子运行存在来源检查点时不再生成新边界。 |

## 2. 版本证据

动态只读计划完成任一节点后保存边界。边界除计划、任务、审批、节点结果和模型用量外，还绑定：

- 计划版本、图摘要、模板范围与授权摘要；
- 工作区标识、仓库路径和基线提交；
- 每次已完成的授权文件读取/搜索调用及其资源版本。

工具网关在动作成功后，将本次实际读取的授权文件路径与 SHA-256 编码为资源版本（`resource_version`），与工具调用终态一起保存；搜索调用记录全部实际读取的授权文件。写入工具也记录写入后的新版本，但写入计划本身不生成恢复边界。

恢复验证会重新读取版本证据中的每个路径，要求：

1. 路径仍在任务当前授权集合内；
2. 当前文件 SHA-256 与记录一致；
3. 节点结果、实例、模型用量和工具调用均已结算；
4. 已完成系统检查全部通过，且没有在途检查或工具调用；
5. 计划摘要、审批、任务授权和工作区身份一致。

任一条件不满足时拒绝复用并说明原因；历史运行、调用和证据保留。

保存边界时如果授权文件已被删除或不可读，边界保存失败按“跳过检查点”处理：已完成节点的结算照常提交，运行继续，事件记录跳过原因；该边界不写入，也不允许从中恢复。数据库等非资源读取故障仍向上抛出，不能伪装成正常结算。

## 3. 边界与摘要

- 纯文本边界继续使用 `workflow-checkpoint-v1` 摘要，历史检查点可读。
- 只读工作区边界使用 `workflow-checkpoint-v2`，在 v1 语义之上加入范围、授权摘要、工作区身份、工具版本证据、检查状态和继承工具次数。
- `workflow_checkpoints.tool_calls` 追加保存边界时的工具调用数；历史记录的 `tools` 仍为 0。
- `completed_nodes` 统计所有已结算节点（含系统检查），用于同一计划的边界唯一性；复用来源仍只包含 Agent 结果。
- 检查节点不进入复用来源：子运行重新执行未完成的检查，以已复用的上游结果重新核对证据。

## 4. 恢复事务与预算

恢复在单一事务中：

1. 锁定原运行并确认只能申请一次；
2. 重新校验存储边界、当前文件版本与授权；
3. 创建直接子运行，记录父运行与来源检查点；
4. 将可复用 Agent 节点标记为 `REUSED` 并关联原实例。

子运行继承父运行的模型轮次、工具次数、已用时间、运行限额、节点预算和角色预算；`reportedTokens`、按工具累计次数继续沿父链计算，不会因恢复归零。认领前再次执行 `validateReuse`，防止恢复后、执行前的来源或文件变化。

## 5. 工作台与报告

- 运行详情 `workflowCheckpoints` 返回只读边界；`available` 与实际恢复验证使用同一逻辑。
- 恢复按钮只在 `available` 时启用；不可用时显示原因由恢复 API 返回。
- 计划面板继续展示 `REUSED` 节点和复用来源实例；刷新后由数据库重建。
- 报告与尝试轨迹保留原运行和子运行，汇总说明复用来源和继承消耗。

## 6. 兼容与不变量

- `tool_invocations.resource_version`、交接证据版本列和 `workflow_checkpoints.tool_calls` 均为追加字段；旧记录为空，视为缺少版本证据，不参与只读工作区复用。
- 旧纯文本检查点摘要算法不变；新增字段不参与 v1 摘要。
- 工作区文件、授权集合、计划、审批或用量任一变化都拒绝恢复，不尝试自动修复。
- 恢复不重放写入、不继续 Bug 修复、不推断未知副作用。

## 7. 验收与测试

自动化覆盖：

1. 首个节点前恢复：子运行完整执行，原运行保留，预算不重置。
2. 已结算只读分析后恢复：分析节点 `REUSED` 且未重复读取；系统检查重新执行；剩余汇总节点继续；模型/工具消耗继承。
3. 文件内容变化、授权集合变化、来源结果篡改、后续检查已认领：边界不可用，恢复被拒绝。
4. 重复恢复：同一来源最多成功一次。
5. 子运行再次恢复：按矩阵拒绝。
6. 纯文本恢复历史用例继续通过。
