# 动态工作流计划迁移与顺序调度设计

## 存储与兼容

本轮增加受信模板「双视角分析」。两个节点引用同一个分析定义，分别检查需求与验收、约束与风险。汇合节点依赖二者。现有只读、写入、Bug 和检查点流程继续走兼容计划。调用方通过任务的 workflowTemplate 显式选择动态模板，可用 reviewPlan 要求确认；省略选择时沿用兼容计划。

- workflow_plans 保存每个动态运行唯一的激活计划版本及确认策略。首期只创建版本 1，模板标识及版本固定，运行中不改图。旧记录无对应计划版本时，保留原始兼容视图。
- plan_nodes 和 plan_node_dependencies 仍是节点与边的权威来源。旧 role_code 槽继续唯一并保留旧依赖回填。动态节点以空旧角色槽、独立节点键、阶段和 permission_role 持久化。后者用于装配及既有单实例额度，调度和交接均按节点标识。
- workflow_attempts 保存尝试标识、序号、节点、实例引用及计时来源。agent_invocations 是实际实例状态和结果的权威来源，节点状态在事务内随实例更新。首期每个节点一次尝试，异常或未知动作停止，手工重跑使用新运行。
- workflow_handoffs 保存接收尝试与发送尝试的依赖关联和交接版本。输出正文只保留在发送实例记录中。认领事务逐一核对完成状态、同计划、直接依赖与输出，写入接受关系后用这些输入构建模型请求。边、尝试和实例的归属缺失时拒绝启动。
- H2 新增表与列采用可重复的增量 DDL。旧 role_code 只放宽可空性，旧唯一约束保留。迁移标识写在本批 DDL 执行之后；启动失败后可重入。旧计划和预算不搬行、不重写定义摘要。验证使用旧脚本创建的隔离库；回退通过恢复迁移前副本保留原版语义，迁移后动态记录只由新程序处理。

## 执行与失败

创建事务同时保存任务、运行、计划与依赖。审批策略固定在计划中；要求审阅的运行留在待执行状态，确认前不投递队列，进程重启仍可确认。确认使用条件更新，只触发一次投递；确认后宕机或投递失败按中断或失败处理。取消仍使用运行控制。

调度每轮从已保存 DAG 按顺序选就绪节点。认领事务锁定运行行，校验运行状态、计划确认和当前执行状态，再原子写入节点认领、实例、尝试和全部直接依赖交接。每次实际执行新建独立 AgentScope 实例和会话并复用同一 RunControl。成功节点原子结算实例与节点；全部完成才提交运行结果。失败或取消结算在途实例、保留已完成节点、跳过未启动节点。动态运行重启后显示中断，符合下述条件时可申请从已保存边界恢复。

受信代码注册模板和定义。当前模板只面向无工作区、无 Bug 的任务，使用无工具的只读分析定义组合。计划创建先校验定义、权限、节点图和引用，执行时再校验定义及摘要。节点职责、任务目标和前置输出采用结构化输入。模型文本按资料处理，任何文本均不能扩大授权。结果只表述模型分析，实际调用和消耗从受控记录获取。

## 验收

用隔离 H2 旧结构验证旧角色、历史依赖、原预算以及重复启动迁移，验证动态记录和历史记录同时可读。用模拟模型验证计划先保存、审批与重复确认、两个同定义实例、汇合的两条交接、总预算耗尽、取消及终态保护。注入认领事务写入异常，检查节点、实例、尝试、回执一致回滚。动态计划与实际节点、实例、尝试和交接通过现有工作台运行详情查询。

## 动态流程安全恢复

- 独立动态检查点记录版本、计划、已完成节点数量、轮次、工具次数、耗时与摘要。初始快照在首个节点认领前保存。未全部完成时，节点完成和后续检查点在同一事务保存。
- 恢复仅允许任务配置和计划版本一致、无工作区副作用、源运行已中断且在选定检查点之后未认领新节点。检查点摘要绑定计划图、审批、任务与预算策略、每个已完成节点的实际实例／尝试、定义与结果。仍有中断、失败、未知或额外调用时拒绝；不恢复框架会话。
- 恢复事务锁定源运行、重新核验检查点和任务、继承最大已结算消耗并创建一次子运行。子运行用新的计划和节点标识，继承模板版本、定义和依赖结构。已完成节点标记为复用并引用同任务源运行的真实实例；从依赖直接来源核验输入，仅未完成节点产生新实例。整个子运行保留可查询的来源。当前只支持直接子运行，子运行中断时保留记录，不支持再次恢复。
- 前端沿用恢复入口，只展示持久化检查点并由服务端重新验证。完整回归覆盖安全边界恢复、已执行预算和双来源汇合，以及边界后发生认领、篡改结果或审批状态不匹配时拒绝。
