# 动态工作流节点重试设计

新建的动态计划可对每个节点最多启动两次尝试，尝试上限随计划保存并参与图摘要。历史计划沿用原有单次尝试和摘要。AgentScope 的模型层继续使用包含首请求在内的一次尝试，节点重试由工作流控制。

适配器仅将可确认的、尚未返回任何响应内容的模型限流拒绝提交为候选。OpenAI 兼容适配器依赖 SDK 的实际 HTTP 429 路径，排除响应正文中推断的状态码。当前 SDK 不提供可用的限流响应头，执行器在剩余时间内退避约一秒。网络超时、响应中断、用户取消、未知写入和无法核验的错误不进入自动重试。

退避前确认当前实例已经结算，且该尝试没有登记任何工具调用。模型失败记账、过往尝试和输入收据全部保留。事务内结束失败实例、记录失败原因并把节点放回待执行；前置节点保持完成状态。重新认领取得新尝试、实例和会话，且再次读取已确认的前置输入。总预算和节点预算累计，角色及单实例限额按新实例计算。用量有上限时，无法确认拒绝请求的用量会禁止重试。已有重试记录的运行暂不生成新的恢复边界。

验收覆盖明确拒绝后重试成功、连续限流到达次数上限、节点预算耗尽或已调用工具时不重试，以及失败尝试和调用用量可查。回归只在功能闭环完成后集中执行。
