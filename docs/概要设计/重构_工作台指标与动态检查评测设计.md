# 工作台指标与动态检查评测设计

> 实施日期：2026-11-18。对应交接任务 5 与 A09、A14—A15、A21、A24—A25。

## 1. 工作台与报告

运行详情新增 `workflowMetrics`（`RunMetricsService.workflow`），从持久化记录汇总：

- 计划节点总数及各状态数量；
- 系统检查记录数、各状态数量、未执行检查节点数；
- 实际启动的模型调用、工具调用和未知用量调用数。

计划面板在标题下显示同一汇总；节点列表继续展示 Agent 尝试、检查状态、交接来源、复用实例和阻塞原因。数据来自数据库查询，刷新或事件重连后不会依赖前端临时状态。

HTML 报告新增“计划、检查与调用统计”小节，列出节点状态、检查状态、未执行检查、实际调用和未知用量，并逐条列出检查记录、摘要与外部证据标识。报告只输出枚举、标识、计数和受控摘要。

## 2. 评测种子

新增套件 `DYNAMIC_CHECK_V1`，包含两个可重复案例：

| 案例 | 输入 | 断言 |
| --- | --- | --- |
| `DYNAMIC_CHECK_PASS` | 临时只读工作区，授权一个文件；`workspace-analysis@2` | 计划保存并确认、检查通过、检查输入来源和摘要存在、模型调用 3 次、工具调用 1 次、全部节点完成。 |
| `DYNAMIC_CHECK_BLOCKED` | 临时 Bug 工作区，无 `tests` 目录；`bug-fix@2` | 运行 `BLOCKED`/`CHECK_FAILED`、检查 `BLOCKED`、复现节点失败、下游全部跳过、Agent 和模型/工具调用为零。 |

评测服务为工作区案例在系统临时目录创建独立 Git 仓库和 worktree，使用模拟模型；临时仓库保留供复核，不触碰用户工作区。套件快照保存模板和版本、断言编码，旧套件定义继续可读，不同定义不被判定为改善或退化。

## 3. 边界

- 不把未启动的模型或工具调用计为实际次数。
- 未知 Token 单独统计，不按零处理。
- 检查节点不产生 Agent 实例；阻塞案例不创建下游调用。
- 评测不调用真实模型；Bug 阻塞案例在缺少 `tests` 时不会启动 Docker。
