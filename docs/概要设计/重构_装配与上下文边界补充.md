# 装配、上下文与控制边界补充设计

> 实施日期：2026-11-18。对应交接任务 4 与验收 A03、A05、A09—A10、A13、A16—A22、A24。补充现有实现缺失的两个明确行为：上下文限额和拒绝原因的可定位记录。

## 1. 上下文限额

0.1 版本不实现自动压缩或多级裁剪。上下文按固定顺序装配：

1. 任务契约、用户目标、授权文件和约束（硬约束，必须先装配）；
2. 用户确认的项目背景（低可信，仅授权时装配）；
3. 本次 Bug 观察等受控证据；
4. 任务输入中已有的上游交接和证据引用。

装配结果超过 `AgentContextAssembler.DEFAULT_MAX_CHARS = 60000` 字符时，在启动模型前抛出明确异常并结束当前节点。系统不静默截断、不丢弃硬约束，也不以“上下文已压缩”作为已完成能力。运行详情记录拒绝原因；模型、工具和 AgentScope 实例不会因该次拒绝产生调用。

后续若要支持压缩，必须分别记录被引用内容、压缩策略、压缩结果及无法满足硬约束时的阻塞，而不是复用当前限额。

## 2. 拒绝原因可定位

装配计划、Agent 定义、工具权限、上下文、系统检查等由项目代码抛出的 `IllegalArgumentException` / `IllegalStateException`，在动态工作流停止时写入运行原因，格式为“工作流执行被拒绝：<安全原因>”，并限制长度。

- 原因只来自项目生成的固定文本，不拼接模型输出、文件正文或密钥。
- 数据库、网络等未分类异常仍使用通用失败原因，避免泄露底层细节。
- 计划创建和确认阶段的拒绝继续由 HTTP 400 返回具体原因；运行阶段拒绝从运行详情和事件查看。

## 4. 事务与失败注入

- 认领、装配快照、交接、节点结算和运行终态继续使用原有事务边界。
- 装配快照落库失败时回滚定义、技能和工具投影，不调用模型。
- 交接写入失败时回滚节点认领、实例和尝试。
- 终态事件失败时回滚运行状态、Agent 状态、节点和系统交接。
- 检查节点认领失败时回滚节点状态与检查记录。

本任务只补充上述上下文限额与原因记录，不改变已有事务实现。

## 5. 测试

- 上下文来源排序、重复来源、空来源和超限拒绝。
- 正常 HTTP 入口下的装配拒绝：运行失败原因包含定义/版本拒绝文本，模型与工具调用为零。
- 动态取消后模型晚到：运行保持 `CANCELLED`，迟到的成功结果不写为完成用量。
- 不确定写入：运行 `FAILED`/`TOOL_EFFECT_UNKNOWN`，写入调用保留失败记录，独立审查不启动，不自动重放。
- 纯文本、只读、写入、Bug 和检查节点的既有回归保持通过。
