# 重构首批：Agent 定义与旧角色兼容设计

> 本文描述将现有真实 AgentScope 执行逐步接入可扩展定义目录的第一步。它不是完整动态任务图实现；整体目标与验收以[动态 Agent 重构概要设计](动态Agent与可组合工作流_重构概要设计.md)为准。

## 1. 目标和现状

现有 `AgentExecutionRequest`、角色预算、交接和数据库仍使用 `AgentRole`；直接删除枚举会绕过既有授权与历史兼容。本批先引入受信代码提供的版本化 `AgentDefinition`，允许定义独立于角色名称配置提示、工具和技能，并使其进入实际 AgentScope 装配流程。现有三个角色继续映射到内置定义。

## 2. 定义、权限和装配

1. 定义引用由开放、受校验的标识和正整数版本组成；定义包含实例名称、系统提示、工具清单、技能清单，以及过渡期的旧角色权限配置引用。
2. 注册表由内置定义和受信代码提供者构建；拒绝重复 ID／版本、缺失数据、未知技能和超出旧权限配置上限的工具。列表不可由模型或任务输入直接注册。
3. 旧角色映射内置定义，原请求不指定定义时继续按旧映射运行；内部请求可引用已注册定义。选择的定义必须匹配请求已绑定的旧权限配置，防止借新定义绕过权限和按角色预算。
4. 实际工具为定义声明、旧权限上限和任务授权的交集；现有工具提供者和网关继续执行。实际技能从已注册的可信目录按定义清单选择。模型模式、上下文、运行控制和 AgentScope 会话继续沿用现有受控路径。
5. 解析成功后、装配工具或启动模型前，将本次选择的定义标识和版本写入真实 Agent 调用记录。旧记录的定义字段保持未知；无法记录时拒绝继续。该记录仅证明定义已解析，不表示工具已注册或模型已运行；完整装配快照仍需后续实现。
6. 旧公开 API 暂不允许用户或模型传入任意定义；内部扩展示例只验证真实装配与 AgentScope 执行。工作流按定义调度、非角色身份及其事件、预算和历史迁移在后续批次完成。

## 3. 兼容与安全边界

- 旧角色提示、工具、技能、版本及授权行为保持兼容；只做基于服务端的受信扩展，插件沙箱与动态代码加载不在范围内。
- `AgentRole` 是过渡期权限和记录兼容配置，不应在文档中声称这一步已消除固定角色或完成动态 Agent；当前数据和页面仍以角色记录。
- 不变更历史角色枚举、数据库编码及旧 API；不读取真实 API Key，不新建具体工具。

## 4. 验收

1. 内置角色通过新目录解析，旧任务的权限、技能及工具装配保持一致。
2. 受信提供者可使用已有技能和权限范围注册新定义并由 AgentScope 执行；身份、运行控制和授权仍由既有系统提供。
3. 版本不存在、重复引用、未知技能、声明越权工具、请求角色权限配置不匹配时在执行前拒绝。
4. 配置集合不可变，未注册定义不能执行；旧模型、旧 API 和历史测试不回退。
5. 新运行记录实际解析的定义标识和版本；历史数据空值保持未知；记录失败或对非运行中实例写入时不能启动模型。
