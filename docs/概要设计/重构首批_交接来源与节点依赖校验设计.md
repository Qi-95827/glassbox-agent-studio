# 交接来源与节点依赖校验

## 目标与范围

旧顺序执行器仍以角色选择接收节点；在它启动接收实例和写入交接回执前，增加基于已保存任务图的来源检查。原有交接校验已经检查任务运行、角色和历史来源；本次进一步确认发送实例是接收节点的直接前置节点，防止同一运行中已完成但不相邻的节点冒充上游。

## 输入与判定

- 输入为运行 ID、接收角色、交接中发送实例 ID；角色只用于兼容旧执行器定位唯一接收节点，节点 ID 和依赖关系以持久化计划为准。
- 图或归属不完整、角色对应零个或多个接收节点、发送者为空、无直接前置依赖或发送实例不匹配时拒绝启动。
- 当前运行内的前置节点必须是 `COMPLETED`，发送实例必须等于该节点保存的 `agentId`。检查点恢复时，前置节点处于 `REUSED`，允许其明确记录的 `sourceAgentId` 作为发送实例；历史来源由现有恢复校验负责确认，不推测补齐。
- 所有前置节点仍须通过节点认领现有的就绪检查；多前置情况下此校验只确认当前交接来源属于其中一个直接依赖，不代表已完成多来源汇合。

## 事务与边界

来源检查、节点认领、实例记录和接收回执位于原有事务中；异常时不创建接收实例或回执。图读取后的状态仍由节点认领 SQL 再次验证，不能将内存检查当作并发锁。

本轮不改数据库、不开放同角色多节点或通用节点交接，不声称覆盖所有节点间通信。后续动态调度改为显式传递接收节点 ID，补充每个依赖的输入契约与多来源交接关联。

## 验收

1. 正常前置节点交接、分析检查点复用和事务回滚的既有流程继续工作。
2. 即使其他运行的发送实例已经完成，也不能冒充当前运行的前置节点；拒绝后接收实例和回执不存在。
3. 多依赖、失败状态、非前置发送者和来源记录缺失均有明确拒绝或通过条件，并以独立数据库测试验证。
