# 重构首批：工具装配上下文解耦

> 本文是动态 Agent 重构的过渡设计，不新增具体工具，也不声称通用工具沙箱已经完成。

## 问题与目标

当前 AgentScope 执行器直接持有模拟检查工具和工作区服务，并将二者放入所有工具共享的 `AgentToolContext`。这使增加不同工具时，Agent 执行器必须了解工具实现。目标是由内置工具提供者通过服务端依赖注入取得自己的业务服务；执行器只传递本次任务的授权路径、模型场景、运行控制及记录上下文。

## 处理流程和约束

1. Agent 请求中的工作区、文件和写授权由旧任务路径验证；执行器创建不可变的本次工具上下文，保留经校验的路径集合、场景、JSON 编解码、运行控制和共享失败状态。
2. 内置模拟工具提供者只注入模拟工具服务；工作区工具提供者只注入工作区服务，使用上下文的授权路径构造 `AuthorizedFileSet`。具体工具仍为独立类。
3. 计划允许的工具与任务权限求交集后，由现有注册表检查工具契约版本并装入 AgentScope；现有工具的网关、预算、错误和版本记录不变。
4. `AgentToolContext` 不持有 `WorkspaceService` 或 `SimulatedTool` 等具体业务服务；新工具的独立服务应由其可信提供者注入，不向执行器增加字段。
5. 保留运行时接口和工具注册的受信任代码边界。当前注册表还不能强制任意第三方提供者经过网关，不能因此声称具备不受信插件沙箱；未受控扩展不得对外开放。

## 验收

- 模拟检查、授权文件读写和搜索的权限、版本、限额和异常行为保持；未授权时不注册对应工具。
- 工具上下文的路径列表不可被事后修改；空工作区不能携带授权文件。
- 现有 AgentScope 模拟运行、工具注册、工作区和旧接口回归通过；新增工具不需要修改 AgentScope 执行器的具体服务字段。
