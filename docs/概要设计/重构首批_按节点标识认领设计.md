# 重构首批：按节点标识认领

> 本文是[动态 Agent 重构概要设计](动态Agent与可组合工作流_重构概要设计.md)的过渡实现：将已有计划认领从直接依赖角色变为可按节点 ID 检查与认领，暂不开放任意动态图或同角色重复节点。

## 目标和边界

现有计划已保存节点 UUID 和多个依赖，但 `PlanRepository.start` 以角色找到节点。先增加按 UUID 的受控认领入口：校验节点确属该运行，构建实际保存的依赖图，仅当全部必需依赖满足时执行条件更新。旧角色入口只作为兼容适配，需唯一映射到一个节点后使用同一条认领路径。

认领更新保留数据库对待执行状态、跨运行引用和所有前置节点状态的再次检查，避免内存就绪结果和落库间发生竞态。调用者仍负责与实际 Agent 调用、委派记录等在既定事务边界内配合；单独认领不表示模型已启动。

当前表仍有 `UNIQUE(run_id, role_code)` 和旧单依赖字段，执行器仍按固定角色运行；不能把此入口称作完整动态任务图、独立尝试或新角色调度。后续迁移约束、身份和调度时须保持旧接口和历史记录兼容。

## 验收

1. 同一运行内通过节点 ID 认领就绪节点并记录真实实例；重复认领或其他运行的节点拒绝。
2. 多前置节点必须全部完成或可靠复用；非就绪节点不启动。
3. 角色兼容入口与节点入口走相同持久化检查；数据库条件更新仍阻止并发重复认领。
