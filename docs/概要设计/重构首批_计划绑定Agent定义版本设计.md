# 重构首批：计划绑定 Agent 定义版本

> 本文是[动态 Agent 重构概要设计](动态Agent与可组合工作流_重构概要设计.md)的过渡实现。当前仅给既有受控计划固定内置定义，仍未开放自定义计划或动态多 Agent 调度。

## 目标

先前计划节点只保存固定角色，而执行时才从角色推导定义；若定义发生变化，计划与实际执行可能不一致。本次在创建计划时同时保存对应的受控定义标识和版本，Agent 启动后从所属节点读取固定引用，交由已有定义目录解析并校验权限。

## 契约和流程

1. 在 `plan_nodes` 中增设可为空的 `definition_id`、`definition_version`，新建计划在原有事务中保存二者；来自角色的内置定义使用同一个服务端映射规则，不能由模型或用户提供权限。
2. `PlanNode` 以可为空的 `AgentDefinitionRef` 表示该引用。两个字段均为空表示历史计划没有此信息，两个字段仅一个为空或格式无效时视为记录损坏并拒绝读取。
3. 创建 Agent 调用记录并认领节点后，执行器依据同一运行与实例查询对应节点的固定引用；定义不存在、版本不匹配或权限配置不匹配时，不能回退到其他定义。
4. 历史节点的两个字段均为空时，旧固定流程可按当前旧角色兼容路径解析，但**不回填或伪造计划的历史定义**；实际解析的定义记录到本次真实 Agent 调用中。
5. API 返回的计划可包含可为空的定义引用，与旧字段并存。定义被记录只说明计划或实例分别引用了它，不表示工具或模型调用成功。

## 恢复、控制和限制

原有安全检查点继续适用；新恢复运行创建新计划时，按已支持的恢复路径重新验证引用与权限，历史证据仍按原有逻辑校验。本批不支持用户选择新定义、同角色重复节点、运行中改图、任意新工作流或完整装配快照。

本批进一步保存**定义声明摘要**：用带长度的规范编码和 SHA-256，覆盖定义标识、版本、名称、系统提示、旧权限配置、按序工具 ID 和技能的 ID／版本／内容摘要。新计划和实际解析记录分别持久化摘要；执行前重新计算并比对，不一致时拒绝调用。摘要不包含密钥或提示明文。

历史节点没有定义引用时保留旧兼容路径；已有定义引用但缺少摘要时，历史查询保留未知，执行时拒绝将其当作已验证版本，不能根据当前定义伪造原摘要。此摘要覆盖定义声明和技能内容，**不证明模型供应商行为、工具实现代码或完整上下文不变**；工具实现和完整装配快照的版本治理仍需后续完成。

## 验收

- 新建计划在任何节点运行前带有可查询的定义标识及版本；实际实例记录与其所属计划一致。
- 相同 ID／版本下的提示、权限配置、工具声明或技能版本／内容变化时摘要变化；计划执行时核验失败，不调用模型。
- 老数据双空保持空；部分字段缺失、格式错误或未知定义不可被静默当作默认定义。
- 运行、节点和实例归属需一致，旧权限、预算、交接和恢复测试保持通过；计划与节点仍在原事务内创建。
