# 通用工作流声明与旧计划适配

## 问题与边界

此前计划以角色作为节点身份，无法表达同一类 Agent 在同一次运行中执行多个不同节点。重构需要区分三个概念：工作流中的节点标识、该节点使用的版本化 Agent 定义，以及它所依赖的前置节点。

## 本轮实现

1. `WorkflowDefinition` 声明独立节点标识、Agent 定义引用及依赖，并通过 `WorkflowGraph` 校验节点数量、标识、依赖及有向无环约束。同一个定义可以由多个不同节点引用。
2. 当前固定角色计划在校验和保存时转为通用声明；存储时由节点标识分配独立运行节点 UUID，再按这些标识写入依赖关系。
3. 兼容旧运行时，以固定角色生成内置定义引用，保存前核对权限配置并计算定义摘要。实际执行和历史数据仍使用现有兼容路径。

## 后续必须完成

- 当前数据库仍限制同一运行中的角色唯一；旧执行器、交接和预算也仍以角色为中心。因此通用声明暂时**不能**通过现有运行 API 执行重复角色节点。
- 在启用动态计划前，需要设计可迁移的版本化持久化方案、节点和实例的身份关系、节点级交接及预算，并处理旧数据与宕机恢复。不能直接移除约束后声称兼容旧执行器。
- 未来接入其他 Agent 定义时，计划保存必须解析受信注册表、固化定义版本与摘要，并在执行时重新校验；节点图的结构校验不能代替权限或执行能力校验。
- 通用声明目前仅描述 Agent 节点，系统动作、审批及其他节点类型尚未纳入，前端也仍展示旧计划。
