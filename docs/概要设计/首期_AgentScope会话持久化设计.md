# AgentScope 会话持久化设计

## 目的与边界

复用 AgentScope 2.0.4 官方 `AgentStateStore` JDBC 实现，把每个 Agent 实例的框架会话保存到当前工作台 H2 数据库。此能力是后续会话恢复的基础；会话保存不等于系统级检查点，不证明完整任务可以恢复，也不会撤销外部副作用。

## 实现方式

1. 每个 Agent 调用使用数据库中的实例 UUID 作为独立 sessionId。当前单机实现使用匿名 userId；这不构成多租户认证或隔离。
2. 使用官方 JDBC 存储与 H2 方言，框架建表使用 `agentscope_` 前缀。成功调用结束时由框架持久化状态；异常处理也可能保存状态，异常状态不能直接当成可恢复检查点。
3. 使用框架乐观版本和 `FAIL` 冲突策略，避免会话版本冲突时静默覆盖。当前业务没有跨进程任务租约，也不能依靠这个机制实现恰好一次执行。
4. 运行页面只展示已保存、尚无记录或读取不可用，以及可用时的版本；接口不返回会话正文。当前的安全边界检查点和恢复逻辑保持原样，尚未把框架会话接入恢复流程。宕机发生在调用期间，最后一次保存后的状态可能丢失，在途模型或工具结果也可能未知。

## 数据治理

框架状态可能包含用户输入、模型响应、工具参数与结果、授权文件内容等，按框架序列化明文保存在本机数据库；当前尚无自动脱敏、加密、保留期限、细粒度访问控制或租户隔离。不要将本机数据库直接公开或纳入源码仓库。后续使用这些状态恢复前，需要明确授权、生命周期、工具权限重建与外部动作对账。

## 验证

集成测试确认不同 Agent 的会话可读且彼此独立；隔离存储测试验证重新创建存储实例后可读、旧版本写入拒绝、不同会话／用户隔开。此测试覆盖的是状态存储，不证明长任务中断后能继续，也不验证分布式租约。
