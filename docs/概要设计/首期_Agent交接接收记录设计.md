# Agent 交接接收记录

## 问题

保存上游交接与启动下游 Agent 原本是两个操作；若中途宕机，已保存交接不代表下游实例已启动。历史数据也没有明确的接收记录。

## 边界与流程

1. 上游完成并保存交接，记录预定接收实例；该记录表示交接已准备，不表示接收方已运行。
2. 在一个数据库事务中重新核对交接与运行归属、接收实例和角色、上游已完成及计划前置条件，启动下游计划节点并创建 Agent 调用，写入接收记录及事件。任一环节失败，整个事务回滚。接收记录对交接 ID 和接收实例分别唯一。
3. 页面与报告展示是否有接收实例启动记录；历史未记录和中途尚未启动使用相同的“未记录”，不倒推。该记录不证明模型实际收到输入、处理成功或外部调用完成。

首期仍为单进程固定顺序计划；没有跨进程消息队列、确认重试、全局恰好一次或外部副作用回滚。

## 协调者委派

协调者向首个分析 Agent 的委派，也将计划节点启动、Agent 调用、委派交接、接收记录和接收事件合并为同一事务。先在事务内创建调用供交接归属校验，任何写入失败均回滚全部内容；历史委派无接收记录时仍显示未知。

## Agent 结果提交

分析、开发和审查 Agent 的成功结果交接与其节点、调用完成状态放在一个事务中。校验交接的 Agent、完成状态和摘要与本次结果一致；写入失败全部回滚，不能只看到结果而没有完成状态。审查结果在最终取消／暂停检查之后提交；审查 Agent 的结果与运行终态共同提交；分析、开发结果不代表整次运行已完成。
