# Agent 交接中的测试证据设计

## 目标

分析、开发和审查 Agent 之间的交接除保留工具事件引用，还需要结构化引用本次 Bug 任务中的失败观察及回归检测 ID，避免只在自然语言摘要里提及测试而无法可靠追溯。

## 契约与校验

1. 保留历史交接契约 v1 的读取语义，旧记录没有测试引用时保持未知；包含明确测试引用的新交接使用 v2，单独保存检测 ID 列表。
2. 分析完成和交给开发阶段可引用本次失败观察；审查阶段可额外引用本次回归。引用只表示记录被纳入交接，不代表特定 Bug 确认复现、回归充分或通过人工审查。
3. 写入交接前校验检测存在，且属于同一运行、同一任务指定的 Bug 和工作区；拒绝重复、跨运行、缺失及不适用的引用。旧版交接不能携带 v2 测试引用。
4. 交接 JSON、运行详情和 HTML 报告展示测试 ID 和契约版本；不自动传递测试完整输出，用户可通过运行检测证据查看原始记录。

## 边界

已有工具事件引用与祖先运行恢复规则保持不变。当前关联工作区／Bug 的检查点仍不支持恢复；测试 ID 不代替代码状态校验、租户授权或端到端修复评测。测试记录内容若含敏感数据，展示和报告仍需用户审查。
