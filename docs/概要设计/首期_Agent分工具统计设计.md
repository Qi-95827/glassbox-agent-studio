# Agent 分工具调用统计设计

## 目标与口径

按实际 Agent 实例和调用记录中的工具名称汇总次数、各状态数量、已知耗时合计与耗时未知的次数，帮助定位评测期间的工具调用问题。统计来自当前数据库快照，包含已启动的成功、失败、取消、中断、超限和运行中调用；如果调用在启动前被预算拒绝，它不会出现在调用次数中，需查看运行事件。

## 类型和未知值

每组包含工具显示名称、调用总数、以受控 InvocationStatus 枚举为键的状态计数、未知状态条数、已知耗时毫秒总和（没有任何已知值时为 null）及耗时未知条数。保留旧记录中的未知状态，不强行解释成失败或成功；工具名称是历史开放文本，不因新增工具强制归入封闭枚举。无调用则列表为空；未知不能算零。它不是每种工具的 P95、真实资源费用或跨运行／跨租户监控。

## 展示和验证

在现有 Agent 统计接口增加字段，保持原字段兼容；工作台和静态 HTML 报告分别显示分工具统计，报告对名称进行 HTML 转义。验收覆盖多 Agent 归属、相同工具不同结果、未知耗时及未知状态、无调用和不可信工具名称；跨恢复运行需要分别查看各运行，不能将复用的旧调用算成本次调用。

后台概况也保留未识别状态编码并显示为未知；Prometheus 以固定 kind 标签暴露未知状态数量，不把任意编码作为标签。未知枚举仍应检查版本或数据兼容，不能被视为成功。
