# Agent 工具装配追溯设计

## 范围与语义

为每个实际启动的 Agent 记录其 Toolkit 初始化时成功注册的工具种类，展示于运行详情和 HTML 报告，帮助用户理解多 Agent 的模块装配。装配是当时角色能力与用户任务授权求交后的结果，记录不代表模型必然调用工具，也不证明每次调用通过权限或参数校验；实际执行仍以工具调用记录为准。

## 流程和数据

按角色和任务权限计算工具集合，逐一注册，并验证注册集合与计算结果一致；注册完成后在一个事务内记录 Agent 装配标记和各工具枚举。空集合也记录标记，以区分“确认无工具”和旧运行或装配未成功时的“未记录”。若无法登记则不启动模型。只存类型和时间，不存路径、参数、工具结果或密钥。重复登记拒绝，已有历史不变。工具执行仍须通过现有服务端授权、参数检查、预算和工具包装，追溯记录不能授权工具。

## 展示与限制

接口先验证运行存在，只返回该运行各实际 Agent 的已登记工具集合；复用的历史 Agent 不伪造成当前 Agent。页面与报告区分空集和无记录，并注明时间点；将来动态撤权时必须另行设计授权版本与传播，不能凭此历史记录放行。当前并非动态插件市场、跨租户隔离或完整工具版本治理。测试覆盖只读／写入角色、空工具审查角色、旧数据、注册失败、同一 Agent 重复登记与既有实际工具调用。
