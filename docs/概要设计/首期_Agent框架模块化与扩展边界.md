# Agent 框架模块化与扩展边界

> 本文的原始模块化重构保持数据库结构；后续任务图依赖持久化新增了数据表，具体范围和兼容方式见对应设计。

## 目标

优先建设 Agent 框架，不增加具体业务工具。协调层依赖稳定的 Agent 执行契约；AgentScope 适配器负责会话与推理；模型、工具分别通过提供者注册；现有角色、技能、授权、预算、事件、记忆和检查点继续由各自模块负责。组件边界服务于现有可运行流程，不把空接口当成已经支持的动态编排。

## 职责与契约

1. **协调与执行**：协调器向 `AgentExecutor` 提交不可变的 `AgentExecutionRequest`，包含角色、实例 ID、输入、工作区授权、场景、模型模式、恢复阶段和运行控制。AgentScope 实现仍通过 `ControlledModel`、`AgentRuntime`、独立会话和真实的 ReActAgent 执行。调用失败、预算、暂停、取消与结果记录保持原有语义。
2. **模型扩展**：`AgentModelProvider` 根据受控模式创建底层模型；注册表按模式查找，重复或缺失拒绝启动。模拟和 DeepSeek 是两个现有适配器；无实际 DeepSeek 选择时不读取密钥。增加新模式仍需更新现有枚举及对应业务兼容，不支持运行时加载不受信插件。
3. **工具扩展**：`AgentToolProvider` 声明受控 `ToolKind`、服务端契约版本并创建 AgentScope 工具；注册表校验重复类型、计划与实现版本、空实例、注册结果。只按角色与任务授权形成的装配计划注册；技能与模型不能扩权。原有模拟与文件工具作为可信内置适配器，其调用仍经过 `ToolGateway`、`AgentRuntime`、预算和审计；扩展必须接入同一网关，不得绕过。开发者编写的插件属于可信本地代码，接口本身不是沙箱。当前工具类型、限额和持久化编码仍使用封闭枚举，新类型还需要明确扩展枚举、授权策略、数据库约束迁移与测试；不能宣称外部任意工具可热插拔。
4. **上下文和记忆**：上下文由协调模块按任务契约组装，任务目标、项目背景、Bug 证据拆为可排序、可扩展的来源；标识重复或返回空值时拒绝执行。项目背景只在显式授权时读取并记录引用，低可信资料不能改变系统规则。后续需要解决压缩、撤权传播和真实长期记忆评测。
5. **多 Agent 与交接**：按节点 UUID 持久化多前置依赖，验证节点、引用与环，并根据真实节点状态计算可启动节点；现有计划校验和启动前检查复用该能力，数据库条件更新仍是防止重复启动的最终依据。当前创建和运行仍只支持固定分析、开发、审查顺序，且同一角色在运行中只能出现一次；尚未开放任意任务图驱动运行。后续需完成可配置角色、同角色多节点、通用调度、并发预算和恢复后才能开放动态任务执行，详见 [依赖持久化设计](首期_多Agent任务图依赖持久化设计.md)。
6. **控制、恢复、观测与评测**：继续复用现有运行控制、事件、检查点、指标和固定种子评测，模块边界不表示周期检查点、跨进程恢复、严格 Token 预算、真实修复评测或多租户已经完成。

## 安全和兼容

只重构框架组装路径，不改变已有 HTTP 请求、角色权限、工具版本、会话和数据库结构。装配失败必须在调用模型前失败，不记录未实际注册的工具；多注册或版本不匹配时拒绝运行。除可信应用自身的访问边界以外，不对扩展代码提供隔离承诺；不读取、打印或提交用户 API Key。

## 验收

隔离测试覆盖新提供者能装配进入 AgentScope、无权限工具不注册、重复或缺失提供者失败、工具版本不匹配失败、模拟与真实模型选择、调用与预算记录仍正确，以及既有多 Agent、恢复和模拟 Bug 回归。检查真实模型创建不作为默认回归的一部分。本阶段不声明整个多 Agent 框架或概要设计已完成。
