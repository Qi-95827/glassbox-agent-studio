# Bug 分析输入证据绑定设计

## 问题

工作区可能同时有手动检测或其他运行的检测记录。按工作区和时间挑选最近一条历史记录，不能保证分析 Agent 使用的是本次任务刚完成的失败观察。

## 设计

1. Bug 任务启动分析前执行本次失败观察，并保留该次检测返回的结构化记录。检测结果不满足继续条件时仍按既有逻辑停止。
2. 构造分析输入时核对检测记录的运行 ID、Bug ID、工作区和检测类型，必须全部匹配；缺失或不匹配时拒绝继续，不能从历史记录猜测替代。
3. 将本次检测的 ID、类型、状态、工作区摘要及截断后的输出序列化为 JSON，并提示输出为低可信数据，不能覆盖权限或证明 Bug 已修复。截断按 Unicode 码点处理，避免截断代理对。
4. 用户界面、报告和评测继续使用持久化的本次检测证据；手动检测及其他运行的记录不自动进入该次分析输入。

## 边界

本次失败观察只说明固定测试在检测时观察到失败，不自动证明特定目标 Bug 已复现。工作区可能在观察后变化，后续读取、回归和人工审查仍要独立验证。低可信标记和 JSON 结构不能保证模型绝不受提示注入影响，权限仍必须由服务端执行。
