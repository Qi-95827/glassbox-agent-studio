# Bug 检测证据归属设计

## 问题

同一工作区可能有多次 Agent 运行和手动测试。仅凭工作区、时间或事件文字，无法可靠证明某次检测属于某一次运行，进而不能用它判定该次 Agent 的修复或回归结果。

## 设计

1. 自动任务发起失败观察或回归时，服务端校验运行处于运行中、运行所属任务的 Bug 与工作区匹配，再在检测记录中写入 runId。
2. 保留检测类型、结果、耗时、输出和执行前后的工作区版本摘要；无法绑定可靠版本或检测过程中版本变化时，不能认定为当前版本的通过证据。
3. 手动检测不属于特定运行，旧检测记录新增字段为空，均不按时间猜测。运行详情仅显示明确关联的检测；工作区检测历史仍可独立查看。任务检测会在准备和启动容器前检查取消与时间预算；检查之后到进程启动之间仍有并发窗口，已启动的容器通过协作式检查请求停止。
4. 运行页面展示检测类型、结果、代码状态摘要和输出；实际测试结果不能替代针对目标 Bug 的复现证明、完整回归或用户审查。

## 限制

该关联为以后评测真实修复提供证据基础，本身不自动判断修复质量、测试覆盖率或完整验收。当前只支持内置模拟 Bug、固定 Python unittest 和本机容器；没有真实 Bug 平台、跨任务取证策略或测试结果脱敏。数据库历史为空不代表从未运行测试。
