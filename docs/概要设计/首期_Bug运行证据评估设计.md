# Bug 运行证据评估设计

## 目标

为一次 Bug 运行提供可复核的证据快照，把“某个测试曾观察到失败”和“当前代码状态有回归通过记录”分开。该功能只查询已有检测，不执行命令、不修改代码，也不自动关闭 Bug 或授予审查。

## 评估步骤

1. 校验运行存在；未关联 Bug 的运行返回不适用。读取该运行明确关联的检测，Bug 或工作区归属不一致、标识或摘要格式损坏、检测类型与状态不兼容或编码未知的记录忽略并报告数量，手动及历史未归属记录不参与。数据库行在判断前转换为 UUID 和检测枚举。
2. 对失败观察，只使用带代码状态摘要的记录。存在失败观察时展示曾观察到失败；只有未观察到失败的有效记录时展示未观察到失败；没有有效记录则证据不足。同一代码状态出现相互矛盾的观察时展示冲突。
3. 读取工作区当前版本摘要。只对与当前摘要相同、状态明确为通过或失败的本次回归记录做判断；通过和失败同时存在时展示冲突，没有可信记录或无法读取当前摘要时展示证据不足。
4. 返回支持结论的检测 ID。用户点击后得到查询时快照，代码或记录发生变化后应重新评估；读取工作区与数据库之间没有跨系统原子快照。

## 边界

失败观察不证明特定目标 Bug 已复现。当前代码有回归通过记录也不证明完整修复、覆盖率充分、人工审查通过或代码已合并；同一状态的结果可能有波动，冲突必须暴露。当前摘要依赖本地 Git 与文件状态；未跟踪文件或读取异常会使当前版本无法确认。只支持内置模拟 Bug 和固定 Python 测试，不是通用真实修复基准或自动评测数据集。
