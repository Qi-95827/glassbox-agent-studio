# 运行事件游标查询：首期详细设计

本地单用户版为工作台及后续观测提供断线补取能力。事件仍以 H2 中既有递增 `events.id` 为稳定游标，游标全局分配但只按指定运行过滤，不声称每个运行的编号连续。查询输入为运行 ID、排他起点 `after`（初始为 0）及上限 `limit`（1—200）；返回按 ID 升序排列的事件及 `nextCursor`，空页沿用输入游标。事件必须从数据库读取，历史事实不靠模型补写。

未知运行、负游标和越界数量直接拒绝；返回包含事件 ID、运行 ID、受控事件类型、消息和发生时间。查询沿用本地服务已有的访问边界，不等于认证或多租户隔离。分页无实时推送、事件保留期或分布式有序保证；现有状态更新与事件写入仍有部分非原子窗口，因此查询不能声称事件绝无缺失。验收覆盖分页不重不漏、不同运行隔离、空页、非法输入和未知运行。

工作台在运行详情使用 `includeEvents=false` 避免反复下载全部事件，并按单运行游标分页补取。切换运行时清空旧游标与事件，串行轮询避免同一次请求重叠；请求失败不推进游标，下一次可重新补取。旧接口默认仍返回全部事件以兼容历史调用方；页面内存仍会累计当前运行的事件，长期运行的虚拟列表与保留策略未实现。
