# 首期人工批准后本地提交设计

仅用户在工作台显式触发本地提交；Agent 不可调用此操作，当前不支持推送或合并。只允许项目创建的可信 Git worktree，提交当前已跟踪文件的全部差异；存在未跟踪文件时拒绝，已有暂存和未暂存修改均包含在审查范围。提交信息由用户填写，长度 1—200 字；Git 身份采用仓库现有配置，不自动伪造身份。

执行前要求存在绑定当前差异、HEAD 和目标分支的有效已批准审查；不存在、代码变动或基础分支变动时拒绝。持有本进程工作区写锁，记录 `STARTED` 动作后执行 `git add -u`，比较暂存后的二进制差异与审批前差异、HEAD 和目标分支；若状态变化则不继续提交。关闭 Git hooks 和交互提示，使用参数数组执行 Git。提交成功后读取实际 HEAD、记录 `CONFIRMED`，返回提交 ID；失败、超时或进程中断可能造成暂存或提交结果未知，标记 `UNKNOWN` 并提示用户核对 Git 状态，不能自动重试。进程重启时未完成动作转为 `UNKNOWN`。

Git 与 H2 不处于同一事务，数据库记录提交失败可能与仓库真实结果不一致；用户应以 Git 为准。本地锁不防外部进程并发修改，Git worktree 也不是安全沙箱，不支持恶意并发进程。已有审批通过后代码提交改变工作区状态，审批按现有规则失效。测试覆盖无审批拒绝、修改后审查失效、已审批变更提交、原仓库与目标分支未被修改、无自动推送合并、错误信息和未知动作保留；测试仅使用临时仓库。
