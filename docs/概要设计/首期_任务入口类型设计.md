# 首期任务入口类型设计

## 目标与边界

允许用户显式标识任务从通用目标、需求、概要设计、代码、测试或 Bug 出发。入口类型是用户提供的任务上下文，不是模型自动识别结果，也不代替目标、约束、验收条件或工具授权。首期仍使用已有固定分析／审查或分析／开发／审查流程，不表示已实现需求到设计的完整产物流、测试 Agent 或动态规划。

## 契约与执行

使用稳定枚举 GENERAL、REQUIREMENT、DESIGN、CODE、TEST、BUG；缺省与迁移历史任务均为 GENERAL，非法编码在创建前拒绝。数据库保存入口类型，恢复运行沿用原任务类型。服务端将入口的简短方法提示加入分析 Agent 输入，并在协调交接约束中带上类型，提醒后续角色区分已知信息和未验证事项；提示属于方法指导，不能扩大工具范围、替代实际测试或声明产物已完成。独立的模拟 Bug 入口在页面预设 BUG，但选择 BUG 本身不会自动关联模拟 Bug、运行测试或授予写入。

工作台任务表单提供入口选择，运行详情和 HTML 报告显示所选值及其非自动判定性质。任务完成仍按现有固定流程和审查边界决定，需求文档、设计文档或测试产物未实际生成时不得显示为已生成。

## 验收

验证新类型持久化与交接、非法类型拒绝、缺省及旧数据库兼容、恢复沿用入口、选择类型不授予工具权限，以及页面／报告显示；模拟模型只能验证控制流程，不能证明真实模型完成各类型业务。
