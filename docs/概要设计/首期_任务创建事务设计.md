# 任务创建事务设计

## 问题与目标

原创建流程依次写任务、运行／计划、创建事件，然后提交本进程执行队列；这些数据库写入不在同一事务中，中途失败可能留下孤立任务或缺少创建事件。将新任务、首个运行、固定计划和创建事件作为单个数据库事务提交。此事务不覆盖线程池或外部系统。

## 数据与流程

输入校验完成后构造不可变 TaskDefinition 与运行限额配置；在事务内写入任务、首运行、计划及创建事件。任何一步失败都回滚，任务不进入执行队列。数据库提交后才向现有本进程线程池提交执行，避免工作线程读到未提交数据。若队列明确拒绝提交，将已保存的运行标为 FAILED、未开始计划标为 SKIPPED，记录安全原因并返回运行 ID，供用户查看；不声称已经启动 Agent。若提交成功后进程宕机，运行可能尚未执行，重启仍由现有中断机制处理，不自动重复外部动作。

## 范围与验证

新增运行配置为明确类型，不改变现有 HTTP 契约；旧数据库结构不变。此实现不提供持久化消息队列、跨进程事务性派发、分布式租约或可靠事件投递。验收包括真实事务故障注入，确认运行写入失败时任务与事件也回滚；既有创建、计划、取消、限额及恢复回归保持正常。队列拒绝后的数据库更新本身若再失败，可能仍需重启中断处理，不能视为完全可靠投递。
