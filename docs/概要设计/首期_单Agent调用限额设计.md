# 单 Agent 调用限额设计

## 目标与范围

在已有运行总模型轮次、工具总次数和单工具限制之外，可选设置每个实际 Agent 实例的模型调用上限及工具调用上限。两类限制独立生效，最先触发的限制终止当前运行；默认不设置，保持旧任务行为。模型上限允许 1—20，工具上限允许 0—20（0 表示禁止新工具调用），保存在运行配置中。

## 执行与恢复

每次启动模型或工具前，在现有总预算检查后，根据该 Agent 实例已持久化的已启动调用计数进行检查；成功、失败、取消、未知及重试只要已经启动都计入。达到上限时不启动额外调用，并以 LIMITED 记录原因。各 Agent 的上限相互独立，审查 Agent 的消耗不会继承分析 Agent 的实例计数。恢复新运行时配置不变，新实例的实例计数从零开始；跨恢复的总轮次、工具次数、单工具及已报告 Token 等现有累计限制继续继承，不能借恢复绕过总预算。

该实现面向当前单进程、单 Agent 执行流程，按数据库已启动记录检查，不宣称支持多个进程并发预留、每个角色独立配置、单次请求的 Token／费用硬限制或准确撤销在途调用。任务入口、Skill 或模型不能修改限额。

## 展示与验证

任务表单、运行详情和报告显示可选限制，空值表示未设置而非零。验证每个 Agent 独立额度、工具额度 0、模型额度到达前拒绝、非法输入、旧数据默认空、恢复保留配置和总额度不倒退；模拟模型用于验证控制，不代表真实模型质量。
