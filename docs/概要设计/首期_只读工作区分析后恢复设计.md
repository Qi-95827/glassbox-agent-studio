# 只读工作区分析后恢复设计

## 场景

允许无 Bug、无写入授权、未启用项目背景记忆的工作区任务，在分析已经完成后建立审查前检查点。恢复时只复用已完成分析并重新执行审查 Agent，不重新读取文件、不重复分析工具调用；旧运行保留，新运行继承累计预算。其他工作区和 Bug 场景继续拒绝恢复。

## 检查点形成

1. 分析前尝试取得工作区验证摘要；未跟踪文件、Git 状态不可读等导致摘要不可确认时，正常任务继续，但不产生此类可恢复检查点。
2. 分析成功完成、结果和交接记录已持久化后，再次计算摘要。只有分析前后摘要一致才保存 v6 检查点；记录工作区 ID、摘要和经过校验的分析来源引用，并与检查点事件同事务保存及计算完整性摘要。
3. 快照的有效性仅表示结构、关联与摘要校验通过，不表示当前工作区必然仍匹配，也不保存 AgentScope 的运行中会话。

## 恢复

1. 用户选择中断运行的检查点；校验检查点属于运行、v6 结构和分析来源有效，任务仍符合只读、无 Bug、未启用项目记忆条件。
2. 重新计算工作区摘要并与检查点比较，无法计算或不匹配则拒绝恢复；在后台真正开始执行前再次核对，避免排队期间状态改变。
3. 创建关联的新运行，复用已验证来源分析，计划节点标为复用；重新执行审查，继续继承父链已消耗预算。恢复运行可在相同条件下保存新的 v6 检查点，支持连续恢复。

## 安全边界

摘要由现有 Git HEAD、目标分支、已跟踪差异与状态计算；未跟踪文件不能完整绑定时拒绝生成或恢复。分析期间先后摘要一致不能证明中间从未改变，检查与后续执行之间也存在竞态，因此这不是可信沙箱、外部事务或 Flink 式一致性。恢复申请入队后，如果执行前复查发现状态变化，新运行会以失败结束；只有事务验证未启动 Agent、模型和工具，才允许从同一个父运行再次申请。DeepSeek 的审查调用可能再次产生费用。该功能不回滚或覆盖用户文件，也不支持写入任务、Bug、会话中途恢复、周期快照或分布式租约。
