# 首期复用 Prometheus 和 Grafana 的监控设计

## 目标与边界

在用户已有的 Prometheus 和 Grafana 中新增独立的工作台抓取任务和只读监控看板。复用现有 Prometheus 数据源和 Grafana 的 3000 端口，不修改现有任务、看板、账号或密码。当前看板位于既有 Grafana 组织及文件提供器中，不提供账号隔离、租户隔离或完整后台操作。

## 采集与展示

工作台默认只监听本机 8088 端口；Docker Desktop 中的 Prometheus 通过 `host.docker.internal:8088/actuator/prometheus` 采集。网络可达性依赖当前 Docker Desktop 配置。工作台关闭时目标显示不可达；这不代表运行次数或 Token 为零。工作台若更改端口，抓取目标须同步调整。项目内保存独立的抓取配置片段和看板原件，现有监控配置中的接入项使用明显标记，便于定位。

运行、Agent／模型／工具调用、模型 Token、已知耗时以及评测状态使用当前工作台指标。指标为**保留数据库记录的汇总快照**，不是单调递增计数器：清理数据或切换数据库后数值可能减少，不能对其套用 `rate`／`increase` 推算吞吐。已知 Token 不包含未知调用；未知调用数必须单独展示，不把未知用量当作零。已知耗时为累加值而非延迟分布，不能计算 P95。评测数字反映已保存案例状态，不代表整体模型质量。

指标不包含租户、任务、运行 ID、提示词或代码等高基数／敏感标签。现有指标是全实例聚合，不支持按用户隔离或逐个 Agent 的完整链路分析。看板不提供告警、鉴权、资源配额、分布式追踪或费用结算；这些能力仍需另行设计与实现。共享监控应只用于可信的本地开发环境。

## 验证

检查 Prometheus 配置语法；在隔离的内存数据库服务上验证目标可抓取及各查询可执行；验证独立看板进入现有 Grafana。测试完成后停止隔离服务，实际工作台未启动时目标变为不可达是正常情况。不得为验证读取或输出用户凭据。
