# 多 Agent 任务图：节点依赖持久化

## 目标与范围

将现有运行计划的前置关系从单个角色字段扩展为独立的节点依赖记录，使一个节点能够表达多个前置节点。节点使用已有的稳定 UUID，状态仍以 `plan_nodes` 为唯一来源；协调器、审查、取消、恢复及工具权限沿用现有实现。用户工作台和报告展示实际保存的依赖关系。

当前计划创建和执行仍使用固定的分析、开发、审查角色顺序。虽然存储和就绪判断可以表示多前置关系，但本期不开放任意任务图、同角色重复节点、模型生成计划、并行调度或跨进程恢复。原表的同运行角色唯一约束仍然存在。

## 数据与兼容

- 新增 `plan_node_dependencies`，以运行 ID、节点 UUID、前置节点 UUID 为联合主键；同一运行内的依赖不得指向自身，写入时校验两端归属并受外键约束。
- 保留原有 `prerequisite_role` 供旧接口兼容；启动初始化时根据历史计划原有字段回填依赖，重复初始化不重复增加关系，不为旧运行凭空创建节点。若旧字段指向的前置节点不存在，不能将该节点视为无依赖；查询或执行时必须拒绝并提示状态不一致。
- 新计划在同一业务事务内写入全部节点及依赖。读取计划时一起加载依赖 UUID，校验两端属于相同运行，构建不可变结果；未知节点、跨运行或旧字段与关系矛盾时拒绝使用。接口保留 `prerequisite`，增加 `dependencyIds`。
- 保留原先由角色引用的单依赖字段，不作为完整任务图的唯一依据。现阶段新节点与依赖仅由服务端固定计划生成，不接受模型或用户自行修改。

## 启动、一致性和恢复

启动前按持久化节点 UUID 重建依赖图，检查环和引用，只有全部前置节点 `COMPLETED` 或 `REUSED` 时才可启动。随后用同一数据库事务中的条件更新再次检查全部实际前置状态，并只从 `PENDING` 更新到 `RUNNING`；判断和更新期间有并发变化时以后者为准。上游失败、跳过或未知都不能满足依赖。

旧检查点恢复仍只支持原有安全边界，新运行创建自己的计划和依赖；复用分析时保留来源且不伪造调用。新增关系不提供模型会话中途恢复、外部副作用回滚或跨实例租约。

## 验收

验证历史单依赖迁移与重复启动、非法或缺失依赖拒绝、多个前置节点均满足才启动、重复和并发启动只允许一次、已有固定多 Agent 交接及恢复流程、工作台与报告显示。测试使用隔离 H2 与模拟模型，不调用真实模型或新增业务工具。
