# 多 Agent 安全边界检查点：首期详细设计

本期在现有 Agent 启动前检查点之外，增加分析 Agent 已完成、审查尚未开始时的检查点，仅适用于未关联工作区且未关联 Bug 的任务。它保存对已完成分析调用的引用及其结果摘要，保留原运行的工具事件作为证据；不保存或恢复 AgentScope 内部会话，也不回滚 Git 或外部系统。真实模型使用该检查点恢复时可能再次产生审查模型费用。

原运行保留分析调用和结果；恢复创建关联的新运行，校验检查点摘要、事件、所属运行、分析调用已完成及结果摘要，再引用原运行的分析结果与证据，仅新建审查 Agent。新计划的分析节点标记 `REUSED` 并记录来源 Agent ID，不能显示成新运行内实际调用；审查依赖允许引用有效的已完成来源。恢复继续继承原运行累计轮次、工具次数、单工具限额和耗时，无法使消耗倒退。

检查点记录使用新版本 `4` 与 `BEFORE_REVIEW`，继续读取旧版 `3` 的启动前检查点；旧 `AFTER_TOOL` 及不兼容版本不恢复。校验不通过、引用缺失或摘要变化时拒绝；包含工作区／Bug 的任务本期不生成该类型检查点，避免把未对账的外部副作用当作已恢复。保存检查点与其事件使用同一数据库事务，但分析完成、运行状态和检查点之间仍不是全局原子事务；崩溃发生在保存前时只能使用已有较早检查点。已有启动前恢复存在重复工具／模型调用风险。

验收：模拟任务出现新检查点并能在模拟中断后恢复审查，恢复运行不再次执行分析和工具、能追溯来源、预算不倒退；损坏摘要、缺失来源、跨运行引用拒绝；旧检查点仍兼容。尚无周期快照、分布式租约、所有 Agent 内部会话状态或外部动作对账。
