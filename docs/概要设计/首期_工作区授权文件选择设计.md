# 首期工作区授权文件选择设计

## 目标与范围

创建任务时，用户可以查询所选工作区的 Git 已跟踪文件，并将自己选择的路径添加到授权列表，减少手工输入；原有手工输入继续可用。列表查询只是面向本机用户的选择辅助，不为 Agent 授权文件，选择条目也不自动提交任务或开启写权限。

## 契约与边界

- 提供工作区文件候选查询：输入已创建工作区的 ID 以及可选的 0—100 字单行路径关键字，按大小写不敏感的字面子串筛选，返回不超过 100 个工作区相对路径和是否截断。使用 Git 已跟踪索引和 NUL 分隔符处理中文与空格，不执行路径通配、命令字符串或代码内容搜索；仅包含当前仍存在且不超过 1 MB 的普通文件，剔除 Git 元数据、目录和符号链接。路径列表可能包含二进制或非 UTF-8 文件，任务创建时仍按原规则校验；工作区可能随时变化，查询结果不是访问授权或快照。
- 查询不扫描未跟踪文件。保留原有手动输入能力，未跟踪文件的读取和审查限制维持原规则。用户明确选择路径后加入文本授权列表，去重并遵守最多 20 个；用户切换工作区时清空旧选择，避免错误复用原路径。
- Git 索引输出沿用工作区 Git 命令 1 MB 上限；超出或 Git 执行失败时显示错误并保留手工输入，不返回静默截断的候选列表。当前工作台为可信本机单用户环境，没有租户鉴权；候选路径不交给模型，只有用户创建任务后所选授权路径才进入执行链路。
- 查询与任务创建之间可能有变化；创建和每次工具操作均重复执行原有路径、文件状态和授权检查。Git 工作区不构成针对恶意本机进程的沙箱。

## 交互与验收

选择工作区后可展开候选查询，输入关键字并点击查询；逐项选择后加入已有授权路径，展示数量和必要的截断、失败与不可用提示。先后切换工作区或关闭页面时丢弃过期响应，不能把前一工作区的候选添加到新工作区。

通过隔离 Git 仓库验证中文和空格、大小写匹配、超过 100 条截断、非跟踪文件不出现、删除文件不出现、路径越界及非法关键词；验证工作区切换、手动输入兼容、20 条上限和异常提示，不改变原项目文件。
