# 工具写入异常边界设计

## 问题

通用工具包装器过去把 action 中任何 IllegalArgumentException 都当成无副作用的参数拒绝，并提示修正后可重试。对未来的写工具而言，异常可能发生在副作用之后，异常类型本身不足以证明没有写入；如果鼓励重试可能重复操作。

## 设计

将纯输入验证与工具动作分开：登记工具调用、执行无副作用的参数验证，验证明确失败才产生 INVALID_ARGUMENT 的可纠正拒绝；验证阶段计入工具预算。动作执行时，已被实现约束为写入前冲突的 WorkspaceVersionConflict 仍可返回 STALE_VERSION；只读动作的参数异常可返回受控拒绝。写动作抛出的其他 IllegalArgumentException 或未知异常，不当作无副作用拒绝，也不自动重试；终止当前执行并沿用通用失败／人工核对路径。工具 effect 由服务端可信注册配置，不由模型选择；错误文本不回传原始异常。

当前单文件写工具在动作前检查摘要格式和内容大小，服务端文件方法仍保留重复校验。上述规则不提供分布式幂等、外部事务或写入结果自动对账；即使异常发生在写入之后，系统也只能报告未确认，必须查看工作区状态。验证函数和具体工具需要保持无副作用契约；扩展外部写工具时还须设计自己的幂等和对账。

## 验收

验证纯输入拒绝不调用动作、错误不泄露、预算记录不消失；模拟写动作先产生可观察副作用再抛 IllegalArgumentException，确认不会生成可重试的拒绝；保留明确的版本冲突和只读参数拒绝，以及成功路径。
