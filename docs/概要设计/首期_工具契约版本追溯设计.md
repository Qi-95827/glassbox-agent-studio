# 工具契约版本追溯设计

## 目标和边界

每个 Agent 装配工具时记录服务端选择的契约版本。工具调用也记录版本，页面和报告可分别查看装配与实际调用；工具装配不是调用成功的证明，也不扩大用户授权。版本由服务端指定，模型不能自行选择。

## 处理流程

1. 根据角色和用户权限选择工具。单文件读取、写入与模拟检查使用版本 1；多文件读取和写入使用版本 2。
2. 装配记录及空集合标记在同一事务保存。无法保存时不启动 Agent；在调用前检查工具类型及版本与本次成功装配的快照一致。
3. 经预算和次数控制允许启动后，调用记录写入契约版本；成功、拒绝或失败都保留该版本。统一结果的版本与工具实现指定版本一致。
4. 页面、API 和 HTML 报告显示每项装配版本及调用版本。缺少装配标记、已装配空集合、历史版本未知和明确版本分别表达。

## 兼容与限制

旧数据增量增加可空版本字段；历史记录没有证据时显示未知，不假定为版本 1。现有工具集合字段保留，增加版本明细。此设计只追溯和校验当前服务端装配，不提供工具注册中心、版本发布审批、动态撤权、跨版本兼容声明或自动升级。预算计数仍按工具类型聚合。

装配计划、实际注册与工具结果复用同一组内置契约版本定义；启动后仍核验实际调用与装配记录一致。协议结构发生变化时仍需开发者维护版本，当前没有自动兼容性分析或发布治理。
