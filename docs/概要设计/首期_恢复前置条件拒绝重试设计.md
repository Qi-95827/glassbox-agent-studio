# 恢复前置条件拒绝后的重试设计

## 场景

只读工作区恢复申请进入队列后，工作区可能在执行前发生变化。后台复查必须拒绝该次恢复；如果可以证明这次尝试尚未启动 Agent、模型和工具，用户修正状态后可从原检查点重新申请。

## 处理规则

1. 后台恢复在复用分析或启动 Agent 之前复查工作区。确认不匹配时，不启动模型和工具。
2. 单个数据库事务检查恢复运行有父运行、状态为运行中、派发状态尚未确认，且没有任何 Agent、模型、工具调用及非待执行计划节点；满足时记录 FAILED、明确的前置条件拒绝分类，结算计划和事件。
3. 单进程恢复申请在同步入口内依据数据库检查防重；防重查询只排除明确未启动的线程池拒绝和前置条件拒绝。状态未知、已启动或校验失败时仍保守阻止重复。
4. 页面依据相同的明确拒绝状态允许重新申请；服务端每次申请仍重新检查检查点、父运行和工作区摘要。

## 边界

重新申请继承原运行预算；被前置条件拒绝的尝试没有模型或工具调用，但其少量调度和检查时间不并入后续尝试。若事务提交前进程崩溃，状态仍可能未知，不自动认定安全重试；不提供跨进程租约、外部副作用回滚或分布式恰好一次。
