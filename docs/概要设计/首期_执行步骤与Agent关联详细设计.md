# 首期详细设计：执行步骤与 Agent 关联

## 目标与范围

在现有 AgentScope 顺序协作链路上，为每次新运行保存可查询的执行步骤，明确展示分析、审查各由哪个 Agent 实例执行、执行状态及其依赖。它为可视化与后续评测提供数据基础；本期不实现模型动态拆解任务、通用 DAG 调度、并行执行或新的 Checkpoint 恢复能力。Bug 复现和回归暂时仍由既有事件及检测记录表达，不伪称包含在本计划中。

## 对象与状态

每次运行创建两个固定步骤，顺序为 `ANALYST` → `REVIEWER`，后者依赖前者完成。步骤包含运行 ID、受控角色、顺序、前置角色、状态、Agent 调用 ID、开始／结束时间；ID 使用 UUID，时间为 UTC。步骤不复制模型回答和工具结果，按 Agent 调用 ID 关联现有记录。状态采用枚举：`PENDING`、`RUNNING`、`COMPLETED`、`FAILED`、`CANCELLED`、`LIMITED`、`INTERRUPTED`、`SKIPPED`。其中 `SKIPPED` 表示本次运行结束但步骤未开始，不表示步骤成功；中断仅表示结果未知，不能认定外部操作已回退。

## 生命周期和一致性

1. 新建或恢复产生新运行时，在同一数据库事务内创建运行和固定步骤；旧运行没有步骤记录，查询返回空列表，不倒推历史事实。
2. 实际启动 Agent 时，在同一事务中校验步骤处于等待状态、依赖已完成，绑定调用 ID 并写入调用记录。不同 Agent 的上下文和已有权限边界保持不变。
3. Agent 结束时，在同一事务更新调用和关联步骤；不能重复结束或者越过依赖。模型及工具结果仍使用现有记录，不由步骤自行推断。
4. 运行终止时，未开始的步骤标为 `SKIPPED`；异常残留的运行中步骤标为 `INTERRUPTED`，不覆盖已完成或已结束结果。启动时对中断运行做同样处理。暂停不会把步骤写成终态。
5. 查询 API 在原有运行详情中新增 `planNodes` 数组，使用稳定枚举编码，保留原有字段。前端仅展示实际保存的步骤和状态，历史数据明确提示无记录。

数据库目前为单机 H2，事务保证本地步骤与调用的原子更新；并发写入、跨实例租约、进程宕机时外部副作用对账和完整事件一致性不在本期范围。检查点后续已扩展安全边界，详见 [多 Agent 安全边界检查点设计](首期_多Agent安全边界检查点设计.md)；恢复的新运行重新创建步骤并保留原运行历史。

## 安全、异常与验收

步骤记录不保存密钥、完整提示词或代码；任务目标、模型输出等仍受现有记录机制限制。角色和状态使用枚举，非法状态转换直接失败；步骤是观测事实，不授予工具权限。验收覆盖正常协作、预算终止、排队取消、运行中取消、中断及历史记录兼容；通过受控模拟模型验证，不需要读取真实 API Key。一次运行的终态、Agent 调用与步骤状态必须一致，未执行的步骤不能显示为已完成。
