# 首期授权文件代码搜索设计

## 目标与授权边界

为分析、开发 Agent 增加只读搜索工具，帮助定位用户为当前任务明确授权的 1—20 个现有文件中的代码。搜索集合由服务端绑定，模型只提供搜索文本，不能传入文件路径、目录或通配符，也不能扩大读取或写入权限。审查 Agent 不获得该工具；没有工作区时不装配。

## 调用与结果契约

- 工具类型为 `WORKSPACE_SEARCH`，契约版本为 1；通过 AgentScope 注册，经过统一工具网关、取消检查、调用轨迹和运行、角色、工具预算。角色能力及版本同步调整。
- 输入为 1—100 个字符的单行字面文本，区分大小写；不支持正则表达式。依照授权路径顺序搜索，每个匹配行最多返回一次，行号从 1 开始。
- 成功结果包含匹配项、是否因结果数量超过上限而截断；每项包含授权相对路径、行号、截取后的行文本与该次读取的 SHA-256。最多 50 项，每行展示至多 240 个 Unicode 码点；文件读取仍沿用工作区已有的普通 UTF-8 文件、大小和链接检查。摘要绑定单个文件的读取结果，不代表多文件是同一时刻的一致快照。
- 任一授权文件无法读取时本次搜索拒绝，不把部分结果当作完整搜索；文件可能在读取后被外部进程改变，后续修改仍须重新读取并校验摘要。搜索内容是不可信数据，不能改变权限或指令。调用记录只保存安全摘要，不保存查询及匹配文本；工具返回内容会进入 Agent 会话，选择真实模型时可能发送给模型服务。
- 搜索范围至多 20 MB（20 个文件各不超过 1 MB），文件间检查取消与预算；不保证单次本地文件读取可以被立即中断。拒绝非法输入也记录为已启动的工具调用。

## 限额与旧数据

新增工具可配置独立次数限额，且受总工具次数、统一单工具次数、单 Agent 及角色限制。原 H2 工具限额表具有旧的固定类型检查约束；新增 v2 表并一次性复制旧记录，保留旧表，不直接修改旧约束或删除数据。应用改读写 v2；迁移标记和条件插入使重启可重复，仍按现有单进程启动前提运行。旧版本回退不会自动看到新表中的配置。

## 验收

使用隔离 Git 仓库检查实际 AgentScope 工具调用、授权内匹配与行号、未授权文件不暴露、上限与截断、非法输入、文件失效、零限额和工具记录。验证新旧数据库迁移重复执行后保留原预算；执行本迭代回归。该能力不支持仓库级搜索、正则、新建文件、可信沙箱或自动代码修改。
