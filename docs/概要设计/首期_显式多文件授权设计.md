# 首期显式多文件授权设计

## 目标与范围

允许用户为一个工作区任务明确列出 1—20 个已存在的文本文件，分析 Agent 可以读取集合内的文件；只有用户另外启用写入时，开发 Agent 才能修改集合内文件。审查 Agent 仍不直接获得文件工具。默认只读，列表不是目录、通配符或整个仓库授权；不允许创建新文件、访问未列出的文件、Git 元数据、绝对路径、越界路径或符号链接。Git worktree 本身仍不是不可信代码沙箱。

## 契约与兼容

保留旧请求 `fileScope` 和数据库字段，新增 `fileScopes` 列表及独立 JSON 持久化列；新列表与旧字段不能同时指定。旧记录的新列为空数组时根据旧字段恢复单文件范围，旧任务和单文件工具调用协议保持兼容。新多文件任务保存完整规范化路径集合，旧字段仅保留首项供历史显示，实际授权以集合为准；列表内不允许重复、空值、绝对路径、盘符路径、越界和过长路径，创建任务时逐个通过现有工作区读取检查。

单文件继续注册不带路径参数的 v1 工具；多文件注册同名、显式接收相对路径的 v2 工具。多文件工具在每次动作前按规范化路径与服务端绑定集合做精确匹配，模型输出、提示词、Skill 与入口类型均无法扩大列表；写入仍需对应文件的最新 SHA-256，遵守预算与已存在的版本冲突／未知副作用规则。模型输入与交接中提供授权路径作为数据，以便选择目标，但最终权限由工具和工作区服务共同执行。

工具登记追溯目前只记录工具种类，不记录工具版本，返回给模型的 v2 工具结果有版本字段，但当前数据库中的工具调用摘要和报告尚未保存该版本；不把它说成完整工具版本治理。角色指导发生变化时递增相应角色版本。对恶意本机进程引起的文件替换竞争、Windows 所有重解析点、跨进程并发和外部副作用不做完整安全承诺。

## 交付与验收

工作台允许每行填写一个相对路径并显示授权数量，报告显示授权范围；路径不作为工具权限本身的唯一证明。验证旧单文件任务与旧库、两文件读取／写入、未授权路径拒绝、越界／链接和重复路径、每文件版本冲突、写权限关闭、AgentScope 工具调用、预算与现有 Bug 流程。临时 Git 仓库用于验证，不修改用户真实项目。当前仍不支持新建文件、目录动态授权、工具动态版本发布或自动推送合并。
