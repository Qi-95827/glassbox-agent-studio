# 模型流式调用记录与能力透传设计

## 问题与范围

AgentScope 的 Model 接口返回多个 ChatResponse 的 Flux。现有 DeepSeek 配置为非流式，但若将来使用流式模型，不能把第一个片段当成整个调用完成，否则可能错过最终用量，预算与耗时记录也会失真。本次修正公共适配层，不改变当前模型服务、密钥或已确认的工具权限。

## 过程与边界

每次订阅先执行预算检查并登记一次模型调用。逐片段透传给框架，只有流正常完成且至少产生一个响应时才登记一次完成、最新一次提供的用量和完成事件；未提供用量记为未知，不将多次用量相加。适配器假设提供方最后一次报告的用量是该次请求的累计值；若提供方的用量语义不同，需专门适配，不能据此保证正确。空流按失败处理。流出错或被取消时不伪造完成，由现有运行终态路径结束未完成的调用；网络结果可能未知。预算检查仍在用量返回后执行，不能保证预扣或费用硬上限，也不能撤回已经发送的响应。

包装器应透传 Model 的原生结构化输出、与工具共同使用该能力、上下文窗口大小等能力，防止不必要地屏蔽底层模型特性；具体代理或供应商仍应单独验证。验收覆盖多片段、最后用量、空流、异常、预算拒绝、能力透传与既有非流式模拟运行。
