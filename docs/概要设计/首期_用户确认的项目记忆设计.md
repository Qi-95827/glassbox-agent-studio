# 用户确认的项目记忆：首期详细设计

## 范围与边界

首期只支持本地单用户为已存在的工作区手工维护文本记忆，作为用户确认的项目背景；它不是用户身份认证、多租户隔离、向量检索或 Agent 自主写入。任务必须关联工作区并显式开启记忆，才可按该工作区读取；禁止模型自行授予或扩大授权。审查 Agent 仍只接收现有结构化交接。

## 数据与生命周期

记忆记录包含 UUID、工作区 ID、类别枚举（项目约定、项目背景、注意事项）、内容、来源 `USER_CONFIRMED`、状态（有效、已删除）、版本、创建和修改时间。单条内容 1—300 字；每个工作区最多 20 条有效记录。创建、修改、删除由本地用户发起，删除为软删除，更新及删除递增版本，保留独立历史记录供审计。查询默认只返回有效记录；删除后新任务不能再检索该内容，但已发送的上下文和历史不可撤回。

## 上下文装配

任务勾选记忆后，按当前工作区读取最新的最多 5 条有效记录，每条含类别、版本、内容；无记忆或未授权时不注入。系统规则和任务目标保持更高优先级，记忆作为 JSON 数据并标注为低可信背景，不能成为权限、审批、路径或工具使用规则。服务端工具权限仍由已有授权校验决定；提示词不能保证完全防御提示注入。记忆内容可能发送给任务选择的外部模型，用户在任务界面开启时必须看到说明。事件只记录采用条数，不记录记忆正文。

## 一致性与验证

数据库事务内完成记录和历史变更，更新、删除使用版本条件防止并发覆盖。检索每次回源 H2；本期不使用 Redis、向量索引或异步缓存，因此不存在缓存传播保证。进程内模型调用开始后删除记忆，不能撤回已读取或发出的内容。验收覆盖不同工作区隔离、未开启不读取、增删改版本冲突、数量与长度限制、缺失工作区、任务授权和 API 输入校验。历史任务默认未开启，恢复新运行遵循原任务授权并重新读取当前有效记忆，而不是声称恢复历史快照。
