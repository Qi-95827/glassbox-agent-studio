# 记忆装配引用追溯设计

## 目的和边界

当任务明确授权读取工作区记忆，分析 Agent 组装输入前，记录本次选中的记忆 ID、版本、类别和顺序，以便理解上下文来源。记录元数据，不重复保存正文。它是装配证据，不证明模型调用成功、模型理解或遵循，也不保证外部模型接收到数据。

## 过程与契约

在数据库事务中读取工作区前五条当前有效记忆，写入运行的装配标记和每条引用；标记与引用全部成功才返回同一批内容用于后续输入。记录加载时间、工作区、数量，引用记录 ID、版本、类别和顺序。零条也写入标记，与旧运行／没有发生装配区分。运行结束后更新或删除记忆不改变已记录的引用；恢复新运行按原授权重新选择并形成新记录。一次运行最多登记一次，失败时不发起对应模型调用。查询先检查运行存在，再返回有无记录、时间和引用；静态运行报告同步展示引用及其证据边界，缺失标记只能说明未记录，不能推断历史运行没有使用记忆。

## 安全与限制

不在引用、事件和看板中记录正文，原有记忆历史仍保留用户数据；不等于自动脱敏或租户隔离。记录后、模型调用前可能发生宕机或记忆被删除，因此不能宣称引用必定已发送，也无法撤回已发送内容；现有单机事务无法提供跨进程撤权传播。Agent 输入仍按低可信数据处理，不能授予工具权限。验收覆盖非空、空记忆、未授权、引用版本稳定、API 运行不存在、跨工作区以及事务失败不写入部分引用。
