# 首期评测批次对照设计

## 目标与范围

允许用户选择基线和候选批次，逐案例对照已保存的种子评测状态，定位从通过变为失败或相反的案例，并能跳转对应运行。此功能只比较事实状态，不运行模型，不修改历史批次，也不是对真实代码修复质量的证明。

## 判定规则

先读取两个真实批次和各自案例，按案例编码匹配，对并集排序，不按列表位置配对。同一套件编码且两侧案例均为 PASSED 或 FAILED 时，分别标识保持通过、保持失败、通过变失败、失败变通过；缺失、待运行、取消、跳过或中断都为无法判断。套件编码不同则全部无法判断，仍显示双方状态。禁止同一批次与自身比较。批次整体状态与逐案例状态分开展示，即使批次未完成也不把未知当失败或通过。

套件编码相同只是必要条件：目前未完整记录模型、代码、工具、环境或裁判配置快照，不能保证实验条件一致，也不能把差异归因于某次改动；界面必须说明这一限制。旧案例编码或当前程序无法识别的情况仍受现有种子集读取限制。

## 接口与验证

`GET /api/evaluations/compare?baseline=...&candidate=...` 返回两个批次、是否同一套件和结构化案例对照，包含两侧状态、运行 ID 和对照结论；找不到批次返回 404。所有结论只代表当下数据库快照，运行中批次可能继续变化。验证通过／失败转换、未完成及缺失、不同套件、重复批次和不存在批次，并核查原有评测运行、取消与历史显示保持正常。
