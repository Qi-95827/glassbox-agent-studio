# 固定评测逐项断言设计

## 目标

固定模拟评测除案例总状态外，保存每一条断言的稳定编码、通过状态和基于运行记录的简要说明，方便定位失败。明细不包含模型输出或源码，也不以模型自述代替验证。

## 流程与一致性

案例运行终止后读取其运行状态、计划节点和工具记录，逐条检查预期状态及对应种子的计划与工具条件；全部通过才将案例标记为通过。保存前按案例校验必需的断言编码集合，不允许缺项、重复或额外断言；断言明细和最终状态在同一事务中提交，任一保存失败均回滚，不能留下“通过但明细部分缺失”。取消、中断和旧批次没有断言明细时，明确显示未记录，不推测通过。

## 边界

维持原固定种子的判断语义和快照版本；明细是对既有断言的展开，不表示已支持用户管理数据集、真实模型评测、完整代码环境快照或统计置信度。历史数据不补造检查结果。
