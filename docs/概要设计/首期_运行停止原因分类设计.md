# 运行停止原因分类设计

## 目的

运行状态只能表达“超限”“失败”等大类。为了在页面和后续评测中区分实际触发的预算保护，运行控制在触发处直接生成枚举原因，不靠解析中文提示或模型推断。

## 范围

- 区分用户取消、进程中断、时间上限、模型总轮次及单 Agent 上限、已报告 Token 上限与用量未知、工具总次数及单 Agent 上限、单工具上限、连续重复调用上限。
- 已知工具写入结果不确定与其他未分类失败分开；未分类不自动推断为网络、模型或具体工具问题。
- 终态、原因编码和资源计数在同一数据库事务中记录；运行页面展示中文含义，HTML 报告保留编码和原始说明。编码与状态不匹配时拒绝保存。
- 历史运行和没有经过该控制路径的队列拒绝、进程启动时中断等记录可能缺少分类，展示未记录，不依据文本猜测。

## 限制

这是单次运行的触发原因，不是完整的故障根因或可重试判断，也不实现成本硬上限。调用可能在触发阈值前产生部分外部影响；未知写入结果仍需要人工对账。本机后台和 Prometheus 按固定原因枚举聚合当前保留的终态记录，未记录与编码／状态不一致单列；Grafana 展示同一快照口径。它不是事件计数器、速率或租户级统计，也没有告警。
