# 运行控制模块拆分设计

## 目标

将当前编排服务内部的运行计数、限额检查、暂停等待及单次模型／工具调用状态抽入 `control` 功能目录，让编排层负责角色与交接，运行控制模块负责单次运行的执行约束。此次为结构重构，不新增动态编排、并发调度、跨进程恢复或安全保证。

## 职责与状态

`RunControl` 为单次运行保存继承后的计数与时间、当前在途模型／工具引用以及限额；它依赖持久化边界和由编排服务管理的本进程暂停／取消信号。公开方法只供编排及 Agent 适配器调用；检查前后状态变化与原实现一致。`StopExecution` 携带受控终态和安全提示，调用方继续区分取消、超限和中断。通过只读方法提供计数，不暴露可写内部字段；模型与工具启动分别经统一入口先检查预算再登记，避免调用方遗漏检查。

暂停信号、服务线程池和恢复关系仍由编排服务管理；当前检查和调用登记未改成跨进程原子预留，原有并发与未知副作用限制继续适用。验收运行完整自动回归，特别关注取消、暂停、模型／工具预算、检查点恢复、异常终态和单 Agent 限额。
