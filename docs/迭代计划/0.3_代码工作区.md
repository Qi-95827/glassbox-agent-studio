# 0.3：代码工作区与 Git 基础

## 目标

让个人用户可授权接入真实仓库，并在明确范围内安全查看和修改代码，看到实际差异。

## 计划功能

- 仓库接入与环境自检：基础版本、目标分支、权限、工作区已有改动和必要工具。
- 按任务创建或关联隔离分支／工作区；明确允许读取、修改与排除范围，避免覆盖用户未提交内容。
- 提供受控代码读取、搜索和文件编辑工具；支持只读模式、授权校验和可审计的调用记录。
- 显示变更文件、具体差异及工作区状态；明确哪些修改尚未提交、已提交或已推送。
- 用户决定是否提交／推送／合并；变化、冲突和权限失效要阻止不再适用的操作并提示。
- 任务结束后查看保留资源和清理选项，清理前提示未提交文件及恢复影响。

## 依赖与边界

依赖 0.2 的工具与角色能力。真实文件读写开放前，必须具备路径授权、基本隔离、用户确认、审计和失败处理；Git 分支本身不是安全沙箱。此期不默认访问生产系统或自动合并。

## 验收

在测试仓库完成授权接入、独立工作区、受限修改和差异展示；验证只读、路径越界、原有未提交内容、分支变化及用户拒绝等场景。
