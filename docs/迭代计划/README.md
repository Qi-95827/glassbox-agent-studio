## 1. 产品范围与原则

产品优先服务个人开发者：用户拥有并控制自己的任务，团队通过各自 Git 分支及已有审查流程协作；多人共同控制同一任务不属于第一版目标。系统保留多租户和平台后台方向，但个人 1.0 不以共享部署为前提。用户工作台展示任务与 Agent 过程，平台后台负责运营、配置、评测与健康管理；两者是否是独立应用后续决定。

每个迭代必须产出可以检查的结果，而不是只有占位接口。0.1 使用模拟模型和模拟工具证明框架贯通；真实工具、Git 和外部写入启用时再实现相应的授权、隔离、审计、取消及恢复保护。各版本在前一版本基础上累积，不可用能力须明确标记。版本顺序是建议，不是必须各自独立发布或按日期交付。

## 4. 进入与完成每期

开始迭代前检查前置版本是否满足当前功能依赖，必要时调整范围；为该期补充更细的需求、交互、契约、异常和测试。完成时记录实际实现、验收结果、已知限制和未完成项，更新文档及版本记录。涉及真实代码、命令和外部写入的能力，只有对应安全措施可用并验证后才能对用户开放。

## 5. 阅读方式

每个版本文档都包含目标、计划功能、依赖／边界、验收场景和后续项；这些是当前预期，可随评测和实际开发调整。0.1–0.9 是内部渐进版本，不代表每一期都会对外公开发布；1.1+ 为候选方向，不承诺时间和顺序。
