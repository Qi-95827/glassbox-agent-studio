> **文档定位**：本文档可直接作为 **Prompt（研发指令）** 投喂给 AI Coding Agent 执行开发。  
> **目标**：将 **Glass-Box Agent Studio** 升级为真正的**中英双语（`zh-CN` / `en-US`）开源多 Agent 工作台与教学平台**，覆盖「前端 UI → 后端报错/校验/诊断 → 大模型 Prompt/Skill/交接提取」三层全链路国际化。

## 整体三层国际化架构设计

```text
[前端 TopBar: 中文 / EN 切换]
       │  持久化至 localStorage('agent_studio_locale')
       ├─► 第 1 层：前端 I18nProvider (zh-CN.json / en-US.json)
       │            渲染所有 UI、图表、教学剧本、「怎么算 PASS」规则字典
       │
       └─► HTTP Header: Accept-Language: zh-CN | en-US (由 src/api/client.js 统一注入)
                │
                ├─► 第 3 层：后端 Spring MessageSource + 结构化 messageKey/params
                │            返回对应语言的报错、安检门/交接校验、5 步故障诊断线索
                │
                └─► 第 2 层：tasks.locale 冻结任务语言
                             PromptResourceLoader.load(locale, path) 加载 prompts/en/ 或 prompts/
                             + StructuredHandoffExtractor 双语结构化提取
```

## 阶段 1：前端全站中英双语（轻量零依赖 i18n 体系）

### 1.1 轻量 i18n 基础设施（无需新增第三方 npm 依赖）
在 `frontend/user-workbench/src/i18n/` 下新建：
- `index.js` / `I18nProvider.jsx`：
  - 支持 `zh-CN` 与 `en-US`（默认读取 `localStorage.getItem('agent_studio_locale')`，未设置时按 `navigator.language` 推断，默认回退 `zh-CN`）。
  - 导出 `I18nProvider`、`useI18n()`（返回 `{ locale, setLocale, toggleLocale, t, isEnglish }`）以及模块级 `getCurrentLocale()`（供 `src/api/client.js` 同步读取）。
  - `t(key, params)` 支持模板插值（如 `t('monitoring.runCount', { count: 12 })` → `"12 runs"` / `"12 次运行"`）；若英文缺少某 key，自动回退到中文或 key 本身，不抛异常。
  - 切换语言时同步更新 `document.documentElement.lang` 与 `document.title`，并通知 React Query 刷新依赖语言的只读查询（或按 `locale` 作为 queryKey 的一部分）。
- `locales/zh-CN.json` 与 `locales/en-US.json`：
  - 按模块命名空间清晰组织：`common.*`、`nav.*`、`auth.*`、`home.*`、`playbooks.*`、`run.*`、`glassbox.*`、`handoff.*`、`gateway.*`、`monitoring.*`、`diagnostics.*`、`settings.*`、`byok.*`、`workspace.*`、`agents.*`、`docs.*`。

### 1.2 全局切换入口与 HTTP Header 联动
- **`frontend/user-workbench/src/layout/TopBar.jsx`**：在右上角账号区域左侧新增简洁的语言切换按钮（如 `EN` / `中文`，带 `TranslateRounded` 或 `LanguageRounded` 图标 + Tooltip），点击即可实时切换全站语言，无需刷新页面。
- **`frontend/user-workbench/src/api/client.js`**：在统一 `send()` 请求函数中自动附带 `Accept-Language: getCurrentLocale()` 请求头。
- **测试兼容**：确保 `I18nProvider` 包裹 `App.jsx` 根节点，且在未包裹 `I18nProvider` 的独立组件单元测试中，`useI18n()` 默认优雅回退到 `zh-CN`（保证现有 44 个前端单测零破坏！）。

### 1.3 前端全站文案双语覆盖范围

## 阶段 2：大模型 Prompt、Skill、Tool 契约与交接提取双语化

### 2.1 任务语言持久化（Flyway `V6__task_locale.sql`）
- 新增迁移脚本 `backend/src/main/resources/db/migration/V6__task_locale.sql`：
  ```sql
  -- 记录任务创建时的语言偏好（zh-CN / en-US），驱动 Prompt 语言选择与输出语言约束。
  ALTER TABLE tasks ADD COLUMN IF NOT EXISTS locale VARCHAR(16) DEFAULT 'zh-CN' NOT NULL;
  ```
- 同步更新 `TaskEntity`、`TaskDefinition`、`TaskData`、`TaskRepository`、`CreateTaskRequest`、`PlanCandidateInput`、`TaskIdeaController`、`RunCreationService` 等链路，透传 `locale`（若请求体未显式传，则从 HTTP 请求头 `Accept-Language` 规范化提取 `en-US` 或 `zh-CN`）。
- 同步更新 `FlywayMigrationCompatibilityTest` 中的目标版本断言至 `"6"`。

### 2.2 外置 Prompt 资源目录双语化（`PromptResourceLoader`）
- **保留原有 `backend/src/main/resources/prompts/` 下的 9 个中文文件完全不变**（确保 `PromptResourceLoader.load(relativePath)` 与 `SkillRegistryTest` 100% 兼容）。
- 新增英文镜像目录 `backend/src/main/resources/prompts/en/`，提供高质量、工程级英文版 Prompt 与工具契约：
  - `prompts/en/agents/analyst.md`
  - `prompts/en/agents/coder.md`
  - `prompts/en/agents/reviewer.md`
  - `prompts/en/skills/analyze-evidence.md`
  - `prompts/en/skills/authorized-edit.md`
  - `prompts/en/skills/review-evidence.md`
  - `prompts/en/planning/plan-candidate.md`
  - `prompts/en/planning/task-idea.md`
  - `prompts/en/tools/tool-descriptions.json`
- 扩展 `PromptResourceLoader.java`：
  - 新增 `public static String normalizeLocale(String locale)`（识别 `en*` → `"en-US"`，其余 → `"zh-CN"`）；
  - 新增 `public static String load(String locale, String relativePath)`：当为 `"en-US"` 时优先加载 `prompts/en/<relativePath>`，若资源不存在则优雅回退 `prompts/<relativePath>`；
  - 新增 `public static ToolCopy tool(String locale, String key)`：支持按语言加载 `prompts/en/tools/tool-descriptions.json`。
- 在 `AgentRoleRegistry`、`SkillRegistry`、`PlanCandidateGenerationService`、`TaskIdeaService`、`DirectRunExecutor` / `WorkflowScheduler`、以及内置工具描述装配中，按当前任务 `locale` 加载对应语言的 Prompt，并注入明确的输出语言指令（英文任务全程英文分析、交接、总结；中文任务全程中文输出）。
- 内置 `DemoModel`（模拟模型）同步支持根据 `locale` 返回对应语言的演示分析与交接文本，确保用户在英文模式下点击**免 Key 教学演示剧本**也能看到全英文的完整运行过程！

### 2.3 `StructuredHandoffExtractor` 双语结构化提取升级
- 现有 `backend/src/main/java/dev/workbench/framework/trace/StructuredHandoffExtractor.java` 仅靠中文关键词（`"决定"`、`"方案"`、`"采用"`、`"实现"`、`"风险"`、`"待确认"`、`"未验证"`）提取决策与风险。
- 升级为**中英双语 + 结构化标记兼容**：
  - 同时识别英文决策关键词（`decision`, `approach`, `strategy`, `implement`, `design`, `adopt`, `chosen`）与英文风险关键词（`risk`, `todo`, `pending`, `unverified`, `caveat`, `warning`, `blocker`, `open question`），并保持对原有中文关键词的完全兼容；
  - 优化 `summary` 提取逻辑：跳过纯 Markdown 章节标题行（如 `## Observed Evidence` / `## 一、已观察到的证据`）和表格分隔行，优先提取包含实质结论的行。

## 阶段 3：后端报错、安检门/交接校验与故障诊断国际化

### 3.1 Spring `MessageSource` 多语言配置
- 在 `backend/src/main/resources/i18n/` 下新建：
  - `messages.properties`（默认中文兜底）
  - `messages_zh_CN.properties`
  - `messages_en_US.properties`
- 配置 Spring Boot `AcceptHeaderLocaleResolver`（支持 `zh-CN`、`en-US`，默认 `zh-CN`）与轻量 `LocalizedMessages` 工具类（封装 `MessageSource` 解析，避免 Controller 直接拼接散落文案）。
- 将关键对外 API 的校验与业务提示接入 `LocalizedMessages`：
  - `ModelConnectionService` & `OpenAICompatibleModelProbe`（连通性测试提示如 `401 Invalid or expired API key` / `Connected successfully`、URL/Key 参数校验提示）
  - `RunCreationService`、`PlanCandidateService`、`TaskIdeaService`

### 3.2 落库校验与诊断记录支持「历史记录实时随语言切换」
- **`GlassboxModels.GatewayCheck`**（用于 `ToolGateway` 6 道安检门与 `StructuredHandoffExtractor` 4 项交接校验）：
  - 在不破坏既有 `gate`、`label`、`status`、`detail` 字段的前提下，前端 `HandoffEnvelopePanel.jsx` 与 `ToolGatewayPanel.jsx` 依据 `gate` + `status` + 结构化信息，按当前界面语言 `locale` 渲染对应的中文/英文标题与说明（英文模式下不再把后端落库的中文 `label` 直接裸显出来！）。
- **`RunDiagnostics`（5 步故障诊断向导）**：
  - `RunDiagnosticsService.diagnose(runId, locale)` 根据当前请求的 `Accept-Language` 生成对应语言的 `primaryIssue`、`title`、`finding`、`actionLabel`；
  - `MonitoringDashboardController` 将解析后的 `Locale` 传入 `RunDiagnosticsService`，确保用户在英文界面点击「One-Click Triage」时，整个 5 步排查向导 100% 呈现自然英文。
